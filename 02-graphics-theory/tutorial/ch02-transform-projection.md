## 分节正文

### 2.1 变换链总览：六个空间与一张地图

先看事故现场。你照着教程搭了个场景：一跑起来画面全黑；或者物体不知道飞哪去了；更诡异的是——只想动一下相机，改了一个矩阵，全场景的物体集体乱跳。没有链路地图时，你只能三个矩阵挨个瞎调，改这个、坏那个。这类事故几乎从来不是「某个数抄错了」，而是**你不知道每个矩阵在整条链路上负责哪一段**。本节先发地图，后面八节逐段拆解。

顶点从出生到上屏，依次经过六个空间（术语沿用 LearnOpenGL 口径，首次出现给出英文）：

| 顺序 | 空间 | 怎么到达下一个 | 这一段的存在理由 |
|---|---|---|---|
| 1 | 模型空间（局部空间，local/model space） | 模型矩阵（model matrix）M | 物体在「自己的坐标系」里建模最方便，再整体摆进世界 |
| 2 | 世界空间（world space） | 视图矩阵（view matrix）V | 万物的公共舞台；物体间关系（谁挨着谁）在这里说清 |
| 3 | 观察空间（相机空间，view space） | 投影矩阵 P | 把世界反向搬进「以相机为原点」的坐标系，「离相机多远」变成一个 z 值 |
| 4 | 裁剪空间（clip space） | 透视除法 ÷w | 用 ±w 判据先裁掉视锥外的点（裁剪在除法之前！2.6 细讲） |
| 5 | 标准化设备坐标（normalized device coordinates，NDC） | 视口变换 | 三个坐标都归一到 [−1,1]，与屏幕多大多宽彻底无关 |
| 6 | 屏幕空间 / 窗口坐标（window coordinates） | ——（交给光栅化，第 3 章） | 落进有像素格子的现实世界 |

songho.ca 把同一条链路画成一条流水线：object → eye → clip → ÷w → NDC → window——本章十节就是在这条流水线上逐站停靠。LearnOpenGL 有一句总纲值得抄在笔记首页：**过渡坐标系的意义，是让某些操作在特定空间里做更方便**——裁剪要在归一化的空间里才只是比大小，「离相机的距离」要在观察空间里才是一个干净的 z。

MVP 三个字母怎么进这条链？GAMES101 的「拍照三步」是最好的记忆结构：**摆人（Model）——把物体摆进世界；放相机（View）——把相机对准场景；按快门（Projection）——把三维场景拍成一张二维照片**。剩下的两站（÷w 与视口）是按完快门后的冲洗流程，2.6 与 2.7 各领一段。

连乘次序：列向量右乘约定下写作 P·V·M·v，从右往左读——**离 v 最近的先上场**（ch01 1.5 的结论原样复用）。先摆物体（M），再摆相机（V），最后按快门（P）。引擎每帧把三个矩阵预先乘成一张矩阵再喂给每个顶点，靠的是矩阵乘法结合律（ch01 1.5）——次序不能换，但可以合并。顺带立一个概念级认知：顶点着色器的最终输出就是裁剪坐标——GPU 管线接手后做裁剪、除法、视口，这三步本章全部用纯 CPU 数值复刻。

最后预告本章的「症状定位地图」——深入专题会给每个症状配数值现场，这里先立目录：

| 症状 | 高嫌疑环节 | 拆解处 |
|---|---|---|
| 画面全黑 / 物体看不见 | 相机朝向（V）、深度范围（P）、±w 裁剪误伤 | 2.3 / 2.5 / 2.6 |
| 画面拉伸变形 | fovY/aspect 与视口宽高比不匹配 | 2.5 / 2.7 |
| 画面上下镜像 | NDC y 朝向 / 手性约定冲突 | 2.9 |
| 近处物体整片消失 | 相机身后点 w<0 被裁 / z 范围口径 | 2.6 / 2.9 |
| 压扁模型后光照脏掉 | 法线没走逆转置 | 2.8 |

**MVP 不是三个孤立的矩阵，是一条流水线——每一站把世界搬进一个更好做事的空间。**

### 2.2 模型变换：把物体摆进世界

事故现场：给角色加「自转 + 公转 + 缩放」，转着转着角色飞出了场景。病根十有八九是变换的次序——缩放和旋转绕的是**谁的原点**？这个问题 ch01 1.5 埋过种子：「线性变换必保原点，想绕物体自身中心转？先挪到原点、转完再挪回去」。本节把这句话升级成日常工具。

先盘家底：模型变换的全部原料 ch01 都造好了——rotateX/Y/Z、scale、translate 三件套，列向量右乘、平移住最后一列（ch01 1.10）。本节只做组装，不重推。组装的标准配方是 **M = T·R·S**：从右往左读，先缩放、再旋转、最后平移。为什么是这个次序？缩放和旋转都必须绕物体**自身原点**进行——趁物体还在原点，先把它捏成形、转好朝向，再整体搬到世界的落脚点。「先穿袜子再穿鞋」的画面原样适用：平移是最后那只鞋。

绕任意点 c 旋转的「三明治」套路，兑现 ch01 1.5 边界陷阱里的承诺：

```text
M = T(c) · R · T(−c)     先把支点挪到原点，绕原点转，再把支点挪回去
```

三片面包夹一块肉：外层两个平移互为逆、中间是干净的旋转。验证一次手感：想让物体绕自己的角 (1, 0, 0) 转 90°，直接 Rz(90°) 会绕世界原点甩一个大圈；套上三明治，物体原地翻身。这个套路在引擎的变换层级里天天出现——「模型矩阵可分解可组合」正是场景树（父变换叠子变换）的观念种子，完整机制将在第 4 节展开。

最后回答「为什么要有局部坐标」：模型在建模时天然以自身为中心——人物模型的脚在原点、头朝上，与它将出现在世界的哪个角落毫无关系。**模型矩阵就是物体的「出生证明 + 摆放记录」**：出生证明说「它的鼻子在自身 (2, 0, 1)」，摆放记录说「把它平移 (10, 0, −3)、转身 45° 放进世界」。一个说明性小片段感受组装形态（省略了数学库实现与 main，完整库见 ch01 1.10 与本章 2.10）：

```cpp
Mat4 M = mul(translate(10, 0, -3),          // 最后：摆到位
             mul(rotateY(45), scale(2, 2, 2)));  // 先在原点捏形：缩放 -> 转身
Vec4 world = apply(M, {2, 0, 1, 1});         // 鼻子的局部坐标 -> 世界坐标
```

边界与陷阱两条。其一，T·R·S 不是唯一的正确次序而是**默认语义**——若你确实想「先摆位再绕世界原点转」（例如公转），次序就要反过来写；关键是次序必须服务意图，而不是随手连乘。其二，非均匀缩放（sx ≠ sy ≠ sz）混进 M 之后，这个矩阵就不再配得上「法线也直接乘它」——这正是 2.8 的引线，先按住不表。

**局部坐标是物体的母语——模型变换就是把母语翻译成世界语，翻译次序即命运。**

### 2.3 视图变换与 lookAt：把相机请回原点

事故现场：「我只是想把相机往左移 2 米，为什么改一个数字全场景都跟着动？」因为**动的从来不是相机，是整个世界**。视图变换的本质是一句话：**把世界反向搬进相机坐标系**——相机被钉死在原点、朝 −Z 看（OpenGL 观察空间约定），你移动相机，等价于用「相机变换的逆」去移动整个场景。快门不动，景动。

为什么非要把相机搬回原点？因为投影矩阵的所有推导（2.4、2.5）都默认「眼睛在原点、往 −Z 看」——先统一视角，投影才有干净的形状。所以视图矩阵的使命只有一个：把任意的相机位姿归零。

兑现 ch01 1.4 挂账——「叉乘两次，坐标系到手」：给定相机位置 eye、注视点 target、世界上方向 up 三个参数，两步叉乘造出相机的标准正交基（LearnOpenGL 工程口径）：

```text
zaxis = normalize(eye − target)      相机 z 基指向「相机后方」（右手系、相机看 −Z）
xaxis = normalize(cross(up, zaxis))  世界 up 只用来定向，不保证正交
yaxis = cross(zaxis, xaxis)          回推第三轴，天然正交化
```

注意构造顺序的门道：up 只是「大致朝上」的意愿，不与视线垂直也没关系——先用它叉出 xaxis（把「左右」定死），再用两条已正交的轴回推出真正的 yaxis。世界 up 被消费了一次就扔，正交性由构造保证。

【推导·全程】视图矩阵 = R_view·T_view（GAMES101 口径），推导走四步。

第一步，先写「相机变换」C——把相机局部坐标变到世界坐标。相机在自己的坐标系里看，前向是 −Z；它坐在世界里的 eye 处、被 xaxis/yaxis/zaxis 三条基定向。一个相机局部点 p_cam 到世界：

```text
p_world = eye + xaxis·p_cam.x + yaxis·p_cam.y + zaxis·p_cam.z
```

按「矩阵每列记录一个基向量去哪了」（ch01 1.5）读：C 的旋转块三列就是 xaxis/yaxis/zaxis，平移列是 eye。

第二步，视图矩阵是相机变换的**逆**：V = C⁻¹。逆的分解：先撤销平移（把相机从 eye 搬回原点），再撤销旋转（把三条基转回世界轴）：

```text
V = R_view · T(−eye)      其中 R_view = R_cam⁻¹
```

第三步，R_view 怎么写？R_cam 的列是正交基 → 它是正交矩阵 → **逆 = 转置**（ch01 1.5 的 RᵀR = I 原地兑现）。转置把「基向量按列摆」翻转成「基向量按行摆」——所以视图矩阵的旋转块三行，恰是 xaxis/yaxis/zaxis 三个行向量。

第四步，合并 R_view·T(−eye)：V·p = R_view·(p − eye)。第 i 行点乘 (p − eye)，展开成「基·p − 基·eye」——旋转块照抄基向量，平移列写入 **−(各基向量与 eye 的点乘)**：

```text
V = [ xaxis.x  xaxis.y  xaxis.z  −dot(xaxis, eye) ]
    [ yaxis.x  yaxis.y  yaxis.z  −dot(yaxis, eye) ]
    [ zaxis.x  zaxis.y  zaxis.z  −dot(zaxis, eye) ]
    [    0        0        0            1         ]
```

验证两条必过性质：把 p = eye 代入，每一行都是「基·eye − 基·eye = 0」→ 相机归原点；把 p = target 代入，target − eye 恰是 −|eye−target|·zaxis（zaxis 定义就是 normalize(eye−target)），三条基里只有 zaxis 与它不垂直 → 结果落在 (0, 0, −|eye−target|)：注视点方向被搬到 −Z 上。下面程序把两条性质连同基的正交性一起数值验证：

```cpp
// ch02_lookat.cpp —— lookAt 视图矩阵：正交基构造 + 三条性质验证（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec3 { float x{}, y{}, z{}; };
struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };              // 行主序存储；数学按「列向量右乘」约定

inline Vec3 operator-(Vec3 a, Vec3 b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; }
inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }
inline Vec3 cross(Vec3 a, Vec3 b) {          // 垂直于 a、b 的向量（右手系朝向）
    return {a.y*b.z - a.z*b.y, a.z*b.x - a.x*b.z, a.x*b.y - a.y*b.x};
}
inline float length(Vec3 a) { return std::sqrt(dot(a, a)); }
inline Vec3 normalize(Vec3 a) { float l = length(a); return {a.x / l, a.y / l, a.z / l}; }

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}

Mat4 lookAt(Vec3 eye, Vec3 target, Vec3 up) {  // 视图矩阵：把相机请回原点、朝 −Z
    Vec3 zAxis = normalize(eye - target);      // 相机 z 基指向「相机后方」（右手系看 −Z）
    Vec3 xAxis = normalize(cross(up, zAxis));  // 世界 up 只用来定向
    Vec3 yAxis = cross(zAxis, xAxis);          // 叉乘回推第三轴，天然正交
    Mat4 V{};                                  // 基向量按行摆放 = 逆 = 转置（ch01 1.5）
    V.m[0][0] = xAxis.x; V.m[0][1] = xAxis.y; V.m[0][2] = xAxis.z; V.m[0][3] = -dot(xAxis, eye);
    V.m[1][0] = yAxis.x; V.m[1][1] = yAxis.y; V.m[1][2] = yAxis.z; V.m[1][3] = -dot(yAxis, eye);
    V.m[2][0] = zAxis.x; V.m[2][1] = zAxis.y; V.m[2][2] = zAxis.z; V.m[2][3] = -dot(zAxis, eye);
    V.m[3][3] = 1.0f;
    return V;
}

void printRow(const char* label, const Mat4& M, int i) {
    std::printf("  %s [%+.4f %+.4f %+.4f %+.4f]\n", label, M.m[i][0], M.m[i][1], M.m[i][2], M.m[i][3]);
}

void checkCamera(const char* name, Vec3 eye, Vec3 target, Vec3 up) {
    Mat4 V = lookAt(eye, target, up);
    std::printf("── 相机 %s：eye=(%.0f,%.0f,%.0f)  target=(%.0f,%.0f,%.0f)\n",
                name, eye.x, eye.y, eye.z, target.x, target.y, target.z);
    printRow("x基行", V, 0);
    printRow("y基行", V, 1);
    printRow("z基行", V, 2);
    printRow("齐次行", V, 3);

    Vec4 e = apply(V, {eye.x, eye.y, eye.z, 1});
    Vec4 t = apply(V, {target.x, target.y, target.z, 1});
```

### 2.4 正交投影：先把长方体拍成立方体

先认识不带走透视的那一半投影，才知道 2.5 的透视矩阵到底比它多干了哪一半。CAD 软件、2D 游戏、工程三视图——为什么它们永远「近大远小不存在」？因为它们用的是正交投影（orthographic projection）：**只负责取景框，不负责近大远小**。直观版：相机在原点看 −Z，把可视矩形里的东西丢掉 z（深度）拍平。正式版（GAMES101 口径）：把一个轴对齐长方体 [l,r]×[b,t]×[f,n]（相机看 −Z，n、f 是负的 z 值）映射到规范立方体（canonical cube）[−1,1]³。

【推导·全程】逐轴映射。三个轴是同一道题的三次重复，把 x 轴推透，y、z 抄模板。目标：把 [l, r] 映到 [−1, 1]。用「先平移到中心、再缩放」两步（GAMES101 次序）：

```text
第一步（平移到中心）：  x1 = x − (r+l)/2          中点 (r+l)/2 被搬到 0
第二步（缩放到 ±1）：   x_ndc = 2·x1/(r−l)        半宽 (r−l)/2 被拉成 1

合并：x_ndc = 2x/(r−l) − (r+l)/(r−l)
```

验算两端：x = l → 2l/(r−l) − (r+l)/(r−l) = (2l−r−l)/(r−l) = (l−r)/(r−l) = −1 ✓；x = r → (2r−r−l)/(r−l) = +1 ✓。y 轴把 (l,r) 换成 (b,t)，z 轴换成 (f,n)，模板原样生效。三轴合并成一个矩阵——「先平移后缩放」写成矩阵乘积 M_ortho = S·T：

```text
            [ 2/(r−l)   0         0        −(r+l)/(r−l) ]
M_ortho  =  [ 0         2/(t−b)   0        −(t+b)/(t−b) ]
            [ 0         0         2/(n−f)  −(n+f)/(n−f) ]
            [ 0         0         0         1           ]
```

这个「先缩放到长度 2、再平移到居中」的逐轴模板是白板推导一切区间映射矩阵的万能钥匙——视口变换（2.7）还会再用一次。等一下，先排雷：把 z = n 代入 z 行，得 (2n−n−f)/(n−f) = +1——**近平面映到了 +1 端**。这就是 n/f 负值雷区（多源一致确认的第一颗雷）：相机看 −Z，可见点的 z 全是负的，n（近）比 f（远）更靠近 0，所以 n > f 是负数比大小；GAMES101 的推导口径里近平面落在规范立方体的 +1 端。而 OpenGL 工程口径（glOrtho：传**正的距离**、内部取负）把近平面映到 **−1** 端——z 行换写成 (0, 0, −2/(f−n), −(f+n)/(f−n))，正距离 N、F 代入得 z=−N → −1、z=−F → +1。两版只差一次 z 轴翻转，都是自洽的约定；本章推导用 GAMES101 负值口径，2.10 的库 API 用 OpenGL 正距离口径，到时候显式换算。**推导前先声明口径，两套口径不在同一张草稿纸上打架。**

正交投影的两个性格，为 2.5 立好对照组：其一，w 恒为 1——矩阵第四行是 (0,0,0,1)，透视除法对它是一次空操作（「除以 1」什么都没做）；其二，平行线保持平行、远近一样大——它只做缩放与平移（都是线性/仿射变换，ch01 1.6 的户口本），不碰「深度换大小」那根弦。所以图纸用它，2D UI 用它，一切「我要尺寸忠实于数值」的场合都用它。下面程序验证角点映射与平行保持：

```cpp
// ch02_ortho.cpp —— 正交投影：角点映射 + 平行保持的数值验证（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}

Mat4 ortho(float l, float r, float b, float t, float n, float f) {
    // 正交投影：长方体 → 规范立方体；n、f 传「正的距离」，内部取负（OpenGL 工程口径）
    Mat4 M{};                                            // 视空间 z=−n 映到 −1、z=−f 映到 +1
    M.m[0][0] =  2.0f / (r - l);  M.m[0][3] = -(r + l) / (r - l);   // x：缩放到 2 再居中
    M.m[1][1] =  2.0f / (t - b);  M.m[1][3] = -(t + b) / (t - b);   // y：同构
    M.m[2][2] = -2.0f / (f - n);  M.m[2][3] = -(f + n) / (f - n);   // z：GL 口径 → 负号
    M.m[3][3] = 1.0f;                                    // w 恒为 1：透视除法空操作
    return M;
}

void printPoint(const char* tag, Vec4 p) {
    std::printf("  %s (%+.1f, %+.1f, %+.1f) -> (%+.3f, %+.3f, %+.3f)  w=%.1f\n",
                tag, p.x, p.y, p.z, p.x, p.y, p.z, p.w);
}

int main() {
    Mat4 O = ortho(-4, 4, -3, 3, 1, 9);          // 盒子 [−4,4]×[−3,3]，近平面距离 1、远平面 9

    // ── 角点映射：长方体八角对应规范立方体（近 → −1，远 → +1）──
    std::printf("[角点映射]\n");
    Vec4 c1 = apply(O, {-4, -3, -1, 1});         // 左下近角
    Vec4 c2 = apply(O, { 4,  3, -9, 1});         // 右上远角
    printPoint("左下近角", c1);
    printPoint("右上远角", c2);
    assert(std::fabs(c1.x + 1) < 1e-5 && std::fabs(c1.y + 1) < 1e-5 && std::fabs(c1.z + 1) < 1e-5);
    assert(std::fabs(c2.x - 1) < 1e-5 && std::fabs(c2.y - 1) < 1e-5 && std::fabs(c2.z - 1) < 1e-5);

    // ── 平行保持：一对同向线段（不同深度、不同位置）投影后方向仍相同 ──
    std::printf("[平行保持]\n");
    Vec4 A{-4, 0, -2, 1}, B{-2, 0, -2, 1};       // 线段一：深度 2 处，方向 (2,0,0)
    Vec4 C{ 0, 2, -8, 1}, D{ 2, 2, -8, 1};       // 线段二：深度 8 处，同方向 (2,0,0)
    Vec4 A2 = apply(O, A), B2 = apply(O, B);
    Vec4 C2 = apply(O, C), D2 = apply(O, D);
    Vec4 dir1{B2.x - A2.x, B2.y - A2.y, B2.z - A2.z, 0};
    Vec4 dir2{D2.x - C2.x, D2.y - C2.y, D2.z - C2.z, 0};
    std::printf("  线段一 -> (%.3f, %.3f, %.3f)->(%.3f, %.3f, %.3f)  方向 (%.3f, %.1f, %.1f)\n",
                A2.x, A2.y, A2.z, B2.x, B2.y, B2.z, dir1.x, dir1.y, dir1.z);
    std::printf("  线段二 -> (%.3f, %.3f, %.3f)->(%.3f, %.3f, %.3f)  方向 (%.3f, %.1f, %.1f)\n",
                C2.x, C2.y, C2.z, D2.x, D2.y, D2.z, dir2.x, dir2.y, dir2.z);
    assert(std::fabs(dir1.x - dir2.x) < 1e-5 && std::fabs(dir1.y - dir2.y) < 1e-5);
    std::printf("  两段投影后方向完全相同 -> 平行保持成立；且 w 恒为 1（除法空操作）\n");
    std::printf("正交投影全部验证通过\n");
    return 0;
}
```

```text
  右上远角 (+1.0, +1.0, +1.0) -> (+1.000, +1.000, +1.000)  w=1.0

  线段一 -> (-1.000, 0.000, -0.750)->(-0.500, 0.000, -0.750)  方向 (0.500, 0.0, 0.0)
```

边界与陷阱：其一，l = r（或 b = t、n = f）时矩阵出现除零——退化成零体积的盒子没有意义，参数先过合法性检查；其二，「GL 口径的负号在 z 行」是初学者高频翻车点：如果你手写 ortho 时 z 行忘了带负号，画面深度方向整体颠倒，症状是「该挡在前面的反而画在后面」——2.9 的深度话题会再见到这个症状。

**正交投影是刚性搬运：换的是坐标系，不改的是形状——它没有透视，所以它是透视最好的对照组。**

### 2.5 透视投影：相似三角形到矩阵的完整旅程（检验标准①主场）

两件事逼你把这一节吃透。其一，面试和考试让手推透视投影矩阵——背是背不住的，唯有推导能现场重造；其二，工程里抄 `glm::perspective` 参数全对、画面就是不对的事故，几乎都出在「不理解参数背后的几何」。推导不是仪式，是检验标准①的直通车。本节是全章最重的一节，请把草稿纸放在手边，跟着一步一步推。

先认识透视的取景框：**视锥体（frustum / view frustum）**。透视相机看到的世界是一个截头四棱锥——近处一个矩形（近平面），远处一个更大的相似矩形（远平面），四条棱向眼睛后方收束。正交投影的取景框是个长方体，透视投影（perspective projection）的是个锥体——这个形状差异，就是「近大远小」的几何本体。

为什么透视不能像正交那样直接「丢 z」？因为透视投影**除以深度**，不是线性变换：近处的东西要被放大、远处要被缩小，缩放比例随深度连续变化——任何固定的矩阵乘法都做不到「每一行除不同的数」。把这件事先写成一个画面：视锥内一点 P = (x, y, z)（z < 0），眼睛在原点，从眼睛发出的光线穿过 P 打在近平面（z = n 处）上，落点就是「透视后的 x、y」。这个落点用中学几何就能算——相似三角形。

【推导·全程】GAMES101「挤压（squeeze）」推导四步。目标：找一个矩阵，把视锥体压成长方体，然后复用 2.4 的正交投影收尾。

**第一步：相似三角形。**眼睛在原点、看向 −Z，P = (x, y, z) 与近平面的像 P′ = (x′, y′, n)。光线穿 P 与 P′，两个三角形相似（水平面切一刀：边长比为深度之比）：

```text
x′ = (n/z)·x        y′ = (n/z)·y        （n、z 都是负数，n/z > 0）
```

验算：z = n（点就在近平面上）→ x′ = x，不动 ✓；z 是两倍远 → 像缩成一半 ✓。近大远小的种子已经在这两行里。

**第二步：齐次化技巧。**矩阵乘法做不了「除以不同的 z」，但**齐次坐标可以**——把除法推迟到「除以 w」那一步（ch01 1.6 说过 w 还能当除数，今天就是它上岗的日子）。想让除法恰好除以 z，就让 w 承载 z：把目标齐次结果设成 (nx, ny, 未知, z)——除以第四分量 z，得到 (nx/z, ny/z, ?/z)，前两个分量正是第一步的 x′、y′。于是矩阵的前两行与第四行当场解出：

```text
第一行 (n, 0, 0, 0)   → x 分量 = n·x
第二行 (0, n, 0, 0)   → y 分量 = n·y
第四行 (0, 0, 1, 0)   → w 分量 = z（第四行设 (0,0,1,0)：让 w 偷偷记住深度）
```

只剩第三行未知，设 (0, 0, C, D)（不带 x、y 项——挤压力沿视线方向，左右对称）。

**第三步：用不变量解第三行。**「挤压」不能乱压，得保住视锥体的前后两个盖子。这里的关键是「不变」必须在**齐次意义**下读——整个点要除以 w 再比较：

```text
约束一（近平面不动）： 任意 (x, y, n, 1) 挤压后应除回原样。
    挤压结果是 (nx, ny, Cn+D, n)，除以 w=n 得 (x, y, (Cn+D)/n, 1)。
    要求 z 分量还原 n：(Cn+D)/n = n  →  Cn + D = n²
约束二（远平面中心不动）： (0, 0, f, 1) 挤压后 (0, 0, Cf+D, f)，除以 f 得 z 分量 f。
    (Cf+D)/f = f  →  Cf + D = f²
```

两式相减：C(n − f) = n² − f² = (n−f)(n+f) → **C = n + f**；代回：D = n² − (n+f)n = **−nf**。（事实上代入后可验：整个近平面、整个远平面都被各自映回原处——中心点只是用来把方程组钉死的那个代表。）第三行解出，挤压矩阵（perspective-to-orthographic squeeze matrix，GAMES101 记号 M_persp→ortho）到手：

```text
                [ n   0   0     0  ]
M_persp→ortho = [ 0   n   0     0  ]
                [ 0   0   n+f  −nf ]
                [ 0   0   1     0  ]
```

**第四步：与正交投影复合。**挤压后的视锥体已是长方体——齐次意义下每个点除以自己的 w 后恰好落进 [l,r]×[b,t]×[f,n] 盒，近、远两盖位置不动——正交推导（2.4）在此被复用：M_persp = M_ortho · M_persp→ortho。乘开（挑关键两行走完，其余同构）：

```text
x 行：(2/(r−l))·(nx) + (−(r+l)/(r−l))·z      → 系数 (2n/(r−l), 0, −(r+l)/(r−l), 0)
z 行：(2/(n−f))·((n+f)z−nf) + (−(n+f)/(n−f))·z = ((n+f)z − 2nf)/(n−f)
                                              → 系数 (0, 0, (n+f)/(n−f), −2nf/(n−f))
w 行：挤压第四行原样透传                      → (0, 0, 1, 0)
```

**最后一步：换算成 OpenGL 工程口径。**把参数换成正距离 N = −n、F = −f（近、远平面的「距离」），并按工程惯例要求「近平面映到 z_ndc = −1、远平面映到 +1、除法前 w 恒正」。做法：第一、二、四行同乘 −1（x、y 除以 −w 商不变，w 从 z 变 −z 转正），z 从「近平面在 +1 端」翻到「近平面在 −1 端」——第三行代入 N、F 后逐项一致：

```text
            [ 2N/(r−l)   0         (r+l)/(r−l)    0          ]
M_persp  =  [ 0          2N/(t−b)  (t+b)/(t−b)     0          ]
            [ 0          0         −(F+N)/(F−N)    −2NF/(F−N) ]
            [ 0          0         −1              0          ]
```

第三行别背——**直推一遍当验算**：设第三行 (0, 0, α, β)、第四行 (0, 0, −1, 0)（w = −z）。两个 z 约束联立：

```text
近平面 z = −N：z_ndc = (−αN + β)/N = −1   →  −αN + β = −N
远平面 z = −F：z_ndc = (−αF + β)/F = +1   →  −αF + β =  F
相减：α(N − F) = N + F  →  α = −(F+N)/(F−N)；代回  β = −2NF/(F−N)
```

与挤压路线的第三行完全一致——一条推导两次到达，这就是「会推」与「会背」的区别。那个 −2NF/(F−N) 一项的来历也就清楚了：**它是「近平面压到 −1、远平面压到 +1」两个约束的联立解**，没有它，深度无从归一。

还差最后一层参数皮：工程上没人手填 l/r/b/t，大家填的是「竖直视场角 + 画面比例」（GAMES101 L05 口径，也是 glm::perspective、glMatrix 的通用形态）：

```text
t = N·tan(fovY/2)        近平面半高：fovY 是竖直方向的视场角
r = aspect·t             近平面半宽：aspect = 宽/高
```

fovY = 90°、N = 1 时 t = 1；aspect = 4/3 时 r = 4/3——视锥体的形状由这两个数完全确定。顺带把术语钉死：fovY 是**竖直方向**的视场角（field of view），aspect 是纵横比（aspect ratio），即宽/高。对称视锥（l = −r、b = −t）下矩阵第一行 2N/(r−l) 化简为 N/r、第二行化为 N/t，这就是 2.10 库函数里那两个 `n/r`、`n/t` 的出处。

边界注记两条。其一，**挤压后中间深度的 z 会挪动**——近、远两个盖子不动，中间的点既不保距也不线性。代数证据程序表里有：d = 2 的点 z_ndc = +0.125，而线性插值该给 0——挪了。这份「挪动」正是 z 非线性的代数根源，2.9 与第 3 章会回来收账。其二，可逆性的精确口径（两说并存，必须分清）：教科书意义的「真投影」（把 z 压平丢掉）行列式为 0、不可逆；而 API 的 4×4 投影矩阵把深度编码进 z 和 w，**矩阵本身可逆**——真正不可逆的分水岭是透视除法：除完丢掉 w，从 NDC 再也恢复不出深度比例。一句话记牢：压扁不可逆，矩阵可逆，除法后不可逆。

```cpp
// ch02_perspective.cpp —— 透视投影：近/远平面角点 z_ndc = ∓1 + w 承载深度的对照表（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>
#include <initializer_list>   // 花括号范围 for 需要（MSVC 不会随 cstdio 隐式提供）

struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}

Mat4 perspective(float fovYDeg, float aspect, float n, float f) {
    // 透视投影：视锥体 → 规范立方体；fovY 竖直视场角（度）、aspect = 宽/高、n/f 正距离
    float t = n * std::tan(fovYDeg * 3.14159265f / 180.0f * 0.5f);  // 近平面半高 t = n·tan(fovY/2)
    float r = aspect * t;                              // 近平面半宽 r = aspect·t
    Mat4 M{};
    M.m[0][0] = n / r;                                 // 对称视锥下 2n/(r−l) 化简为 n/r
    M.m[1][1] = n / t;
    M.m[2][2] = -(f + n) / (f - n);                    // 第三行：两个 z 约束联立解的产物
    M.m[2][3] = -2.0f * f * n / (f - n);
    M.m[3][2] = -1.0f;                                 // 第四行 (0,0,−1,0)：w = −z，偷记深度
    return M;
}

int main() {
    const float N = 1.0f, F = 9.0f;
    Mat4 P = perspective(90.0f, 1.0f, N, F);           // fovY=90°、aspect=1：近平面方形 [−1,1]²

    // ── 近平面四角：应映到 z_ndc = −1 ──
    std::printf("[近平面 z=−1 的四角]\n");
    for (int sx = -1; sx <= 1; sx += 2)
        for (int sy = -1; sy <= 1; sy += 2) {
            Vec4 c = apply(P, {sx * 1.0f, sy * 1.0f, -N, 1});
            std::printf("  (%+.0f, %+.0f) -> z_ndc = %+.4f\n", c.x / c.w, c.y / c.w, c.z / c.w);
        }

    // ── 远平面四角（近角点按 f/n=9 放大）：应映到 z_ndc = +1 ──
    std::printf("[远平面 z=−9 的四角]\n");
    for (int sx = -1; sx <= 1; sx += 2)
        for (int sy = -1; sy <= 1; sy += 2) {
            Vec4 c = apply(P, {sx * F, sy * F, -F, 1});
            std::printf("  (%+.0f, %+.0f) -> z_ndc = %+.4f\n", c.x / c.w, c.y / c.w, c.z / c.w);
        }

    // ── 视锥内点的 w 对照表：w_clip = −z_view（视空间深度的负值拷贝）──
    std::printf("[视锥内点对照表]  P·(x, y, −d, 1)：\n");
    std::printf("  d(z_view)    x_clip    w_clip    w=−z_view?   z_ndc\n");
    for (float d : {1.0f, 2.0f, 4.0f, 9.0f}) {
        Vec4 c = apply(P, {0.5f, 0.25f, -d, 1});
        bool ok = std::fabs(c.w - d) < 1e-5f;          // w 应恰等于深度 d
        std::printf("  %-9.1f  %8.3f  %7.3f     %-8s   %+.4f\n",
                    d, c.x, c.w, ok ? "是" : "否", c.z / c.w);
    }

    // 断言收口：近角 z_ndc=−1、远角 z_ndc=+1、w 恒为深度
    Vec4 nc = apply(P, {1, 1, -N, 1}), fc = apply(P, {F, F, -F, 1});
    assert(std::fabs(nc.z / nc.w + 1.0f) < 1e-5 && std::fabs(fc.z / fc.w - 1.0f) < 1e-5);
    assert(std::fabs(nc.w - N) < 1e-5 && std::fabs(fc.w - F) < 1e-5);
    std::printf("透视投影全部验证通过\n");
    return 0;
}
```

**透视投影矩阵的全部秘密一句话：让 w 偷偷记住深度，透视除法时刻一次结账。**

### 2.6 透视除法与 w：近大远小的账单（检验标准②主场）

看两张照片：铁轨明明平行，画面里却会聚成一个远处的点；并排走的两个人，远处那位在照片里只有半个高。「画面里天然存在一次除法」——是谁、在什么时候、除了什么？本节回答这三个问题，顺便正式兑现 ch01 挂账。

投影矩阵吐出的是**裁剪坐标** (x, y, z, w)，四个分量。GPU 管线接着做一次固定动作：**透视除法（perspective divide）**——四个分量统统除以 w，得到 NDC：

```text
(x, y, z, w) ÷ w = (x/w, y/w, z/w, 1)
```

**兑现 ch01 挂账**：1.6 里 w 的第一身份是「区分点与向量」（w=1 点、w=0 向量），并留了一句伏笔「w 还能当除数（透视除法）」。今天伏笔收束：2.5 的第四行 (0, 0, −1, 0) 让 w 装满了视空间深度，这里的除法把这份深度兑换成「近大远小」。NVIDIA Cg Tutorial 有句名言「w 是除数」——在本章，它从一句口径变成了一张可打印的数值账单。

w 的几何意义先说破：透视投影下 **w_clip = −z_view**——视空间深度的负值拷贝（右手系相机前方的点 z_view < 0，所以可见点的 w 恒正，这也是工程口径偏爱「第四行 −1」的原因）。除以 w，就是除以「你离相机多远」。于是近大远小的机制一页纸讲完：同一物体（同样的 x、y 尺寸），放在 2 倍深度处 → w 变 2 倍 → 除完的 x/w、y/w 缩成一半 → **屏幕坐标按 1/z 缩放**。远处 w 大、商小、显得小。铁轨的会聚也是同一笔账：两条平行铁轨上等间距的枕木，越远 w 越大、投影间距越小，间距趋于 0 的极限就是灭点——**透视除法是「画面里那一次除法」的全部真相**。对照组：正交投影 w 恒为 1（2.4），除法是空操作，所以永远近不大、远不小。

还有一个顺序问题必须钉死：**裁剪（clipping）发生在透视除法之前**。GPU 用 −w ≤ x, y, z ≤ w 判定一个点（准确说是图元）是否可见，判完了才做除法。为什么判据是 ±w 而不是 ±1？两个理由：其一，除法之后齐次信息已经丢失——w 里的深度比例被消费掉，再想裁就只剩裸坐标；其二，相机身后的点 w < 0，除以负 w 会把坐标镜像翻转，用 ±1 判据反而漏判——±w 判据在「除法前」一把抓住这类点。深入专题开关 3 会让你亲眼看到 w < 0 的点如何被整批裁掉。

```cpp
// ch02_perspective_divide.cpp —— 透视除法：近大远小数值账单 + ±w 裁剪判定演示（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>
#include <initializer_list>   // 花括号范围 for 需要（MSVC 不会随 cstdio 隐式提供）

struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}

Mat4 perspective(float fovYDeg, float aspect, float n, float f) {   // 同 ch02_perspective.cpp
    float t = n * std::tan(fovYDeg * 3.14159265f / 180.0f * 0.5f);
    float r = aspect * t;
    Mat4 M{};
    M.m[0][0] = n / r;
    M.m[1][1] = n / t;
    M.m[2][2] = -(f + n) / (f - n);
    M.m[2][3] = -2.0f * f * n / (f - n);
    M.m[3][2] = -1.0f;
    return M;
}

bool insideClipVolume(Vec4 c) {              // 裁剪判据：−w ≤ x, y, z ≤ w（除法之前！）
    return -c.w <= c.x && c.x <= c.w &&
           -c.w <= c.y && c.y <= c.w &&
           -c.w <= c.z && c.z <= c.w;
}

int main() {
    const float N = 1.0f, F = 9.0f;
    Mat4 P = perspective(90.0f, 1.0f, N, F);

    // ── 近大远小：同一根竖直线段（y ∈ [−0.5, +0.5]），放在两个深度 ──
    std::printf("[近大远小账单]  线段 y ∈ [−0.5, +0.5]，x=0\n");
    for (float d : {2.0f, 4.0f}) {
        Vec4 lo = apply(P, {0, -0.5f, -d, 1});
        Vec4 hi = apply(P, {0,  0.5f, -d, 1});
        float loN = lo.y / lo.w, hiN = hi.y / hi.w;
        std::printf("  深度 d=%.0f：clip y = (%.2f, %.2f)，w = %.0f -> NDC y = (%.3f, %+.3f)，跨度 %.3f\n",
                    d, lo.y, hi.y, lo.w, loN, hiN, hiN - loN);
    }
    std::printf("  -> 深度翻倍，跨度减半：屏幕尺寸 ∝ 1/w（w 即深度）\n");

    // ── 裁剪判定：三个点过 ±w 判据（发生在透视除法之前）──
    std::printf("[±w 裁剪判定]\n");
    Vec4 probes[] = {{0, 0, -5, 1}, {0, 0,  2, 1}, {0, 0, -20, 1}};
    const char* names[] = {"视锥内点(深度5)", "相机身后点(z=+2)", "超出远平面(深度20)"};
    for (int i = 0; i < 3; ++i) {
        Vec4 c = apply(P, probes[i]);
        std::printf("  %s：clip = (%.2f, %.2f, %.2f, %.2f)  判据 %s\n",
                    names[i], c.x, c.y, c.z, c.w,
                    insideClipVolume(c) ? "全过 -> 保留" : "未过 -> 裁剪");
    }

    // 断言收口：近段 NDC 跨度恰为远段两倍；身后点必被裁
    Vec4 n1 = apply(P, {0, -0.5f, -2, 1}), n2 = apply(P, {0, 0.5f, -2, 1});
    Vec4 f1 = apply(P, {0, -0.5f, -4, 1}), f2 = apply(P, {0, 0.5f, -4, 1});
    assert(std::fabs((n2.y/n2.w - n1.y/n1.w) - 2.0f * (f2.y/f2.w - f1.y/f1.w)) < 1e-4);
    assert(!insideClipVolume(apply(P, probes[1])));
    std::printf("透视除法验证通过\n");
    return 0;
}
```

```text

  深度 d=2：clip y = (-0.50, 0.50)，w = 2 -> NDC y = (-0.250, +0.250)，跨度 0.500
  深度 d=4：clip y = (-0.50, 0.50)，w = 4 -> NDC y = (-0.125, +0.125)，跨度 0.250
```

读表三处：其一，同一根线段，裁剪坐标的 y 完全相同（±0.50）——差距全在 w；其二，跨度 0.500 对 0.250，**深度翻倍、屏幕尺寸减半**，近大远小从「生活经验」变成一行可打印的除法；其三，相机身后的点 w = −2 < 0，z = −4.75 连 −w = 2 都够不着——判据在除法前就把它拦下了，除法根本没轮到它出场。

留一句前向指针就翻篇：除以 w 之后，「屏幕上的直线」不再是「三维里的直线」的线性映像——屏幕空间线性插值 ≠ 视空间线性插值，正确做法是按 1/z 插值（透视校正插值），将在第 3 章展开。

**w 是视空间深度的一份拷贝——透视除法除以 w，就是除以「你离相机多远」。**

### 2.7 视口变换与完整链路：从 NDC 到像素（手工计算主场）

事故现场：「顶点着色器最后一行写完 gl_Position 之后，到底发生了什么？为什么那必须是个四分量的 vec4？」前五节你手里已经有全部零件：M、V、P、÷w、视口。本节先补上最后一块（视口变换），然后做一件全章最有仪式感的事——**一个顶点从模型空间出发，每一站用笔算走到像素**。手算走完，黑盒就拆成了五站明账。

视口变换（viewport transformation）是 NDC 到窗口坐标的仿射映射：NDC 的 (−1,−1) 映到视口左下角、(+1,+1) 映到右上角。又是「区间映射」——2.4 的模板原样套用，把 [−1, 1] 映到 [x, x+width]：

```text
x_win = (width/2)·x_ndc + (x + width/2)          缩放 width/2，平移 x + width/2
y_win = (height/2)·y_ndc + (y + height/2)
z_win = (z_ndc + 1)/2                             默认深度范围（depth range）[0,1]：z 顺带映射
```

【推导·全程】以 x 轴为例走一遍模板（y、z 同构）：第一步缩放——[−1,1] 长度 2，要变成长度 width，乘 width/2；第二步平移——缩放后区间是 [−width/2, +width/2]，要挪到 [x, x+width]，加 x + width/2。合并即上式。矩阵形式四行写全（2.10 会把它做成函数）：

```text
            [ width/2    0         0     x + width/2 ]
viewport =  [ 0          height/2  0     y + height/2 ]
            [ 0          0         1/2   1/2          ]
            [ 0          0         0     1            ]
```

口径注记一句：本教程采用 width/2 主流口径（Cornell、GAMES101 等讲义同款）；「像素中心 vs 像素边界」的半像素偏移在 Foley 系教材中存在，知道有这回事即可，不展开。

热身手算（LearnOpenGL 书内同款例题）：NDC 点 (−0.5, 0.5)，视口 800×600（x=y=0）。x_win = (800/2)·(−0.5) + (0 + 800/2) = −200 + 400 = **200**；y_win = (600/2)·(0.5) + (0 + 600/2) = 150 + 300 = **450**。落在左上半区——NDC 的 y 朝上、窗口 y 也朝上（本教程口径），位置自洽。

现在上主菜。【推导·全程】**标准数据集完整链路手算**。本章其余示例与深入专题共用这组数：每一步都是整数或干净小数，纸面五分钟可推完。

```text
标准数据集：
  顶点   p_model = (1, 1, 0)
  模型   M = T(0, 1, 0) · Rz(90°)          先绕 z 转 90°，再抬升 1
  相机   eye = (0, 0, 5)，target = 原点，up = (0, 1, 0)
  投影   fovY = 90°，aspect = 4/3，N = 1，F = 9
  视口   800 × 600，位置 (0, 0)
```

第一站，模型空间 → 世界空间：先作用 Rz(90°)（离 v 近的先上场）。Rz(90°) 把 (x,y) 按 (x,y)→(−y,x) 翻转：(1,1) → (−1,1)，得 (−1, 1, 0)；再作用 T(0,1,0)：加 (0,1,0) → **世界坐标 (−1, 2, 0)**。

第二站，世界空间 → 观察空间：相机在 (0,0,5) 看原点，2.3 推过这台相机的视图矩阵是「旋转恒等 + 平移 (0,0,−5)」（zaxis = (0,0,1)，xaxis = (1,0,0)，yaxis = (0,1,0)）。**观察坐标 (−1, 2, −5)**——z = −5，在相机前方 5 个单位，这就是「深度 d = 5」。

第三站，观察空间 → 裁剪空间：先算投影矩阵的四个关键数。t = N·tan(45°) = 1，r = aspect·t = 4/3；第三行 α = −(F+N)/(F−N) = −10/8 = −1.25，β = −2NF/(F−N) = −18/8 = −2.25。逐分量：

```text
x_clip = (N/r)·x = (3/4)·(−1)          = −0.75
y_clip = (N/t)·y = 1·2                 =  2
z_clip = α·z + β = −1.25·(−5) − 2.25   =  4
w_clip = −z_view                       =  5
                             裁剪坐标 (−0.75, 2, 4, 5)
```

第四站，裁剪判定：−5 ≤ −0.75 ≤ 5 ✓，−5 ≤ 2 ≤ 5 ✓，−5 ≤ 4 ≤ 5 ✓——三项全过，保留。

第五站，透视除法：÷5 → **NDC (−0.15, 0.4, 0.8)**。

第六站，视口变换：x_win = 400·(−0.15) + 400 = **340**；y_win = 300·0.4 + 300 = **420**；z_win = 0.5·0.8 + 0.5 = **0.9**。落地：像素 (340, 420)，深度 0.9。

六站走完，「一个顶点的完整旅程」闭环——从模型里的一行坐标，到屏幕上一个确定的像素格子和一个确定的深度值。下面程序把同一顶点逐站打印，与手算对照：

```cpp
// ch02_mvp_pipeline.cpp —— 标准数据集：一个顶点从模型空间到窗口坐标的五站全程（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec3 { float x{}, y{}, z{}; };
struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };

inline Vec3 operator-(Vec3 a, Vec3 b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; }
inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }
inline Vec3 cross(Vec3 a, Vec3 b) {
    return {a.y*b.z - a.z*b.y, a.z*b.x - a.x*b.z, a.x*b.y - a.y*b.x};
}
inline Vec3 normalize(Vec3 a) { float l = std::sqrt(dot(a, a)); return {a.x/l, a.y/l, a.z/l}; }

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}
inline Mat4 mul(const Mat4& A, const Mat4& B) {   // 复合：先 B 后 A
    Mat4 r{};
    for (int i = 0; i < 4; ++i)
        for (int j = 0; j < 4; ++j)
            for (int k = 0; k < 4; ++k)
                r.m[i][j] += A.m[i][k] * B.m[k][j];
    return r;
}
inline Mat4 translate(float tx, float ty, float tz) {   // 平移：整体搬家
    Mat4 M{};
    M.m[0][0] = M.m[1][1] = M.m[2][2] = M.m[3][3] = 1.0f;
    M.m[0][3] = tx; M.m[1][3] = ty; M.m[2][3] = tz;
    return M;
}
inline Mat4 rotateZ(float deg) {         // 绕 z 轴旋转
    float rad = deg * 3.14159265f / 180.0f;
    float c = std::cos(rad), s = std::sin(rad);
    Mat4 M{};
    M.m[0][0] = c; M.m[0][1] = -s;
    M.m[1][0] = s; M.m[1][1] = c;
    M.m[2][2] = M.m[3][3] = 1.0f;
    return M;
}
inline Mat4 lookAt(Vec3 eye, Vec3 target, Vec3 up) {   // 视图矩阵（2.3 的构造）
    Vec3 zAxis = normalize(eye - target);
    Vec3 xAxis = normalize(cross(up, zAxis));
    Vec3 yAxis = cross(zAxis, xAxis);
    Mat4 V{};
    V.m[0][0] = xAxis.x; V.m[0][1] = xAxis.y; V.m[0][2] = xAxis.z; V.m[0][3] = -dot(xAxis, eye);
    V.m[1][0] = yAxis.x; V.m[1][1] = yAxis.y; V.m[1][2] = yAxis.z; V.m[1][3] = -dot(yAxis, eye);
    V.m[2][0] = zAxis.x; V.m[2][1] = zAxis.y; V.m[2][2] = zAxis.z; V.m[2][3] = -dot(zAxis, eye);
    V.m[3][3] = 1.0f;
    return V;
}
inline Mat4 perspective(float fovYDeg, float aspect, float n, float f) {   // 2.5 的矩阵
    float t = n * std::tan(fovYDeg * 3.14159265f / 180.0f * 0.5f);
    float r = aspect * t;
    Mat4 M{};
    M.m[0][0] = n / r;
    M.m[1][1] = n / t;
    M.m[2][2] = -(f + n) / (f - n);
    M.m[2][3] = -2.0f * f * n / (f - n);
    M.m[3][2] = -1.0f;
    return M;
}
inline Mat4 viewport(float x, float y, float width, float height) {   // 2.7 的矩阵
    Mat4 M{};
    M.m[0][0] = width  * 0.5f;  M.m[0][3] = x + width  * 0.5f;
    M.m[1][1] = height * 0.5f;  M.m[1][3] = y + height * 0.5f;
    M.m[2][2] = 0.5f;           M.m[2][3] = 0.5f;
    M.m[3][3] = 1.0f;
    return M;
}

int main() {
    // ── 标准数据集（2.7 手算与深入专题对账共用）──
    Mat4 M  = mul(translate(0, 1, 0), rotateZ(90.0f));  // 先绕 z 转 90°，再抬升 1
    Mat4 V  = lookAt({0, 0, 5}, {0, 0, 0}, {0, 1, 0});  // 相机在 (0,0,5) 看原点
    Mat4 P  = perspective(90.0f, 800.0f / 600.0f, 1, 9);// fovY=90°，aspect=4/3，n=1，f=9
    Mat4 VP = viewport(0, 0, 800, 600);

    Vec4 p{1, 1, 0, 1};                                  // 模型空间出发点
    std::printf("[第0站 模型空间]   p        = (%.0f, %.0f, %.0f, %.0f)\n", p.x, p.y, p.z, p.w);

    Vec4 world = apply(M, p);                            // 第1站：M
    std::printf("[第1站 世界空间]   M·p      = (%.0f, %.0f, %.0f, %.0f)   先转 90°(-1,1,0) 再抬 1\n",
                world.x, world.y, world.z, world.w);

    Vec4 view = apply(V, world);                         // 第2站：V
    std::printf("[第2站 观察空间]   V·M·p    = (%.0f, %.0f, %.0f, %.0f)   相机平移 z−=5\n",
                view.x, view.y, view.z, view.w);

    Vec4 clip = apply(P, view);                          // 第3站：P（裁剪坐标，四个分量都有意义）
    std::printf("[第3站 裁剪空间]   P·V·M·p  = (%.2f, %.2f, %.2f, %.2f)   w = −z_view = %.0f\n",
                clip.x, clip.y, clip.z, clip.w, clip.w);

    bool inside = -clip.w <= clip.x && clip.x <= clip.w &&
                  -clip.w <= clip.y && clip.y <= clip.w &&
                  -clip.w <= clip.z && clip.z <= clip.w; // 第4站：±w 裁剪判定（除法之前）
    std::printf("[第4站 裁剪判定]   −%.0f ≤ x,y,z ≤ %.0f ？ %s\n",
                clip.w, clip.w, inside ? "通过" : "裁掉");

    Vec4 ndc{clip.x / clip.w, clip.y / clip.w, clip.z / clip.w, 1.0f};   // 第5站：透视除法
    std::printf("[第5站 NDC]        ÷w       = (%.2f, %.2f, %.2f, %.0f)\n",
                ndc.x, ndc.y, ndc.z, ndc.w);

    Vec4 win = apply(VP, ndc);                           // 第6站：视口变换
    std::printf("[第6站 窗口坐标]   VP·ndc   = (%.1f, %.1f, %.2f, %.0f)   像素门口\n",
                win.x, win.y, win.z, win.w);

    // 与 2.7 手算对照（手算值：五站结果硬编码，容差内全等）
    assert(std::fabs(world.x + 1) < 1e-5 && std::fabs(world.y - 2) < 1e-5);
    assert(std::fabs(view.z + 5) < 1e-5);
    assert(std::fabs(clip.x + 0.75f) < 1e-5 && std::fabs(clip.z - 4) < 1e-5 && std::fabs(clip.w - 5) < 1e-5);
    assert(std::fabs(ndc.x + 0.15f) < 1e-5 && std::fabs(ndc.y - 0.4f) < 1e-5);
    assert(std::fabs(win.x - 340) < 1e-3 && std::fabs(win.y - 420) < 1e-3 && std::fabs(win.z - 0.9f) < 1e-5);
    std::printf("与手算五站结果全部一致\n");
    return 0;
}
```

### 2.8 法线变换：为什么是逆转置 (M⁻¹)ᵀ

事故现场：美术把一个圆柱沿 z 压扁成椭圆截面，模型一压扁光照就脏了——亮暗不对、立体感诡异。你检查代码：法线明明乘了模型矩阵呀？它确实被变换了，但**被错误地变换了**。这一节的结论先给：切向量用 M 变换没有争议，法线必须用**逆转置矩阵（inverse transpose matrix）(M⁻¹)ᵀ**。为什么？五行的代数推导给你钉死。

先想清楚法线的本质。它不是「随便一个方向」，而是**「垂直关系」的守护者**：法线 N 的存在意义是与表面切向 T 垂直，光照计算消费的正是这份垂直（N·L 的 N 必须真的垂直于表面）。变换物体时，表面跟着变、切向跟着变，法线的使命是**继续垂直**——注意，不是「跟着 M 变」。

【推导·全程】Lengyel 的代数论证，五行走完。设模型矩阵为 M，切向量 t 变换后 t′ = Mt；要找一个法线的变换，使 n′·t′ = 0 恒成立（只要原来垂直，变换后仍垂直）。候选 n′ = (M⁻¹)ᵀn，代入验证：

```text
n′ᵀ·t′ = ((M⁻¹)ᵀn)ᵀ·(Mt)          代入两个定义
       = nᵀ·M⁻¹·M·t                转置的乘积反序：(AB)ᵀ = BᵀAᵀ
       = nᵀ·t                      M⁻¹M = I，中间抵消（逆矩阵 = 变换的倒带）
       = 0                         原本垂直
```

五行代数，严丝合缝：**(M⁻¹)ᵀ 是「保持垂直关系」的那个变换**。注意推导里 M⁻¹ 与 M 的相遇不是巧合——逆转置的设计目的就是让「M 的形变」在法线身上被精确抵消，只留下旋转的部分。概念层再补一句（点到即止）：用代数语言说，法线本质是协变向量（covector），与切向量（逆变向量）天然对偶——Nathan Reed 从对偶视角给出同一结论的深化，有兴趣可延伸阅读（2.8 资源）。

ch01 深入专题的「高度场法线」在这里接上：那批由梯度与叉乘造出的法线，一旦所在的模型被非均匀缩放，就必须走今天这条路——同一批法线场景做「直接乘 vs 逆转置」的对照实验即可复用，一句后向指针，不再重推。

工程结论直接立住（化简边界）：**只含旋转与均匀缩放时，(M⁻¹)ᵀ 与 M 只差一个标量，normalize 之后等价**——因为旋转的正交性给 R⁻¹ = Rᵀ，均匀缩放 s 给 S⁻¹ = (1/s)I，合起来 (M⁻¹)ᵀ = (1/s)·R ∝ M。所以「均匀缩放随便乘、非均匀缩放必须逆转置」。还有一条铁纪律：**不管走哪条路，变换后的法线必须重新 normalize**——非均匀缩放的逆转置天然不保长度，逆矩阵还可能引入分数长度。引擎里的名字：法线矩阵（normal matrix）= model 矩阵去掉平移的 3×3 部分，再做逆转置。前向指针一句：切线空间与法线贴图将在第 4 章展开，那里 (M⁻¹)ᵀ 还会再出场。

```cpp
// ch02_normal_transform.cpp —— 法线变换对账：直接乘 M vs 逆转置 (M⁻¹)ᵀ（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec3 { float x{}, y{}, z{}; };
struct Mat4 { float m[4][4]; };

inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }
inline Vec3 scaleV(Vec3 a, float s) { return {a.x * s, a.y * s, a.z * s}; }
inline Vec3 normalize(Vec3 a) { float l = std::sqrt(dot(a, a)); return {a.x/l, a.y/l, a.z/l}; }

inline Vec3 applyDir(const Mat4& M, Vec3 d) {     // 只作用线性部分：当方向向量（w=0）用
    return {M.m[0][0]*d.x + M.m[0][1]*d.y + M.m[0][2]*d.z,
            M.m[1][0]*d.x + M.m[1][1]*d.y + M.m[1][2]*d.z,
            M.m[2][0]*d.x + M.m[2][1]*d.y + M.m[2][2]*d.z};
}
inline Mat4 mul(const Mat4& A, const Mat4& B) {
    Mat4 r{};
    for (int i = 0; i < 4; ++i)
        for (int j = 0; j < 4; ++j)
            for (int k = 0; k < 4; ++k)
                r.m[i][j] += A.m[i][k] * B.m[k][j];
    return r;
}
inline Mat4 scale(float sx, float sy, float sz) {      // 缩放矩阵（对角）
    Mat4 M{};
    M.m[0][0] = sx; M.m[1][1] = sy; M.m[2][2] = sz; M.m[3][3] = 1.0f;
    return M;
}
inline Mat4 rotateZ(float deg) {                       // 旋转矩阵（正交块）
    float rad = deg * 3.14159265f / 180.0f;
    float c = std::cos(rad), s = std::sin(rad);
    Mat4 M{};
    M.m[0][0] = c; M.m[0][1] = -s;
    M.m[1][0] = s; M.m[1][1] = c;
    M.m[2][2] = M.m[3][3] = 1.0f;
    return M;
}
inline Mat4 transpose3x3(const Mat4& M) {              // 3×3 线性部分转置
    Mat4 R{};
    for (int i = 0; i < 3; ++i) for (int j = 0; j < 3; ++j) R.m[i][j] = M.m[j][i];
    R.m[3][3] = 1.0f;
    return R;
}
inline Mat4 inverse3x3(const Mat4& M) {                // 3×3 伴随式求逆（教学版，det=0 时未拦截）
    float a = M.m[0][0], b = M.m[0][1], c = M.m[0][2];
    float d = M.m[1][0], e = M.m[1][1], f = M.m[1][2];
    float g = M.m[2][0], h = M.m[2][1], i = M.m[2][2];
    float A =  (e*i - f*h), B = -(d*i - f*g), C =  (d*h - e*g);
    float D = -(b*i - c*h), E =  (a*i - c*g), F = -(a*h - b*g);
    float G =  (b*f - c*e), H = -(a*f - c*d), I =  (a*e - b*d);
    float det = a*A + b*B + c*C;
    Mat4 R{};
    R.m[0][0] = A/det; R.m[0][1] = D/det; R.m[0][2] = G/det;
    R.m[1][0] = B/det; R.m[1][1] = E/det; R.m[1][2] = H/det;
    R.m[2][0] = C/det; R.m[2][1] = F/det; R.m[2][2] = I/det;
    R.m[3][3] = 1.0f;
    return R;
}
inline Mat4 normalMatrix(const Mat4& M) {              // 法线矩阵 = model 3×3 部分的逆转置
    return transpose3x3(inverse3x3(M));
}

int main() {
    // ── 事故现场：scale(1, 1, 0.5) 把模型沿 z 压扁一半 ──
    Mat4 S = scale(1, 1, 0.5f);
    Vec3 t = normalize({ 1, 0, 1});                    // 斜面的切向量
    Vec3 n = normalize({-1, 0, 1});                    // 斜面的法向量（n·t = 0）
    std::printf("[压扁前]  t=(%.4f, 0, %.4f)  n=(%.4f, 0, %.4f)  n·t = %+.5f\n",
                t.x, t.z, n.x, n.z, dot(n, t));

    // 路 A：直接乘 M —— 切向量合法，法向量非法
    Vec3 t2 = applyDir(S, t);
    Vec3 nBad = normalize(applyDir(S, n));
    std::printf("[直接乘M] n' = (%.4f, 0, %.4f)  n'·t' = %+.4f   <- 不再垂直，光照必脏\n",
                nBad.x, nBad.z, dot(nBad, t2));

    // 路 B：逆转置 —— 垂直关系保住
    Mat4 NT = normalMatrix(S);                         // 对角矩阵的逆转置 = 分量取倒数
    Vec3 nGood = normalize(applyDir(NT, n));
    std::printf("[逆转置]  n' = (%.4f, 0, %.4f)  n'·t' = %+.4f   <- 垂直保住（变换后已 normalize）\n",
                nGood.x, nGood.z, dot(nGood, t2));

    // ── 化简边界：旋转 + 均匀缩放下，直接乘也侥幸可用 ──
    Mat4 M2 = mul(rotateZ(90.0f), scale(2, 2, 2));     // 先均匀放大 2 倍再转 90°
    Vec3 t3 = applyDir(M2, t);
    Vec3 nDirect = normalize(applyDir(M2, n));         // 直接乘
    Vec3 nProper = normalize(applyDir(normalMatrix(M2), n));   // 逆转置
    std::printf("[均匀缩放] 直接乘 n·t' = %+.5f   逆转置 n·t' = %+.5f   <- 归一化后两条路同向\n",
                dot(nDirect, t3), dot(nProper, t3));

    assert(dot(nBad, t2) < -0.4f);                     // 直接乘：明显不垂直
    assert(std::fabs(dot(nGood, t2)) < 1e-5);          // 逆转置：垂直保住
    assert(std::fabs(dot(nDirect, t3)) < 1e-5 && std::fabs(dot(nProper, t3)) < 1e-5);
    std::printf("法线变换对账完成：切向量用 M，法线用 (M^-1)^T\n");
    return 0;
}
```

```text
[直接乘M] n' = (-0.8944, 0, 0.4472)  n'·t' = -0.4743   <- 不再垂直，光照必脏
[逆转置]  n' = (-0.4472, 0, 0.8944)  n'·t' = +0.0000   <- 垂直保住（变换后已 normalize）
[均匀缩放] 直接乘 n·t' = +0.00000   逆转置 n·t' = +0.00000   <- 归一化后两条路同向
法线变换对账完成：切向量用 M，法线用 (M^-1)^T
```

读表一处：压扁后的真实表面，切向是 (1, 0, 0.5) 方向——逆转置给出的法线 (−0.447, 0, 0.894) 与它点乘严格为 0，**它就是变形后表面的真正法线**；而直接乘 M 的产物点乘 −0.474，歪了 118° 里的 28°——光照拿它去算 N·L，脏是必然的。

**切向量用 M、法线用 (M⁻¹)ᵀ——法线不是方向，是「垂直关系」的守护者。**

### 2.9 API 差异与坑点地图：同一理论，几套约定

事故现场：同一段投影代码，从 OpenGL 教程搬进 Vulkan 工程，画面「上下镜像 + 近处一截物体凭空消失」。不是 bug——**兑现 ch01 1.7 挂账**：那里说「跨 API 的恩怨到对应节再结」「第 3/6 节跨 API 坑点全部溯源至此」，本节就是约定之战的正式结算场（理论层）。先声明边界：本节只是理论对照地图，全程不涉 API 实操；坑点的实弹复现，第 3 节（OpenGL）与第 6 节（Vulkan）各领一份。

先把各家 NDC 的约定摊在同一张表里（TU Wien primer 与各家官方文档口径）：

| API | NDC x 朝向 | NDC y 朝向 | NDC z 范围 | 惯用称呼 |
|---|---|---|---|---|
| OpenGL | 右 | 上 | [−1, 1] | NO（negative one） |
| Vulkan | 右 | **下** | **[0, 1]** | ZO（zero to one） |
| Direct3D | 右 | 下 | [0, 1] | ZO |
| Metal | 右 | 下 | [0, 1] | ZO |

手性注记：TU Wien 的 primer 明确指出 OpenGL 与 Vulkan 的 NDC **手性相反**（GL 左手、Vulkan 右手）——同一个「标准化设备坐标」名字下，藏着两套镜像世界。经典症状由此可解释：OpenGL 的投影矩阵（y 朝上、z ∈ [−1,1]）直接搬进 Vulkan，y 轴翻转 → **画面上下镜像**；z 值落在 [−1, 0) 的那一整段深度带超出 Vulkan 的 [0,1] 判据 → **近处一截物体被整批裁掉**（深入专题第五部分给了这张表数值版）。这是检验标准③「镜像/看不见」症状最著名的理论出处。

弥合机制存在性声明（一句级，实操归第 3/6 节）：OpenGL 4.5 的 glClipControl 可切到 ZO 口径（ARB_clip_control）；Vulkan 侧 VK_EXT_depth_clip_control 可切回 [−1,1]；数学库则显式分叉——GLM 的 `GLM_FORCE_DEPTH_ZERO_TO_ONE` 与 perspectiveZO/orthoZO、glMatrix 的 ZO 后缀函数，都是「z 范围双口径」的工程佐证。另有 reversed-Z 一句：把深度范围倒挂（近=1 远=0，Vulkan 的 minDepth/maxDepth 允许）配合浮点深度缓冲，能让远处精度大幅提升——机制在第 3 章才好讲清，先记名字。

矩阵约定的两派差异（后向引用 ch01 1.7，一句收束）：存储主序与乘法方向是正交的两件事（fgiesen 的原文论证），GLM 与 DirectXMath 是两端代表——判断陌生代码先看 `M * v` 还是 `v * M`，再看内存布局。深度非线性第一印象（深入归第 3 章）：透视投影后的深度值与 1/z 成正比而非线性于距离——精度全部堆在近平面附近，**zNear 逼近 0 是深度精度第一杀手**（zFar 拉远伤害小得多）；两个共面物体因深度精度不足互相闪烁，就是 z-fighting——深度缓冲（depth buffer）的著名痼疾。代数勾连一句：z_ndc = −(F+N)/(F−N) − 2NF/((F−N)·(−z))——把 2.5 的第三行除以 w 后恰是 a + b/z 型，**非线性是推导的直接副产品，不是硬件玄学**（深入专题第四部分有扫描表）。

**理论只有一套，约定各有一套——写投影矩阵前先问：我的 NDC z 从几到几、y 朝哪边？**

### 2.10 数学库落地：lookAt/ortho/perspective/viewport 进库（P3·M0 收官，实践任务主场）

开篇先兑现一个显式挂账：ch01 1.10 立过一份「显式缺席声明」——lookAt、ortho、perspective、viewport 不在第 1 章 API 里，它们是变换链的零件，将在第 2 章实现。今天四件武器全部进库。对位 Projects.md 的 P3·M0 原文：「Vec2/3/4、Mat4 及 lookAt/ortho/perspective/viewport，每函数注明几何意义，性质单测全绿」——**本节跑绿的那一刻，P3·M0 收官**。

API 签名与口径决策，正文显式声明（这是本章最后一次大字报口径）：

- `lookAt(eye, target, up)`——右手系、相机看 −Z（2.3 的推导原样落地）；
- `ortho(l, r, b, t, n, f)` 与 `perspective(fovYDeg, aspect, n, f)`——**n、f 均取正距离参数、内部取负**（OpenGL 工程口径，与 GLM 对齐）。2.4/2.5 推导用的 GAMES101 负值口径在此显式换算：z 行换算在 2.4 已逐步给出，透视的整体矩阵在 2.5 已逐项到达——两版代数上只差一次 z 轴翻转（近平面映 −1 还是 +1），属于 2.9 的约定差异。本章库选 **NO 口径**（NDC z ∈ [−1,1]，近平面 → −1）；ZO 变体（orthoZO/perspectiveZO）作为任务 1 的可选进阶；
- `viewport(x, y, width, height)`——2.7 的仿射映射，z 顺带映到默认深度范围 [0,1]。

同时新增一位清单外成员：`inverse(M)`，通用 4×4 逆（Gauss-Jordan 消元，教学注释一句几何意义：**逆矩阵 = 变换的倒带**）。它是变换链的配套设施，服务两件事：2.8 的法线矩阵在一般矩阵下的完整实现需要「求逆」这一步；性质测试要验证 view·view⁻¹ = I 这类「倒带归零」性质。

性质测试清单（裁判纪律全部复用 ch01 1.10 基建：assert 式自测、1e-5 量级相对容差带 max(1,|a|,|b|) 地板、NDEBUG 排雷——不再重述理由）：透视除法后近大远小（同尺寸物体两深度，屏幕跨度近大远小）；正交保平行与 w=1；近平面角点 z_ndc = −1、远平面角点 z_ndc = +1（NO 口径）；lookAt 把 eye 变到原点、target 落在 −Z；NDC 边界点经视口变换落到预期像素。数学上必须成立的关系比任何「标准答案」都可信——库函数结果和手推对不上时，先让性质测试当裁判。

```cpp
// ch02_mathlib_cameras.cpp —— 四件武器 lookAt/ortho/perspective/viewport + inverse 进库，性质测试全绿（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec3 { float x{}, y{}, z{}; };        // 纯值类型：rule of zero（ch01 1.10）
struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };              // 行主序存储；数学按「列向量右乘」约定（ch01 1.7）

inline Vec3 operator-(Vec3 a, Vec3 b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; } // 从 b 指向 a 的箭头
inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }            // 方向一致性
inline Vec3 cross(Vec3 a, Vec3 b) {      // 垂直于 a、b 的向量（右手系朝向）
    return {a.y*b.z - a.z*b.y, a.z*b.x - a.x*b.z, a.x*b.y - a.y*b.x};
}
inline float length(Vec3 a) { return std::sqrt(dot(a, a)); }   // 向量长度
inline Vec3 normalize(Vec3 a) {         // 拧到长度 1、方向不变
    float len = length(a);
    assert(len > 0.0f);
    return {a.x / len, a.y / len, a.z / len};
}

inline Vec4 apply(const Mat4& M, Vec4 v) {   // M·v：列向量右乘
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}
inline Mat4 mul(const Mat4& A, const Mat4& B) {   // 复合：先作用 B，再作用 A
    Mat4 r{};
    for (int i = 0; i < 4; ++i)
        for (int j = 0; j < 4; ++j)
            for (int k = 0; k < 4; ++k)
                r.m[i][j] += A.m[i][k] * B.m[k][j];
    return r;
}
inline Mat4 identity() {                 // 什么都不做
    Mat4 M{};
    for (int i = 0; i < 4; ++i) M.m[i][i] = 1.0f;
    return M;
}
inline Mat4 translate(float tx, float ty, float tz) {  // 平移：整体搬家（ch01 1.6）
    Mat4 M = identity();
    M.m[0][3] = tx; M.m[1][3] = ty; M.m[2][3] = tz;
    return M;
}
inline Mat4 rotateZ(float deg) {         // 绕 z 轴旋转：xy 平面转身，z 不动
    float rad = deg * 3.14159265f / 180.0f;
    float c = std::cos(rad), s = std::sin(rad);
    Mat4 M = identity();
    M.m[0][0] = c; M.m[0][1] = -s;
    M.m[1][0] = s; M.m[1][1] = c;
    return M;
}
inline Mat4 scale(float sx, float sy, float sz) {      // 缩放：绕原点胖瘦
    Mat4 M{};
    M.m[0][0] = sx; M.m[1][1] = sy; M.m[2][2] = sz; M.m[3][3] = 1.0f;
    return M;
}

// ══════════ 本章新成员：四件武器 + inverse（P3·M0 收官清单）══════════

inline Mat4 lookAt(Vec3 eye, Vec3 target, Vec3 up) {   // 视图矩阵：把相机请回原点、朝 −Z
    Vec3 zAxis = normalize(eye - target);              // 相机 z 基指向「相机后方」
    Vec3 xAxis = normalize(cross(up, zAxis));          // 世界 up 只用来定向
    Vec3 yAxis = cross(zAxis, xAxis);                  // 叉乘回推第三轴，天然正交
    Mat4 V{};                                          // 基向量按行摆放 = 逆 = 转置（ch01 1.5）
    V.m[0][0] = xAxis.x; V.m[0][1] = xAxis.y; V.m[0][2] = xAxis.z; V.m[0][3] = -dot(xAxis, eye);
    V.m[1][0] = yAxis.x; V.m[1][1] = yAxis.y; V.m[1][2] = yAxis.z; V.m[1][3] = -dot(yAxis, eye);
    V.m[2][0] = zAxis.x; V.m[2][1] = zAxis.y; V.m[2][2] = zAxis.z; V.m[2][3] = -dot(zAxis, eye);
    V.m[3][3] = 1.0f;
    return V;
}

inline Mat4 ortho(float l, float r, float b, float t, float n, float f) {
    // 正交投影：长方体 → 规范立方体；n、f 传「正的距离」，内部取负（OpenGL 工程口径）
    Mat4 M{};                                          // 视空间 z=−n 映到 −1、z=−f 映到 +1（NO 口径）
    M.m[0][0] =  2.0f / (r - l);  M.m[0][3] = -(r + l) / (r - l);   // x：缩放到 2 再居中
    M.m[1][1] =  2.0f / (t - b);  M.m[1][3] = -(t + b) / (t - b);   // y：同构
    M.m[2][2] = -2.0f / (f - n);  M.m[2][3] = -(f + n) / (f - n);   // z：GL 口径近远对调 → 负号
    M.m[3][3] = 1.0f;                                  // w 恒为 1：透视除法空操作
    return M;
}

inline Mat4 perspective(float fovYDeg, float aspect, float n, float f) {
    // 透视投影：视锥体 → 规范立方体；fovY 竖直视场角（度）、aspect = 宽/高、n/f 正距离（NO 口径）
    float t = n * std::tan(fovYDeg * 3.14159265f / 180.0f * 0.5f);  // 近平面半高：t = n·tan(fovY/2)
    float r = aspect * t;                              // 近平面半宽：r = aspect·t
    Mat4 M{};
    M.m[0][0] = n / r;                                 // 对称视锥（l=−r）下 2n/(r−l) 化简为 n/r
    M.m[1][1] = n / t;                                 // 对称视锥（b=−t）下 2n/(t−b) 化简为 n/t
    M.m[2][2] = -(f + n) / (f - n);                    // z 行：两个 z 约束联立解的产物
    M.m[2][3] = -2.0f * f * n / (f - n);
    M.m[3][2] = -1.0f;                                 // 第四行 (0,0,−1,0)：w = −z，偷记深度
    return M;
}

inline Mat4 viewport(float x, float y, float width, float height) {
    // 视口变换：NDC [−1,1]² → 窗口 [x, x+width]×[y, y+height]，z 顺带映到深度范围 [0,1]
    Mat4 M{};                                          // 缩放 (w/2, h/2) + 平移 (x+w/2, y+h/2)
    M.m[0][0] = width  * 0.5f;  M.m[0][3] = x + width  * 0.5f;
    M.m[1][1] = height * 0.5f;  M.m[1][3] = y + height * 0.5f;
    M.m[2][2] = 0.5f;           M.m[2][3] = 0.5f;      // z_ndc ∈ [−1,1] → [0,1]（默认深度范围）
    M.m[3][3] = 1.0f;
    return M;
}

inline Mat4 inverse(Mat4 A) {            // 逆矩阵 = 变换的倒带（Gauss-Jordan，[A|I] → [I|A⁻¹]）
    Mat4 I = identity();
    for (int col = 0; col < 4; ++col) {
        int piv = col;                              // 选绝对值最大的主元，稳住数值
        for (int row = col + 1; row < 4; ++row)
            if (std::fabs(A.m[row][col]) > std::fabs(A.m[piv][col])) piv = row;
        for (int j = 0; j < 4; ++j) {               // 行交换（两矩阵同步换）
            std::swap(A.m[col][j], A.m[piv][j]);
            std::swap(I.m[col][j], I.m[piv][j]);
        }
        float d = A.m[col][col];
        for (int j = 0; j < 4; ++j) { A.m[col][j] /= d; I.m[col][j] /= d; }   // 主元归一
        for (int row = 0; row < 4; ++row) {         // 消掉本列其余元素
            if (row == col) continue;
            float f = A.m[row][col];
            for (int j = 0; j < 4; ++j) { A.m[row][j] -= f * A.m[col][j]; I.m[row][j] -= f * I.m[col][j]; }
        }
    }
    return I;
}

inline bool approx(float a, float b, float eps = 1e-5f) {   // 相对容差比较（ch01 1.10 纪律）
    float s = std::fmax(1.0f, std::fmax(std::fabs(a), std::fabs(b)));
    return std::fabs(a - b) <= eps * s;
}
inline bool approxV(const Vec4& a, const Vec4& b) {
    return approx(a.x, b.x) && approx(a.y, b.y) && approx(a.z, b.z) && approx(a.w, b.w);
}
inline bool approxM(const Mat4& A, const Mat4& B) {
    for (int i = 0; i < 4; ++i) for (int j = 0; j < 4; ++j)
        if (!approx(A.m[i][j], B.m[i][j])) return false;
    return true;
}

int main() {
    // ── 性质 1：lookAt 把 eye 变到原点、target 落在 −Z ──
    Vec3 eye{3, 3, 3}, target{0, 0, 0}, up{0, 1, 0};
    Mat4 V = lookAt(eye, target, up);
    Vec4 eyeT  = apply(V, {eye.x, eye.y, eye.z, 1});
    Vec4 tgtT  = apply(V, {target.x, target.y, target.z, 1});
    assert(approxV(eyeT, {0, 0, 0, 1}));                        // 相机回到原点
    assert(approx(eyeT.x, 0) && approx(eyeT.y, 0) && approx(eyeT.z, 0));
    assert(approx(tgtT.x, 0) && approx(tgtT.y, 0) && tgtT.z < 0.0f);  // 目标在 −Z 上
    std::printf("[lookAt]   eye -> (%.3f, %.3f, %.3f)  target -> (%.3f, %.3f, %.3f)\n",
                eyeT.x, eyeT.y, eyeT.z, tgtT.x, tgtT.y, tgtT.z);

    // ── 性质 2：透视投影近/远平面角点 z_ndc = −1 / +1，w_clip = −z_view ──
    Mat4 P = perspective(90.0f, 4.0f / 3.0f, 1.0f, 9.0f);
    Vec4 nearC = apply(P, {2, -1.5f, -1, 1});                   // 近平面角点（t·aspect, t, n）
    Vec4 farC  = apply(P, {6, 4.5f, -9, 1});                    // 远平面角点（= 近角点 ×f/n）
    assert(approx(nearC.z / nearC.w, -1.0f));
    assert(approx(farC.z  / farC.w,  1.0f));
    assert(approx(nearC.w, 1.0f) && approx(farC.w, 9.0f));      // w_clip = −z_view
    std::printf("[persp]    近角点 z_ndc = %+.4f  远角点 z_ndc = %+.4f  w_clip = z_view 负值拷贝\n",
                nearC.z / nearC.w, farC.z / farC.w);

    // ── 性质 3：正交投影保平行、w 恒 1、角点映射 ──
    Mat4 O = ortho(-4, 4, -3, 3, 1, 9);
    Vec4 oA = apply(O, {-4, -3, -1, 1});                        // 左下近角
    Vec4 oB = apply(O, { 4,  3, -9, 1});                        // 右上远角
    Vec4 d1 = apply(O, {2, 0, 0, 0});                           // 方向向量（w=0）：只测线性部分
    Vec4 d2 = apply(O, {2, 0, 0, 0});
    assert(approxV(oA, {-1, -1, -1, 1}) && approxV(oB, {1, 1, 1, 1}));
    assert(approx(d1.x, d2.x) && approx(oA.w, 1.0f) && approx(oB.w, 1.0f));
    std::printf("[ortho]    角点 (±l,±b,−n)/(±r,±t,−f) -> (%.1f,%.1f,%.1f)/(%.1f,%.1f,%.1f)，w 恒 1\n",
                oA.x, oA.y, oA.z, oB.x, oB.y, oB.z);

    // ── 性质 4：透视除法后近大远小（同尺寸竖直段，近段 NDC 跨度 = 远段两倍）──
    Vec4 n1 = apply(P, {0, -0.5f, -2, 1}), n2 = apply(P, {0, 0.5f, -2, 1});
    Vec4 f1 = apply(P, {0, -0.5f, -4, 1}), f2 = apply(P, {0, 0.5f, -4, 1});
    float spanNear = (n2.y/n2.w) - (n1.y/n1.w);
    float spanFar  = (f2.y/f2.w) - (f1.y/f1.w);
    assert(approx(spanNear, 2.0f * spanFar));                   // 深度翻倍 → 屏幕尺寸减半
    std::printf("[divide]   同尺寸段 NDC 跨度：深度 2 -> %.4f，深度 4 -> %.4f（近大远小）\n",
                spanNear, spanFar);

    // ── 性质 5：NDC 边界点经视口变换落到预期像素 ──
    Mat4 VP = viewport(0, 0, 800, 600);
    Vec4 bl = apply(VP, {-1, -1, 0, 1});                        // 左下角
    Vec4 tr = apply(VP, { 1,  1, 0, 1});                        // 右上角
    assert(approxV(bl, {0,   0,   0.5f, 1}) && approxV(tr, {800, 600, 0.5f, 1}));
    std::printf("[viewport] NDC (-1,-1) -> (%.0f, %.0f)   (+1,+1) -> (%.0f, %.0f)\n",
                bl.x, bl.y, tr.x, tr.y);

    // ── 性质 6：逆矩阵 = 倒带（V·V⁻¹ = I；正交基下逆 = 转置的交叉验证）──
    Mat4 VI = mul(V, inverse(V));
    assert(approxM(VI, identity()));
```

## 深入专题：一个顶点的完整旅程数值解剖——逐站对账与症状复现实验场

全章合流处。2.1 立了地图，2.3–2.7 修了五段路，2.10 交付了工程队——本专题把一切收进同一条流水线，并直接训练检验标准③「症状定位」：阶段学习目标的那句「画面不对能定位是哪一环出错」，在这里从口号变成操作手册。实验设计四件事（一个完整可编译程序承载）：

1. **三个顶点全程逐站打印**：中景点、远景点、相机身后点各一——每站一行，身后点用 ±w 判据显式判裁；

3. **症状复现开关**：预置五个「事故开关」逐个打开——忘透视除法、连乘次序颠倒、Z 朝向弄反、aspect 弄反、忘视口变换——每个开关配「症状描述 + 诊断数值指纹」；

```cpp
// ch02_vertex_journey.cpp —— 顶点旅程数值解剖：逐站对账 + 五个事故开关 + 深度非线性扫描（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>
#include <initializer_list>   // 花括号范围 for 需要（MSVC 不会随 cstdio 隐式提供）

struct Vec3 { float x{}, y{}, z{}; };
struct Vec4 { float x{}, y{}, z{}, w{}; };
struct Mat4 { float m[4][4]; };

inline Vec3 operator-(Vec3 a, Vec3 b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; }
inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }
inline Vec3 cross(Vec3 a, Vec3 b) {
    return {a.y*b.z - a.z*b.y, a.z*b.x - a.x*b.z, a.x*b.y - a.y*b.x};
}
inline Vec3 normalize(Vec3 a) { float l = std::sqrt(dot(a, a)); return {a.x/l, a.y/l, a.z/l}; }
inline Vec4 apply(const Mat4& M, Vec4 v) {
    return {M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
            M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
            M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
            M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}
inline Mat4 mul(const Mat4& A, const Mat4& B) {
    Mat4 r{};
    for (int i = 0; i < 4; ++i)
        for (int j = 0; j < 4; ++j)
            for (int k = 0; k < 4; ++k)
                r.m[i][j] += A.m[i][k] * B.m[k][j];
    return r;
}
inline Mat4 translate(float tx, float ty, float tz) {
    Mat4 M{};
    M.m[0][0] = M.m[1][1] = M.m[2][2] = M.m[3][3] = 1.0f;
    M.m[0][3] = tx; M.m[1][3] = ty; M.m[2][3] = tz;
    return M;
}
inline Mat4 rotateZ(float deg) {
    float rad = deg * 3.14159265f / 180.0f;
    float c = std::cos(rad), s = std::sin(rad);
    Mat4 M{};
    M.m[0][0] = c; M.m[0][1] = -s;
    M.m[1][0] = s; M.m[1][1] = c;
    M.m[2][2] = M.m[3][3] = 1.0f;
    return M;
}
inline Mat4 lookAt(Vec3 eye, Vec3 target, Vec3 up) {
    Vec3 zAxis = normalize(eye - target);              // 改成 target − eye 就是事故开关 3
    Vec3 xAxis = normalize(cross(up, zAxis));
    Vec3 yAxis = cross(zAxis, xAxis);
    Mat4 V{};
    V.m[0][0] = xAxis.x; V.m[0][1] = xAxis.y; V.m[0][2] = xAxis.z; V.m[0][3] = -dot(xAxis, eye);
    V.m[1][0] = yAxis.x; V.m[1][1] = yAxis.y; V.m[1][2] = yAxis.z; V.m[1][3] = -dot(yAxis, eye);
    V.m[2][0] = zAxis.x; V.m[2][1] = zAxis.y; V.m[2][2] = zAxis.z; V.m[2][3] = -dot(zAxis, eye);
    V.m[3][3] = 1.0f;
    return V;
}
inline Mat4 perspective(float fovYDeg, float aspect, float n, float f) {
    float t = n * std::tan(fovYDeg * 3.14159265f / 180.0f * 0.5f);
    float r = aspect * t;
    Mat4 M{};
    M.m[0][0] = n / r;
    M.m[1][1] = n / t;
    M.m[2][2] = -(f + n) / (f - n);
    M.m[2][3] = -2.0f * f * n / (f - n);
    M.m[3][2] = -1.0f;
    return M;
}
inline Mat4 viewport(float x, float y, float width, float height) {
    Mat4 M{};
    M.m[0][0] = width  * 0.5f;  M.m[0][3] = x + width  * 0.5f;
    M.m[1][1] = height * 0.5f;  M.m[1][3] = y + height * 0.5f;
    M.m[2][2] = 0.5f;           M.m[2][3] = 0.5f;
    M.m[3][3] = 1.0f;
    return M;
}

inline Mat4 lookAtWrongZ(Vec3 eye, Vec3 target, Vec3 up) {   // 事故开关 3：z 基写成 target − eye
    Vec3 zAxis = normalize(target - eye);              // 两派混用的典型错法（D3D 口径闯进右手系）
    Vec3 xAxis = normalize(cross(up, zAxis));
    Vec3 yAxis = cross(zAxis, xAxis);
    Mat4 V{};
    V.m[0][0] = xAxis.x; V.m[0][1] = xAxis.y; V.m[0][2] = xAxis.z; V.m[0][3] = -dot(xAxis, eye);
    V.m[1][0] = yAxis.x; V.m[1][1] = yAxis.y; V.m[1][2] = yAxis.z; V.m[1][3] = -dot(yAxis, eye);
    V.m[2][0] = zAxis.x; V.m[2][1] = zAxis.y; V.m[2][2] = zAxis.z; V.m[2][3] = -dot(zAxis, eye);
    V.m[3][3] = 1.0f;
    return V;
}

bool insideClipVolume(Vec4 c) {                // −w ≤ x, y, z ≤ w
    return -c.w <= c.x && c.x <= c.w && -c.w <= c.y && c.y <= c.w && -c.w <= c.z && c.z <= c.w;
}

    Vec4 view  = apply(V, world);

                p.x, p.y, p.z, world.x, world.y, world.z, view.x, view.y, view.z);
    std::printf("  -> 裁剪(%.3f,%.3f,%.3f,w=%.2f)  ±w 判定：%s\n",
                clip.x, clip.y, clip.z, clip.w,
                insideClipVolume(clip) ? "保留" : "裁剪");
    if (insideClipVolume(clip)) {
        Vec4 ndc{clip.x/clip.w, clip.y/clip.w, clip.z/clip.w, 1};
        Vec4 win = apply(VP, ndc);
        std::printf("  -> NDC(%.4f,%.4f,%.4f) -> 窗口(%.1f, %.1f, z=%.3f)\n",
                    ndc.x, ndc.y, ndc.z, win.x, win.y, win.z);

}
```

第五部分再点一句 2.9 的题：GL 矩阵直接搬进 Vulkan，深度带 d ∈ (1, 1.8) 的点 z_ndc < 0、整段被裁——「近处消失」的数值版。第四部分的扫描表则把 2.9 的深度非线性从一句话变成一列数：近处 1 个单位深度吃掉 1.125 个 NDC，远处 4 个单位只吃 0.2——zNear 取太小的代价，先在这里见个面，机制将在第 3 章展开。

收束：「画面不对能定位哪一环出错」的阶段地图至此真正展开——开篇立的承诺全部兑付。工程注记：任务 1 完成后，用你自己的库重写本专题的链路函数（lookAt/perspective/viewport 换成库调用），顺手把五个开关固化成断言。

## 常见误区

1. **连乘次序随手写（M·V·P·v）**。症状：全体顶点飞出画面或完全错乱；病根：忘了「离 v 近的先作用」，三个矩阵职责清楚但顺序装反；纠偏：P·V·M·v 从右往左读——先摆物体（M）、再摆相机（V）、最后按快门（P），乘法方向约定的排雷沿用 ch01 1.7 两问自查。
2. **忘透视除法**。症状：投影后坐标量级怪异、直接当屏幕坐标用全飞；病根：把裁剪坐标当 NDC，漏掉管线里固定的那次 ÷w；纠偏：投影后必除 w；裁剪判定在除法前用 ±w 做——深入专题开关 1 的指纹是「坐标量纲不像像素」。
3. **Z 朝向 / forward 符号弄反**。症状：画面镜像或整个深度带被裁；病根：z 基 = eye − target（右手系看 −Z）写成 target − eye（D3D 口径），两派混用；纠偏：选定「右手系、相机看 −Z」全程声明一致，跨 API 先查 Z 朝向（ch01 1.7 + 2.9 对照）。
4. **n/f 符号两套口径混用**。症状：手推结果与库函数对不上、深度方向反了；病根：GAMES101 推导用负值（n、f 是负数且 n > f）而 glOrtho/GLM 传正距离内部取负，两口径在草稿纸上打架；纠偏：推导前声明口径，库 API 统一正距离参数（2.10 口径决策）。
5. **fov/aspect 弄反或 aspect 定义用错**。症状：画面拉伸变形；病根：fovY 是**竖直**方向视场角、r = aspect·t 且 aspect = **宽/高**，参数填反或用了高/宽；纠偏：记「竖 fov + 宽比高」，用数值例自测（aspect = 2 时 r 是 t 的两倍）。
6. **近平面取 0（或逼近 0）**。症状：远处物体闪烁、深度错乱（z-fighting 第一印象）；病根：zNear → 0 时深度精度坍塌——精度堆在近平面附近，zNear 是第一杀手，zFar 拉远伤害小得多；纠偏：zNear 取尽可能大的正值，深度非线性机制将在第 3 章展开（2.9 + 深入专题扫描表）。
7. **法线直接用 model 矩阵变换**。症状：非均匀缩放/压扁模型后光照脏掉；病根：法线的本质是垂直关系不是方向，直接乘 M 在非均匀缩放下不再垂直；纠偏：法线矩阵 = model 3×3 部分逆转置 (M⁻¹)ᵀ，变换后 normalize；旋转 + 均匀缩放可退化为直接乘，但要知道边界（2.8）。
8. **深度范围 GL/D3D 口径混用**。症状：半个深度带的物体消失或只有一半深度可用；病根：OpenGL NDC z ∈ [−1,1]、Vulkan/D3D z ∈ [0,1]，投影矩阵与目标 API 不配套；纠偏：写投影矩阵前先问「我的 NDC z 从几到几」（2.9 速查表）；GLM 的 NO/ZO、glClipControl、VK_EXT_depth_clip_control 是工程弥合口，实操在第 3/6 节。

## 参考答案

### 自测题

**1.**
- 第一步相似三角形：视锥内点 (x, y, z)（z < 0）在近平面（z = n）上的像 x′ = (n/z)·x、y′ = (n/z)·y；
- 第二步齐次化：目标齐次结果设为 (nx, ny, ?, z)，前三行解出 (n,0,0,0)、(0,n,0,0)，第四行设 (0,0,1,0) 让 w 承载 z——除以 w 恰好补上相似三角形的除法；
- 第三行两个约束（齐次意义下「除回原样」）：近平面 (Cn + D)/n = n → Cn + D = n²；远平面中心 (Cf + D)/f = f → Cf + D = f²。相减得 C = n + f、D = −nf，得挤压矩阵 [n 0 0 0; 0 n 0 0; 0 0 n+f −nf; 0 0 1 0]；
- 第四步 M_persp = M_ortho · M_persp→ortho（先压成长方体、再做正交投影）；
- −2fn/(f−n) 的来历：换到正距离口径后它是「近平面映 z_ndc = −1、远平面映 z_ndc = +1」两个 z 约束联立解的常数项 β——没有它，深度无法归一进 [−1,1]。

**2.**
- w 从哪来：透视矩阵第四行 (0, 0, −1, 0) 让 w = −z_view——视空间深度的负值拷贝，随深度连续变化；
- 为什么近大远小：透视除法 (x/w, y/w) 等于给屏幕坐标除以深度——同一物体放 2 倍远处，w 变 2 倍、商变一半，屏幕尺寸按 1/z 缩放；平行线向灭点会聚是同一除法（远处间距趋 0）；
- 正交为什么没有：正交矩阵第四行 (0,0,0,1) 让 w 恒为 1，除法是空操作，尺寸与深度无关。

**3.**
- 完全看不见：先查相机朝向与位置（V 是否把场景搬到 z > 0 侧——深入专题开关 3 的指纹：观察 z 为正、w < 0 整批被裁）；再查 ±w 判据（点在视锥外则必然不可见——判据 −w ≤ x,y,z ≤ w 打印即可定位）；再查深度范围（n/f 配置是否把整个场景裁掉）；
- 上下镜像：NDC y 朝向冲突——OpenGL y 朝上、Vulkan/D3D y 朝下（2.9 表）；证据：把同一顶点的 NDC y 与预期符号比对，或查视口 y 方向；修复在投影矩阵或视口侧翻转 y，两处只翻一处；
- 横向拉伸：aspect 与视口宽高比不匹配——投影里 aspect = 宽/高（800/600 = 1.333），填成 0.75 或视口尺寸改了矩阵没改都会拉伸；证据：深入专题开关 4——只有 x 通道偏移（340 → 293.3），y 不动。

**4.**
- zaxis = normalize(eye − target) = normalize(−1, 0, 4) = (−0.2425, 0, 0.9701)；
- xaxis = normalize(cross(up, zaxis)) = cross((0,1,0), (−1,0,4))/√17 = (4, 0, 1)/√17 = (0.9701, 0, 0.2425)（已单位）；
- yaxis = cross(zaxis, xaxis) = (0, 1, 0)；
- 视图矩阵旋转部分（基向量按行摆）：
  [0.9701 0 0.2425; 0 1 0; −0.2425 0 0.9701]，平移列 −(各基·eye) = (−0.9701, 0, −3.8806)；
- 验证：每一行与 eye = (0,0,4) 的点乘恰等于平移列的相反数（构造即如此），故 V·(eye,1) = (0,0,0,1)——eye 归原点。

**5.**
- 映到 NDC 原点的是盒中心：x = (r+l)/2、y = (t+b)/2（代入 x_ndc 公式为 0）；
- 推导：先平移到中心 x1 = x − (r+l)/2，再缩放到 ±1：x_ndc = 2x1/(r−l) = 2x/(r−l) − (r+l)/(r−l)；验端点 l → −1、r → +1；
- 代入 l = −2、r = 6：x_ndc = 2·1/8 − 4/8 = 0.25 − 0.5 = **−0.25**。

**6.**
- 裁剪在除法之前：除法是「消费」w 的动作——除完齐次信息已丢，只有除法前才能用 ±w 这把「齐次尺」一次性量出可见性；
- 判据是 ±w：可见域在齐次空间里恰好是 −w ≤ x, y, z ≤ w 这个「方锥」；特别地相机身后的点 w < 0，若除完再用 ±1 判，负 w 会把坐标镜像翻回界内造成漏判——±w 在除法前一把抓住它。

**7.**
- 法线守的是「与切向垂直」这一关系，不是自身方向；非均匀缩放下直接乘 M 的形变把垂直关系破坏（示例数值：n′·t′ = −0.474 ≠ 0），光照立刻错位；
- 侥幸条件：M 只含旋转与均匀缩放——此时 (M⁻¹)ᵀ ∝ M（差一个标量），方向一致；但长度一般不为 1（旋转保长、均匀缩放变长），而光照公式假设 N 是单位向量，所以变换后必须 normalize；
- 非均匀缩放：必须走 (M⁻¹)ᵀ（法线矩阵 = model 3×3 部分逆转置），且同样要 normalize——它天然不保长度。

**8.**
- 手算：x_win = (800/2)·(−0.5) + (0 + 800/2) = 200，y_win = (600/2)·(0.5) + (0 + 600/2) = 450 → **(200, 450)**；
- GL 投影矩阵搬进 Vulkan：症状是画面上下镜像 + 近处一截深度带整段消失；根源：NDC 约定不同——OpenGL y 朝上、z ∈ [−1,1]，Vulkan y 朝下、z ∈ [0,1]（NDC 手性相反），z 落在 [−1,0) 的点超出 Vulkan 裁剪范围被裁（深入专题第五部分数值版）。
