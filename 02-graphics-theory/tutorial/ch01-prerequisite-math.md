### 1.1 图形学要消费哪个数学子集：先立地图再出发

先讲一个事故现场。你照着某篇教程抄了一段 shader，一个下标抄错，画面全黑——然后你盯着那串字母数字组合完全不知道错在哪。问题不在于你「数学不好」，而在于那串符号对你来说只是符号：你不知道每个数在几何上是什么、在画面上负责什么。**这一章要拆掉的正是这层迷雾：让每个数字重新变回几何。**

第二个事故现场更常见：打开线性代数教材，从「n 元有序数组」的定义出发，三周后学完特征值、秩、若尔当标准形——然后发现图形学根本没用上其中大半。数学系的线代课没有错，错的是把整门课当作图形学的前置。**本章只学图形学真正消费的子集：向量运算、矩阵变换、微积分直觉、概率直觉；特征值、秩、行列式深水区一概不进——学完即走，第 2 章见。**阶段路线原文把这叫「明确图形学只消费其中一个明确子集」，本章把这句话当预算纪律执行。

所以本章的每个小节都遵循同一条暗线：先给「图形学在哪里消费它」，再讲机制。消费点提前剧透如下，后面每节展开：

### 1.2 向量：方向与长度的几何语言

开场先纠正一个根深蒂固的混用：「位置」和「位移」。你站在 (3, 4)，往东北走两个单位——(3, 4) 是位置，「东北两个单位」是位移。**向量是位移不是位置：它没有家，只有方向和长度。**GAMES101 的讲法是「向量 = 方向 + 长度，没有绝对的开始位置」。这句话听起来像咬文嚼字，但它直接决定了 1.6 里「点带 w=1、向量带 w=0」的整个设计——平移一个位置有意义，平移一个「东北」没有意义。

记法约定本章从一而终：小写粗体 **a** 表示向量，分量写作 (aₓ, a_y, a_z)；**向量默认写成列向量**（竖着排）——这是数学教材、OpenGL、GLM、GAMES101 的共同惯例。行向量那一派确实存在，1.7 会正面开战，这里先立旗。

基本运算，每个都配画面：

- **加法 a + b**：几何上是位移叠加（三角形法则：b 的尾巴接在 a 的头上）；数值上是分量相加。画面：先往东走 3 步再往北走 4 步 = 直线往东北走 5 步。顺带一句：a + b = b + a，先东后北还是先北后东，终点一样——加法交换律在地图上一眼成立。
- **标量乘 s·a**：长度拉缩 s 倍，s 为负时方向反转。画面：位移的「步幅 ×2」或「掉头」。
- **减法 a − b**：**「从 b 指向 a」的箭头**。画面：不知道从哪到哪时，终点减起点——B − A 就是从 A 指向 B 的位移。这个画面在 1.4 求三角形边向量时天天用。
- **模长 |a|**：向量的长度，|a| = √(aₓ² + a_y² + a_z²)。就是勾股定理。

然后是本章第一个高频动作——**归一化（normalization）**：â = a / |a|，把长度拧到 1、方向不动，拧出来的叫**单位向量（unit vector）**。为什么要归一化？因为很多场景里你只关心方向不关心长度：光照里的「光从哪个方向来」、剔除里的「面朝不朝向相机」。**只谈方向，先把长度归一；后续一切角度公式都默认输入是单位向量。**

画面锚一个：单位圆。所有单位向量的终点都躺在半径为 1 的圆上——归一化就是把任意向量「缩放到圆上」，方向不变。cosθ = a·b（两边归一化后）的几何身份也在圆上：两个圆上向量点乘，就是「从圆心看这两个方向差了多少度」的余弦打分。

一个说明性的小片段感受一下（省略了头文件与 main，仅示意运算形态）：

```cpp
Vec3 a{3.0f, 4.0f, 0.0f};         // 位移：往东 3、往北 4
Vec3 dir = normalize(a);          // 只留方向：长度 1 的「东北偏东」
Vec3 edge = b - a;                // 从 a 指向 b 的箭头（终点减起点）
Vec3 stepped = 2.0f * dir;        // 同方向走两倍步幅
```

拿真实数字走一遍，画面立刻落地。a = (3, 4, 0)：|a| = √(3² + 4²) = 5（三内角股定理），归一化 â = (0.6, 0.8, 0)——「往东偏北」的那个方向，长度 1。B − A，其中 A = (1, 1, 0)、B = (4, 5, 0)：终点减起点 = (3, 4, 0)——正是刚才那个位移，从 A 走到 B。**减法的画面永远成立：想知道「从哪到哪」，拿终点减起点。**

再加一个马上要用的小区别：点用大写字母（A、B），向量用小写粗体（**a**、**b**）。这不是洁癖——1.4 求三角形法线时，你每天都在写「B − A」这种「点减点得向量」的表达式，符号分清，公式自己不会骗你。

边界与陷阱两条。其一，**零向量没有方向**，normalize(0) 在数学上未定义、在代码里是除零——工程库会断言或返回原向量，你手写的库（1.10）得对这事有个态度。其二，「向量没有家」意味着它**不参与平移**：把「东北」平移 10 米，还是「东北」。现在记住这句话，1.6 会看到它在代码里的样子（w=0）。

图形学在哪里消费它？无处不消费——但最快能看到的：1.3 的光照方向 L、1.4 的法线 N，全部是归一化向量的舞台。

### 1.3 点乘：夹角、投影与光照的同一把尺（对位检验标准②前半）

两个事故现场开场。现场一：角色的背光面莫名发亮，你检查了半天灯光位置——其实是表面朝向和光方向「点乘读数」取反了。现场二：明明该被剔除的背面还在闪现——剔除判定里的点乘符号搞反了。这两件事表面上是两个 bug，底下是同一把尺子：**点乘（dot product）量的是「两个方向有多一致」。**

定义有两版，先摆出来再说明它们是同一回事：

- **分量式**：**a**·**b** = aₓbₓ + a_yb_y + a_zb_z（对应相乘再求和——程序最好算的一版）
- **几何式**：**a**·**b** = |**a**||**b**|cosθ（θ 是两向量夹角）

为什么两版等价？直觉版说明（不搞严格证明）：把其中一个向量拆成「沿另一个方向的分量 × 垂直分量」，垂直分量对求和的贡献恰好抵消（ab 逐项相乘时正负对称），剩下的就只跟「沿方向的长度 × 夹角余弦」有关。分量式是「怎么算」，几何式是「算出来是什么意思」——**cosθ 就是「方向一致性」的打分器：同向 1 分、垂直 0 分、反向 −1 分。**

三大用途，逐个来。

**用途一：夹角与方向关系。**cosθ = **a**·**b** / (|**a**||**b**|)；若两边都已归一化，直接 **a**·**b** 就是 cosθ。正 = 同侧、零 = 垂直、负 = 背向——不用反算角度就能分类，这在分支判断里比 arccos 便宜得多（arccos 只在真需要「角度数值」时才用）。一张读数速查表，后面两个用途都在用它：

| 点乘读数（已归一化） | 几何含义 | 图形学现场 |
|---|---|---|
| +1 | 完全同向（θ = 0°） | 表面正对光，最亮 |
| (0, 1) | 同侧，夹角锐角 | Lambert 贡献介于 0 与 1 之间 |
| 0 | 垂直（θ = 90°） | 掠射光照零贡献；正侧向剔除临界 |
| (−1, 0) | 背向，夹角钝角 | 背光；背面剔除区间 |
| −1 | 完全反向（θ = 180°） | 光从正后方来 |

**用途二：投影与分解。****a** 在 **b** 方向上的投影 = (**a**·**b**̂)**b**̂（**b**̂ 是 **b** 的归一化）。于是任何向量都能拆成「平行于 **b** 的分量 + 垂直于 **b** 的分量」：平行分量 = (**a**·**b**̂)**b**̂，垂直分量 = **a** − 平行分量。这个「正交分解」是后面一切「在某方向上的贡献」类问题的通用解法（正交基的完整故事第 1.5 节的正交矩阵会接上）。

**用途三：Lambert 光照与背面剔除——检验标准②的正面答案。**先说 Lambert。物理事实：表面越正对光源越亮，亮度正比于「表面法线 N 与光方向 L 夹角的余弦」——而余弦就是单位化的 N·L。**为什么偏偏是点乘？因为「朝向的一致程度」这个物理量，数学名字就叫余弦，点乘就是余弦的计算器。**N·L = 1 正对最亮，N·L = 0 掠射熄灭，N·L < 0 光在背面——工程上把负值钳到 0。完整 Blinn-Phong 光照模型将在第 4 章展开，这里先把 N·L 这颗螺丝拧紧。

再说背面剔除。三角形有正反两面（顶点绕序决定哪面朝外，1.4 详述），朝外的法线是 N，从三角形指向相机的方向是 V，那么 **N·V > 0 你看到的是正面，N·V < 0 是背面——直接剔除，三角形级别的光栅化都不用做**。叉乘负责「造出 N」（1.4），点乘负责「读出朝不朝向」——两个积在这一个功能里接力。

下面是本章第一个完整可编译示例，把三个用途全部数值化：

```cpp
// ch01_dot_products.cpp —— 点乘三用途：夹角、投影分解、Lambert 贡献与背面剔除（完整可编译）
#include <cmath>
#include <cstdio>

struct Vec3 {
    float x, y, z;
};

float dot(const Vec3& a, const Vec3& b) {          // 分量式点乘
    return a.x * b.x + a.y * b.y + a.z * b.z;
}
Vec3 operator-(const Vec3& a, const Vec3& b) {     // 分量相减：从 b 指向 a 的箭头
    return Vec3{a.x - b.x, a.y - b.y, a.z - b.z};
}
Vec3 operator*(const Vec3& a, float s) {           // 标量乘：步幅拉缩
    return Vec3{a.x * s, a.y * s, a.z * s};
}
float length(const Vec3& a) { return std::sqrt(dot(a, a)); }
Vec3 normalize(const Vec3& a) {                    // 教学版：零向量处理留给 1.10
    float len = length(a);
    return Vec3{a.x / len, a.y / len, a.z / len};
}

int main() {
    // ── 用途一：夹角与方向关系 ──
    Vec3 east{1, 0, 0};
    Vec3 northEast{1, 1, 0};
    float cosAB = dot(normalize(east), normalize(northEast));
    std::printf("[夹角]  cos = %.4f -> 约 %.1f 度（正 = 同侧）\n",
                cosAB, std::acos(cosAB) * 180.0f / 3.14159265f);

    // ── 用途二：投影与正交分解 ──
    Vec3 bHat = normalize(northEast);
    Vec3 probe{2, 5, 0};
    Vec3 along = bHat * dot(probe, bHat);           // 平行分量
    Vec3 perp  = probe - along;                     // 垂直分量
    std::printf("[分解]  probe=(2,5,0) -> 平行(%.3f,%.3f,%.0f) + 垂直(%.3f,%.3f,%.0f)\n",
                along.x, along.y, along.z, perp.x, perp.y, perp.z);

    // ── 用途三：Lambert 贡献（法线朝 +Z 的一块平板，三盏方向光）──
    Vec3 N{0, 0, 1};
    Vec3 lights[] = {normalize(Vec3{ 1, 0,  1}),   // 从正前上方来
                     normalize(Vec3{ 1, 0,  0}),   // 纯侧向，掠射
                     normalize(Vec3{-1, 0, -1})};  // 从背后来（z 为负：光在表面另一侧）
    const char* names[] = {"正前上方", "纯侧向  ", "正后方  "};
    for (int i = 0; i < 3; ++i) {
        float lambert = dot(N, lights[i]);
        if (lambert < 0.0f) lambert = 0.0f;         // 背光钳零
        std::printf("[光照]  来自%s的光：N·L = %+.4f -> Lambert 贡献 %.4f\n",
                    names[i], dot(N, lights[i]), lambert);
    }

    // ── 用途三：背面剔除 ──
    Vec3 triNormal{0, 0, 1};                        // 三角形朝外法线（1.4 教你造它）
    Vec3 toCamera{0.3f, 0.2f, 1.0f};                // 从三角形指向相机
    Vec3 awayFromCamera{0.3f, 0.2f, -1.0f};         // 假设相机跑到背面去了
    std::printf("[剔除]  面向相机：N·V = %+.2f -> %s\n", dot(triNormal, toCamera),
                dot(triNormal, toCamera) > 0.0f ? "正面，绘制" : "背面，剔除");
    std::printf("[剔除]  背对相机：N·V = %+.2f -> %s\n", dot(triNormal, awayFromCamera),
                dot(triNormal, awayFromCamera) > 0.0f ? "正面，绘制" : "背面，剔除");
    return 0;
}
```

示例输出（示意，小数位可能因浮点环境略有差异）：

```text
[夹角]  cos = 0.7071 -> 约 45.0 度（正 = 同侧）
[分解]  probe=(2,5,0) -> 平行(3.500,3.500,0) + 垂直(-1.500,1.500,0)
[光照]  来自正前上方的光：N·L = +0.7071 -> Lambert 贡献 0.7071
[光照]  来自纯侧向  的光：N·L = +0.0000 -> Lambert 贡献 0.0000
[光照]  来自正后方  的光：N·L = -0.7071 -> Lambert 贡献 0.0000
[剔除]  面向相机：N·V = +1.00 -> 正面，绘制
[剔除]  背对相机：N·V = -1.00 -> 背面，剔除
```

读程序两处小刻意：其一，`normalize` 返回值直接嵌进 `dot` 调用——数学库里「先归一再用」的节奏会渗透到每一行调用代码；其二，剔除判定打印的是**原始点乘值**和**判定结论**两列——数值和结论分开看，错了才知道错在哪一步，这个习惯到了第 3 章调光栅化时会救你很多次。

注意「分解」那行自洽性：平行 + 垂直 = (3.5−1.5, 3.5+1.5, 0) = (2, 5, 0)，严丝合缝拼回原向量——这就是「分解」一词的分量。

边界与陷阱：其一，几何式 cosθ 默认两边已归一化，忘了归一化就会得到「cosθ 乘上一堆长度」的怪数——光照代码里方向向量进函数前先 normalize 是纪律。其二，点乘满足交换律（**a**·**b** = **b**·**a**），所以「谁点谁」不用慌；但 1.4 的叉乘**不满足**，别把这份从容带过去。

### 1.4 叉乘：法线、定向与左右判定（对位检验标准②后半）

事故现场换一个：一个三角形，从正面看得到、稍微转个角度突然消失；或者法线朝上还是朝下全看心情。这类事故里拧着三件事——法线怎么出生、顶点绕序、坐标系手性。本节拆前两件，第三件（手性）1.7 正面处理。

**叉乘（cross product）的定义**：**a** × **b** 是一个**向量**（注意，点乘出标量，叉乘出向量），

- 分量式（行列式助记版）：
  **a** × **b** = (a_yb_z − a_zb_y, a_zbₓ − aₓb_z, aₓb_y − a_ybₓ)
- 几何式：长度 |**a** × **b**| = |**a**||**b**|sinθ（两向量张成的平行四边形面积），方向**同时垂直于 a 和 b**，具体朝那边由**右手定则**给出——右手从 **a** 握向 **b**，大拇指指向就是结果方向。

面积读法验一个数：**a** = (1, 0, 0)、**b** = (0, 1, 0)，夹角 90°，|**a** × **b**| = 1·1·sin90° = 1——单位正方形的面积，恰好是 1；若把 **b** 换成 (2, 0, 0)（与 a 平行），sinθ = 0，叉乘为零向量——平行四边形被压扁成一条线，面积归零，「垂直信息」也归零。**叉乘长度 = 「这两个方向张开了多少」，叉乘方向 = 「张开的面朝哪」。**

分量式不用背到老，用「行列式口诀」现场推导即可：中间分量取负、其余按 yz / zx / xy 轮转，摆成 2×2 小块一目了然：

```text
x 分量 = | a_y  a_z |      y 分量 = -(a_x  a_z)      z 分量 = | a_x  a_y |
         | b_y  b_z |               -(b_x  b_z)               | b_x  b_y |

口诀：x 看 yz，y 看 zx（带负号），z 看 xy
```

建议现在拿 **a** = (1,2,3)、**b** = (4,5,6) 算一遍，结果应是 (−3, 6, −3)——1.10 的性质测试会用同一组数。

**叉乘方向依赖手性**——这句话现在只需记住：同样的公式，左手系下「右手定则」换成左手定则，结论翻转。1.7 展开，先立概念。

三大用途：

**用途一：三角形法线——「叉乘为何出现在背面剔除」的完整答案。**三角形三个顶点 A、B、C，两条边向量 **e**₁ = B − A、**e**₂ = C − A（回忆 1.2：终点减起点），法线 N = normalize(**e**₁ × **e**₂)。**顶点绕序（winding order）= 朝向约定**：A→B→C 逆时针排布（从正面看）时法线朝向观察者一侧；把 B、C 对调，**e**₁ × **e**₂ 整体反向，法线就翻了。所以「绕序反了法线就反、剔除判定跟着反」——渲染管线里大量「这个面为什么消失了」的事故，根源在此。工程纪律：**导出模型时统一绕序约定（引擎通常约定逆时针为正面），并在代码评审时把它当契约看。**

**用途二：左右关系与内外判定。**二维平面上，**a** × **b** 的 z 分量符号告诉你 **b** 在 **a** 的左边还是右边。把这一点连用三次：对三角形三条边分别叉乘「边 × (点 − 边起点)」，**三个叉乘同号 ⇔ 点在三角形内**。这个「点在三角形内」判定正是光栅化的心脏——每个像素都要问一次「我在不在这个三角形里」，第 3 章软件光栅器正式上岗，这里先种下。

**用途三：构建局部坐标系。**已知一个朝向 N，随便找一个不平行于 N 的向量，叉乘一次得到与 N 垂直的方向，再叉乘一次得到第三个轴——三步造出一组**标准正交基**（三个互相垂直的单位向量）。相机就是靠这个动作「看」世界的：lookAt 矩阵的构造将在第 2 章展开，本节先掌握「叉乘两次，坐标系到手」。

自身性质（1.10 性质测试的主角）：**a** × **b** ⊥ **a** 且 ⊥ **b**；**a** × **a** = **0**；**反交换**：**a** × **b** = −**b** × **a**——顺序反了，方向翻转，这是它和点乘最大的性格差异。

第二个完整示例，法线出生 + 绕序翻转 + 内外判定三合一：

```cpp
// ch01_cross_normal.cpp —— 三角形法线：绕序决定朝向，叉乘链判定内外（完整可编译）
#include <cmath>
#include <cstdio>

struct Vec3 {
    float x, y, z;
};

Vec3 cross(const Vec3& a, const Vec3& b) {         // 分量式叉乘
    return Vec3{a.y * b.z - a.z * b.y,
                a.z * b.x - a.x * b.z,
                a.x * b.y - a.y * b.x};
}
float dot(const Vec3& a, const Vec3& b) { return a.x*b.x + a.y*b.y + a.z*b.z; }
float length(const Vec3& a) { return std::sqrt(dot(a, a)); }
Vec3 normalize(const Vec3& a) {
    float len = length(a);
    return Vec3{a.x / len, a.y / len, a.z / len};
}
Vec3 sub(const Vec3& a, const Vec3& b) { return Vec3{a.x-b.x, a.y-b.y, a.z-b.z}; }

int main() {
    // ── 三角形法线：A -> B -> C 逆时针（从 +Z 往下看）──
    Vec3 A{0, 0, 0}, B{1, 0, 0}, C{0, 1, 0};
    Vec3 n1 = normalize(cross(sub(B, A), sub(C, A)));
    std::printf("[法线]  绕序 A,B,C：N = (%.0f, %.0f, %.0f)\n", n1.x, n1.y, n1.z);

    // ── 绕序翻转：法线跟着翻 ──
    Vec3 n2 = normalize(cross(sub(C, A), sub(B, A)));
    std::printf("[法线]  绕序 A,C,B：N = (%.0f, %.0f, %.0f)  <- 反交换的代价\n",
                n2.x, n2.y, n2.z);

    // ── 内外判定：三条边叉乘同号 = 在三角形内 ──
    auto edgeZ = [](const Vec3& e, const Vec3& p, const Vec3& v) {
        return cross(sub(p, v), sub(e, v)).z;       // 边 × (点到边起点)
    };
    Vec3 P_in {0.2f, 0.2f, 0.0f};
    Vec3 P_out{2.0f, 2.0f, 0.0f};
    float s1 = edgeZ(P_in,  A, B), s2 = edgeZ(P_in,  B, C), s3 = edgeZ(P_in,  C, A);
    std::printf("[内外]  P=(0.2,0.2)：边叉乘符号 %+.0f %+.0f %+.0f -> %s\n",
                s1, s2, s3, (s1>0)==(s2>0)&&(s2>0)==(s3>0) ? "在内" : "在外");
    float t1 = edgeZ(P_out, A, B), t2 = edgeZ(P_out, B, C), t3 = edgeZ(P_out, C, A);
    std::printf("[内外]  P=(2.0,2.0)：边叉乘符号 %+.0f %+.0f %+.0f -> %s\n",
                t1, t2, t3, (t1>0)==(t2>0)&&(t2>0)==(t3>0) ? "在内" : "在外");
    return 0;
}
```

示例输出（示意）：

```text
[法线]  绕序 A,B,C：N = (0, 0, 1)
[法线]  绕序 A,C,B：N = (0, 0, -1)  <- 反交换的代价
[内外]  P=(0.2,0.2)：边叉乘符号 -0 -1 -0 -> 在内
[内外]  P=(2.0,2.0)：边叉乘符号 -2 +3 -2 -> 在外
```

注意内点那行打印里有 `-0` 也有 `-1`——内判定三边的叉乘 z 分量实际是 −0.20、−0.60、−0.20，`%.0f` 四舍五入到整数位（−0.2 → `-0`，−0.6 → `-1`）；外点离三角形远，又乘值 −2.00、+3.00、−2.00 直接显形。把格式改成 `%.1f` 就能看到完整数值，任务 3 会让你亲手做这个实验。符号都是负的会不会不对？不会——三个符号**同号**就是判定标准，整体正负取决于你取边向量的方向（本例统一取「终点减起点」再统一调换了参数顺序），内部自洽即可。还有个更细的看头：P_out 三符号「− + −」不同号，一票否决判「在外」——三条边是三道关卡，全过才算内。

边界与陷阱：其一，**叉乘不满足交换律**，写反顺序 = 法线翻转，这是和点乘并肩的头号笔误。其二，两向量平行时叉乘是零向量，normalize 它会除零——构造坐标系时记得选一个「不平行」的搭档向量。其三，手性决定「右手定则」是右手还是左手——1.7 见。

### 1.5 矩阵 = 线性变换：乘法即复合（对位检验标准①主场）

开场先立判据，再给画面。一个变换 F 叫**线性变换（linear transformation）**，当且仅当它满足两条：可加性 F(**a** + **b**) = F(**a**) + F(**b**)，齐次性 F(c**a**) = cF(**a**)。合起来一句话：**先变换再求和 = 先求和再变换**。旋转、缩放、剪切都过这两条；平移过不了——f(0) = **a** ≠ **0**，原点都保不住，1.6 专门收拾它。

然后是本章最值得带走的一个画面：**矩阵是线性变换的账本——每一列记录一个基向量去了哪里。**想把「旋转 30°」写成矩阵？不需要背任何模板，只需要回答两个问题：x̂ = (1, 0) 转完之后到哪了？ŷ = (0, 1) 转完之后到哪了？把答案按列摆好，矩阵就写完了。

【推导·全程】2D 旋转矩阵。把平面绕原点转 θ，跟着基向量走：

- x̂ = (1, 0)：单位圆上从东出发转 θ，落在 (cosθ, sinθ)；
- ŷ = (0, 1)：从北出发转 θ，落在 (−sinθ, cosθ)（转过头越过正西一点点，θ 小的时候 y 分量接近 1）；

按列拼起来：

```text
        [ cosθ  -sinθ ]
R(θ) =  [              ]
        [ sinθ   cosθ ]
```

验证一下手感：θ = 90° 时 x̂ 应该转到正北 (0, 1)——代入第一列 (cos90°, sin90°) = (0, 1) ✓；ŷ 转到正西 (−1, 0)——第二列 (−sin90°, cos90°) = (−1, 0) ✓。**旋转矩阵不是背出来的，是「基向量去哪了」问出来的。**同一招推缩放：x̂ 拉伸 2 倍到 (2, 0)、ŷ 到 (0, 2)，对角矩阵 diag(2, 2) 脱口而出；推剪切：x̂ 不动 (1, 0)、ŷ 歪向 (1, 1)（y 越大 x 偏得越多），矩阵第一列 (1, 0)、第二列 (1, 1)——剪切矩阵也到手了。检验标准①的「不查资料手推」，方法就是这一个问题。

3D 旋转一句概念带过：Rx/Ry/Rz 三张 3×3 矩阵，本质都是「2D 旋转嵌进 3D + 旋转轴那个维度原地不动」。比如绕 z 轴转 θ，x、y 平面照着 2D 转法走，z 分量岿然不动——矩阵右下角一个 1 就是「z 不动」的宣言。完整 3D 旋转（含任意轴）本章不展开。

```text
        [ cosθ  -sinθ   0 ]
Rz(θ) = [ sinθ   cosθ   0 ]      <- 左上角就是 1.5 推出的 2D 旋转矩阵
        [   0      0     1 ]     <- 右下角的 1 是「z 不动」的宣言
```

Rx、Ry 同理，只是「2D 平面」换到另外两个坐标面、宣言的那个 1 挪到对应轴的位置：

```text
         [ 1    0     0  ]          [ cosθ  0  sinθ ]
Rx(θ) =  [ 0  cosθ -sinθ ]   Ry(θ) = [   0    1    0  ]
         [ 0  sinθ  cosθ ]          [ -sinθ  0  cosθ ]
```

形状一眼认得即可，完整 3D 旋转（含任意轴）本章不展开。

**矩阵乘法 = 变换复合。**先做 A 再做 B，合起来就是 B·A（列向量右乘约定下，离向量近的先作用）。几何读法：矩阵-向量乘积 A·v = 「v 按列向量组做线性组合」——结果的第一分量 = 第一行的点乘，也可以读成「v 的 x 份新 x̂ 加 y 份新 ŷ」。两个画面等价，选顺手的用。至于「为什么列向量约定下复合要从右往左读」：先做 A 再做 B 写成 B·A 后，离 v 最近的是 A——**靠近向量的先上场**，就像穿袜子先于穿鞋，写出来的顺序恰好是日常语序的倒序。

立刻能推出一个重要事实：**矩阵乘法不可交换，复合顺序即命运。**先旋转 90° 再把 x 拉伸 2 倍，与先拉伸再旋转，结果不同——下面程序会给出数值证据。

先热个身，用「线性组合」读法手算一次矩阵-向量乘法。取 v = (2, 1)，R(30°) 的两列分别是新 x̂ = (0.866, 0.5) 与新 ŷ = (−0.5, 0.866)，那么：

```text
R(30°)·v = 2·(0.866, 0.5) + 1·(−0.5, 0.866) = (1.232, 1.866)
```

画面：新 x 方向走 2 步，再往新 y 方向走 1 步——落点 (1.232, 1.866)。这个读法与「逐行点乘」结果一致，但几何意义直白得多：**矩阵-向量乘法 = 拿旧坐标当比例，去调配新基向量。**

```cpp
// ch01_matrix_push.cpp —— 手推对照：2D 旋转/缩放矩阵，与「先旋后缩 ≠ 先缩后旋」（完整可编译）
#include <cmath>
#include <cstdio>

struct Vec2 { float x, y; };
struct Mat2 { float m[2][2]; };                      // 行优先记号：m[行][列]

Mat2 mul(const Mat2& A, const Mat2& B) {             // 矩阵乘矩阵 = 复合
    Mat2 r{};
    for (int i = 0; i < 2; ++i)
        for (int j = 0; j < 2; ++j)
            for (int k = 0; k < 2; ++k)
                r.m[i][j] += A.m[i][k] * B.m[k][j];
    return r;
}
Vec2 apply(const Mat2& A, Vec2 v) {                  // 矩阵乘向量
    return Vec2{A.m[0][0] * v.x + A.m[0][1] * v.y,
                A.m[1][0] * v.x + A.m[1][1] * v.y};
}

int main() {
    const float PI = 3.14159265f;
    // ── 手推对照：R(30) 的两列应是我们推出的基向量去向 ──
    float c = std::cos(30.0f * PI / 180.0f);         // 0.8660
    float s = std::sin(30.0f * PI / 180.0f);         // 0.5000
    Mat2 R30{{{c, -s}, {s, c}}};                      // 列 0 = x^ 去向，列 1 = y^ 去向
    Vec2 rx = apply(R30, Vec2{1, 0});
    Vec2 ry = apply(R30, Vec2{0, 1});
    std::printf("[手推对照] R(30)·x^ = (%.4f, %.4f)，手推应为 (0.8660, 0.5000)\n", rx.x, rx.y);
    std::printf("[手推对照] R(30)·y^ = (%.4f, %.4f)，手推应为 (-0.5000, 0.8660)\n", ry.x, ry.y);

    // ── 次序实验：R(90)·S 与 S·R(90) 作用在 (1, 0) ──
    Mat2 R90{{{0.0f, -1.0f}, {1.0f, 0.0f}}};          // 90 度，正余弦手填
    Mat2 S {{{2.0f,  0.0f}, {0.0f, 1.0f}}};           // x 方向拉伸 2 倍
    Vec2 rs = apply(mul(R90, S), Vec2{1, 0});         // 先拉伸，后旋转
    Vec2 sr = apply(mul(S, R90), Vec2{1, 0});         // 先旋转，后拉伸
    std::printf("[次序]   (R·S)·v = (%.0f, %.0f)   (S·R)·v = (%.0f, %.0f)\n",
                rs.x, rs.y, sr.x, sr.y);
    return 0;
}
```

示例输出（示意）：

```text
[手推对照] R(30)·x^ = (0.8660, 0.5000)，手推应为 (0.8660, 0.5000)
[手推对照] R(30)·y^ = (-0.5000, 0.8660)，手推应为 (-0.5000, 0.8660)
[次序]   (R·S)·v = (0, 2)   (S·R)·v = (0, 1)
```

读程序一处小刻意：90° 的正余弦我手填了 0 和 1 而不是调库——不是抠门，是想让你看到「特殊角的正余弦本就是几何事实」（x̂ 转到正北就是 (0,1)，不需要任何 π），手推与代码在这种地方严丝合缝。

次序实验读一遍画面：先拉伸再转 90°，点 (1,0) 先跑到 (2,0) 再转到 (0,2)；先转 90° 点已在正北 (0,1)，再沿 x 拉伸——北向的点在 x 方向没有分量，纹丝不动还是 (0,1)。**同两步操作，次序不同，落点不同。**「变换顺序为什么重要」这个图形学第一谜题，本节数值版解答完毕。

顺手补一个记号：上标 ᵀ 是**转置（transpose）**——行列互换，第 i 行变成第 i 列。旋转矩阵的转置有几何身份：Rᵀ = R(−θ)，转过来等于反着转——因为它俩都把基向量送到同一样多的地方，只是方向相反。这个身份等下验证 RᵀR = I 时会帮你省算力：Rᵀ·R = R(−θ)·R(θ) = R(0) = I，一行心算。

最后是**正交矩阵（orthogonal matrix）**：满足 RᵀR = I 的矩阵——展开就是「列向量组互相垂直且长度为 1」（两列点乘为零、各自归一化）。旋转矩阵天然正交（你推的 R(θ) 两列恰好如此）。正交变换是刚体运动：**保长度、保夹角、保点乘**——所以旋转不改变物体的形状，只改变它的朝向。这条性质马上就是 1.10 性质测试的验针对象：RᵀR = I 是测试清单第一条。现在就手验一遍 R(30°)：两列分别是 (0.866, 0.5) 与 (−0.5, 0.866)，转置乘原矩阵——对角线：0.866² + 0.5² = 0.75 + 0.25 = 1、同理 1；非对角：(0.866)(−0.5) + (0.5)(0.866) = 0。结果正是单位矩阵——两列各自长度 1（对角）、互相垂直（非对角），纸面上三步完事，程序里就是一个断言。

边界与陷阱：其一，矩阵乘法**有结合律**（(AB)C = A(BC)）却没有交换律——引擎里把「模型·视角·投影」预先乘成一张矩阵，靠的正是结合律；「先旋转后平移 ≠ 先平移后旋转」靠的正是无交换律。其二，**线性变换必保原点**：旋转/缩放「绕原点」进行——想绕物体自身中心转？先把它挪到原点、转完再挪回去，这个「三明治」套路第 2 章变换链里天天见。

### 1.6 齐次坐标与仿射变换：平移为何要升维

【推导·全程】第一件事：证明平移不是线性变换，因此 3×3 矩阵表达不了它。平移是 f(**u**) = **u** + **a**。线性要求可加性 F(**a** + **b**) = F(**a**) + F(**b**)，取两边都是零向量的情形：左边 F(**0** + **0**) = f(**0**) = **a**，右边 F(**0**) + F(**0**) = **a** + **a** = 2**a**。**a** ≠ 2**a**，除非 **a** = **0**——可加性当场阵亡（换齐次性检验死得一样快）。更直白的说法：**线性变换必须保持原点**，而平移把原点搬走了。既然每个 3×3 矩阵都定义一个线性变换、线性变换都保原点，那么**无论 3×3 矩阵怎么填，都写不出平移**——这不是技巧不够，是表达能力的硬边界。

第二件事：升维。给每个位置补一个第四分量 w：

- **点（point）**：(x, y, z, **1**)——有位置的东西；
- **向量（vector）**：(x, y, z, **0**)——只有方向的东西。

然后把平移写进 4×4 矩阵的最后一列（列向量右乘约定）：

```text
        [ 1 0 0 tx ]   [x]   [x + tx]
        [ 0 1 0 ty ]   [y]   [y + ty]
T(tx,ty,tz) = [ 0 0 1 tz ] · [z] = [z + tz]
        [ 0 0 0  1 ]   [1]   [  1   ]
```

乘开看第四行：点的 w 是 1，第四行运算 = 0·x + 0·y + 0·z + 1·1 = 1——**w 乘完还是 1，点还是点**；向量带 w = 0 时，同一行算出 0——**平移只动点、不动向量**。两种情况并排看清楚：

```text
对点   (x,y,z,1)：第四行 = 0·x + 0·y + 0·z + 1·1 = 1  -> w 保持 1，平移量生效
对向量 (x,y,z,0)：第四行 = 0·x + 0·y + 0·z + 1·0 = 0  -> w 保持 0，平移量被吃掉
```

1.2 埋的那句话「向量没有家，平移『东北』还是『东北』」在这里拿到了代码形态。顺带解释「齐次」二字：把 (x, y, 1) 整体乘 2 得 (2x, 2y, 2)，除回 w 后还是同一个点——同一位置的表示有无穷多个、彼此差一个比例，故称「齐次（同族）坐标」。第 2 章透视除法会把这个性质用到飞起。**线性变换 + 平移 = 仿射变换（affine transformation）；升维不是技巧，是让平移也进矩阵的代价与红利**——从此旋转、缩放、平移、剪切全部是「4×4 矩阵 × 向量」一种运算，复合就是连乘，管线只需要一种硬件单元。

把仿射家族列个户口本，每个成员都是「线性部分 + 平移」的不同配方：

| 变换 | 3×3 线性部分 | 最后一列（平移） | 画面 |
|---|---|---|---|
| 平移 | 单位矩阵 | (tx, ty, tz) | 整体搬家 |
| 缩放 | 对角矩阵 | 任意（常为 0） | 绕原点胖瘦 |
| 旋转 | 正交矩阵（1.5） | 任意（常为 0） | 绕原点转身 |
| 剪切 | 单位矩阵改一格 | 任意（常为 0） | 斜塔倾倒 |
| 复合 | 上面的乘积 | 相应组合 | 次序即命运（1.5） |

仿射变换还有一条温柔的性质：**平行线变换后仍然平行**（线性部分把平行向量对变成平行向量对，平移不动方向）。这就是为什么渲染里的盒子永远不会因为「放远处」而变成梯形——那是透视的事（第 2 章），仿射阶段不背这个锅。

w 的第二个身份只埋一句伏笔：它还能当除数（透视除法，w 越小物体越「近」），带来近大远小——将在第 2 章变换链正式展开。

第三个完整示例，点与向量同场对比：

```cpp
// ch01_point_vs_vector.cpp —— 平移矩阵作用：点动了，向量没动（完整可编译）
#include <cstdio>

struct Vec4 { float x, y, z, w; };
struct Mat4 { float m[4][4]; };                      // 行优先存储；数学按「列向量右乘」约定

Vec4 apply(const Mat4& M, const Vec4& v) {
    return Vec4{M.m[0][0]*v.x + M.m[0][1]*v.y + M.m[0][2]*v.z + M.m[0][3]*v.w,
                M.m[1][0]*v.x + M.m[1][1]*v.y + M.m[1][2]*v.z + M.m[1][3]*v.w,
                M.m[2][0]*v.x + M.m[2][1]*v.y + M.m[2][2]*v.z + M.m[2][3]*v.w,
                M.m[3][0]*v.x + M.m[3][1]*v.y + M.m[3][2]*v.z + M.m[3][3]*v.w};
}

int main() {
    Mat4 T{};                                        // 平移 (10, 0, 0)
    T.m[0][0] = T.m[1][1] = T.m[2][2] = T.m[3][3] = 1.0f;
    T.m[0][3] = 10.0f;                               // 平移量住在最后一列

    Vec4 point {1, 2, 3, 1};                         // w = 1：点（有位置）
    Vec4 vector{1, 2, 3, 0};                         // w = 0：向量（只有方向）

    Vec4 tp = apply(T, point);
    Vec4 tv = apply(T, vector);
    std::printf("[点]   (1,2,3,1) -> (%.0f, %.0f, %.0f, %.0f)   位置被平移\n",
                tp.x, tp.y, tp.z, tp.w);
    std::printf("[向量] (1,2,3,0) -> (%.0f, %.0f, %.0f, %.0f)   方向纹丝不动\n",
                tv.x, tv.y, tv.z, tv.w);
    return 0;
}
```

示例输出（示意）：

```text
[点]   (1,2,3,1) -> (11, 2, 3, 1)   位置被平移
[向量] (1,2,3,0) -> (1, 2, 3, 0)   方向纹丝不动
```

读程序一处小刻意：apply 对第四分量的处理与其它分量毫无区别——它只是老老实实做点乘。是 w 的值（1 或 0）在决定「平移是否生效」，不是 apply 里有 if。**语义长在数据里，不长在分支里**——这是齐次坐标设计最漂亮的地方。

一个常见疑问先堵上：为什么不直接用「3×3 矩阵 + 单独一个平移向量」，非要升维？因为复合时形态不统一——「旋转×旋转」是矩阵乘，「旋转+平移」是矩阵乘加向量加法，一条变换链里两种运算混着来，代码和硬件都得为「下一步是什么类型」操心。升到 4×4 之后，**一切变换、无论多少层，都是同一种动作：矩阵乘矩阵，矩阵乘向量**——这就是齐次坐标真正的红利：不是「能表示平移」，而是「让整条管线只剩一种运算」。

边界与陷阱：其一，1.10 的 Mat4 会提供 transform 点与 transform 向量两个入口——**别用一个函数通吃**——用 w=1 的乘法去「平移」法线，法线会跟着物体跑，光照立刻错位（法线变换的完整故事——为什么用逆转置矩阵——在第 2 章）。其二，「点 vs 向量」的区分不是学院洁癖：它就是 w 语义，是渲染管线里真实传递的第四个分量。

### 1.7 约定之战：行/列向量、主序与左右手系

同一段变换代码，从 OpenGL 教程搬到 DirectX 教程，画面镜像了、Z 反了——「约定之战」的实弹现场。本节把三张独立的「约定轴」摊开，给你一张排雷地图。

**第一张轴：乘法方向（数学约定）。**列向量右乘 M·v（数学教材、OpenGL、GLM、GAMES101 默认），复合从右往左读（离 v 近的先作用）；行向量左乘 v·M（DirectX 历史传统），从左往右读。同一套变换，两派写出的矩阵**互为转置**——这就是「抄来的矩阵长得像转置了」的第一嫌疑。

**第二张轴：存储主序（内存摆放）。**行主序（row-major）= 按行铺进内存；列主序（column-major）= 按列铺。关键澄清，也是最常见的混淆：**存储主序与乘法方向是两个独立概念**——完全可以「列向量约定 + 行主序存储」。GLM 是「列主序存储 + 列向量约定」，DirectXMath 是「行主序 + 行向量」，而本章 1.6 那段示例代码就是「行主序存储 + 列向量约定」的活例子——一个 C 风格二维数组按行铺，数学上照样右乘。判断别人代码用哪派，别看内存布局看乘法：找一行 `M * v` 还是 `v * M`。

| | 列向量右乘 M·v | 行向量左乘 v·M |
|---|---|---|
| 代表 | 数学教材、OpenGL/GLM、GAMES101 | DirectX 传统 |
| 复合读法 | 从右往左 | 从左往右 |
| 同一变换的矩阵 | 原版 | 转置版 |
| 4×4 平移量位置 | 最后一列 | 最后一行 |

存储主序再看一眼就透。同一个 4×4 矩阵，两种铺内存的顺序：

```text
行主序铺内存：[m00, m01, m02, m03,  m10, m11, m12, m13, ...]   按行一路铺过去
列主序铺内存：[m00, m10, m20, m30,  m01, m11, m21, m31, ...]   按列一路铺过去
```

同一堆数，两种下标解读——这就是为什么「把 GLM 的矩阵直接 memcpy 给 DirectXMath 用」会出事：数没变，读法变了。

顺手答一个常见疑问：「既然列向量是数学主流，DirectX 为什么不改？」——历史惯性 + 生态配套：四十年的教材、示例、着色器约定都长在那套写法上，约定本身就有人在护。这恰好是本节的结论预演：约定无所谓对错，看你落在哪个生态；麻烦的从来不是「用哪套」，而是「两套混用」。

**第三张轴：手性（左右手系）。**右手系：x 叉 y 得 z（右手定则），OpenGL/GLM/GAMES101 默认；左手系：DirectX 传统。手性影响叉乘方向解释、Z 轴朝向、深度范围——第 3 节 OpenGL 与第 6 节 Vulkan 移植时的经典坑点都溯源到这里。本章全程右手系；手性是「约定的一部分」这个概念先立住，跨 API 的恩怨到对应节再结。手性的数值感：右手系里 x × y = z（东叉北得上天花板）；同一对向量换个左手系，公式没变，但「正 Z」那一边被叫反了，结论跟着翻——**叉乘公式本身没有手性，手性长在「你把哪边叫正 Z」里。**

本章选定声明，全程遵守：**列向量、右乘、右手系。**三张轴的速查卡，贴在显眼处：

| 约定轴 | 选项 A | 选项 B | 本章选择 |
|---|---|---|---|
| 乘法方向 | 列向量右乘 M·v | 行向量左乘 v·M | M·v |
| 存储主序 | 行主序 | 列主序 | 行主序（示例代码 C 数组） |
| 手性 | 右手系 | 左手系 | 右手系 |

约定没有对错，全程一致才是命——读别人代码先看它是 v·M 还是 M·v、Z 朝里还是朝外。拿到任何一段陌生矩阵代码，两问自查：**「乘法写在哪边？」**（定约定）与**「Z 朝哪边？」**（定手性）——两问答完，排雷完成大半。一段对照示意（说明性片段，非完整程序——省略结构与 main，仅看调用形态）：

```cpp
Vec3 p = M * v;        // 本章约定：列向量右乘（GLM 同款形态）
Vec3 q = v * M;        // DirectX 传统：行向量左乘——矩阵应当是 M 的转置
```

边界与陷阱：移植代码时「矩阵看起来被转置了」，先查乘法方向再查存储主序——两张轴各翻一次是转置、各翻两次等于没翻，排列组合对一遍就能定位。另外，光照计算只涉及向量与向量（点乘叉乘），完全不经过矩阵——**约定之战打的是「位置与变换」，不殃及 1.3/1.4 的纯向量运算**。

### 1.8 微积分核心：梯度求法线，积分算总和

微积分在图形学只消费两件东西：**梯度**（变化率的方向感）与**定积分**（连续求和）。每一件都从一个事故现场开始。

先看梯度。地形是一张高度场 h(x, y)：每个平面位置给一个高度。「地形光照看起来不对但说不出哪不对」——多半是法线错了，而求法线的正路是微积分。一元的导数 f′(x) 是瞬时变化率（切线斜率），你已认识；多元函数的升级版是**偏导数（partial derivative）**：∂h/∂x 是「只往东走、高度变化多快」（y 冻结），∂h/∂y 同理「只往北走」。把两个偏导打包成向量，就是**梯度（gradient）**：

```text
∇h = ( ∂h/∂x , ∂h/∂y )
```

梯度的几何身份：**指向上坡最快的方向**。站在山坡上环顾四周，梯度箭头指着最陡的上坡。一元版先找感觉：f(x) = x²，导数 f′(x) = 2x，在 x = 1 处 f′ = 2 > 0——函数正在上坡，往 x 增大的方向爬更陡；在 x = −1 处 f′ = −2 < 0——往 x 减小的方向才上坡。导数的符号就是一元的「坡向」，梯度把这件事推广到了「每个方向都有自己的坡度」的多元世界，并把它们合成一个箭头。

【推导·全程】高度场求法线。表面 z = h(x, y)，要的是「垂直于表面朝上」的单位向量。结论先行，再拆每个部件：

```text
n = normalize( -∂h/∂x , -∂h/∂y , 1 )
```

- **为什么是负号？**梯度指上坡最快方向；法线是「从表面竖起来」的方向，它水平分量必须与「上坡」相反——你在山坡上朝上坡方向走，脚下的表面朝向朝「下坡」一侧倾斜。负号就是把梯度水平分量转 180°。
- **为什么 z 分量是 1？**坡度平缓（偏导近 0）时法线应当竖直 (0, 0, 1)；坡度陡峭（偏导巨大）时法线被水平分量「拉倒」向近乎水平。z = 1 是归一化前的「基准高度」，让水平分量的相对大小直接编码坡度陡缓。

代入一个具体函数验算：h(x, y) = x·y，则 ∂h/∂x = y、∂h/∂y = x，在点 (2, 3) 处 n = normalize(−3, −2, 1)——手算即可完成，不需要任何库。再练一个本章深入专题要用的：h(x, y) = sin(x)·cos(y)，乘法求导法则拆开：∂h/∂x = cos(x)cos(y)（y 因子不变）、∂h/∂y = −sin(x)sin(y)（sin 对 y 的导数是 −cos，负号从这来）。两条偏导一落地，任意点的法线都能现场计算——深入专题会拿它当「解析真值」给两条数值路线对答案。

数值版一句：没有解析式（或懒得求导）时，用**有限差分（finite differences）**当偏导数的替身：∂h/∂x ≈ (h(x+ε, y) − h(x−ε, y)) / 2ε。先用一个能口算的函数感受它：h(x, y) = x·y 在点 (2, 3)，真值 ∂h/∂x = y = 3；取 ε = 0.1：((2.1)(3) − (1.9)(3))/0.2 = (6.3 − 5.7)/0.2 = 3——分毫不差！原因：x·y 沿 x 方向是线性的，中心差分对线性函数天然精确（它的误差项含三阶导，而线性函数的三阶导是零）。深入专题里的 sin(x)·cos(y) 是弯的，误差才开始出现。ε 取太大浮点相消、太大失去「瞬时」意义的完整讨论也在那里。顺带一句消费点：法线贴图本质就是「逐像素存梯度信息」（完整机制——切线空间——将在第 4 章展开）。

再看定积分。**定积分 = 连续求和**：把曲线下面积切成无数窄矩形求和取极限（黎曼和直觉）。图形学的消费点一句话：**渲染方程就是一个积分**——表面上每一点收到的光 = 周围所有方向来的光贡献的连续求和（将在第 6 章正式展开）；你在代码里写的每一层「累加贡献」循环，都是它的离散亲戚。积分思想的最小体验：∫₀¹ 2x dx，把 [0,1] 切成 N 条窄条、每条取左端点高度 2x 乘宽度 1/N 累加——左端点永远低估半条宽度，总和是 1 − 1/N：N = 10 时得 0.90，N = 1000 时得 0.999，步步逼近真值 1。**定积分不是符号游戏，是「切条求和取极限」这个动作本身**；1.9 的蒙特卡洛估 π 只是把「均匀切条」换成「随机撒点」，两者是同一件事的确定性/随机性两版。本章只需把「积分=求和的连续版」这个身份认下来，配合基础手算功：d/dx x² = 2x、∫₀¹ x dx = 1/2 级别的题要能闭卷做——自测题第 1 题与任务 2 会让练。

边界与陷阱：其一，偏导数符号 ∂ 不是希腊字母 δ，读「partial」；其二，梯度是**向量**（有方向），导数是**标量**（一元情形），混称会在法线推导里立刻翻车。

### 1.9 概率直觉：期望、方差与大数定律（概念级，蒙特卡洛铺路）

事故现场先行：「渲染出来的图全是噪点，等一会儿自己变干净了。」这不是 bug，也不是显卡抽风——这是随机采样的方差在收敛，是概率论在画面上的现场直播。本节只建立直觉，完整机制（蒙特卡洛积分、重要性采样）将在第 7 章展开。

三件套，每个一句话：

- **期望（expectation）**：长期平均。反复实验无数次的平均值收敛到的那个数。
- **方差（variance）**：离散程度。单次实验结果绕着期望抖得多厉害。
- **大数定律（law of large numbers）**：样本均值收敛到期望。样本越多，平均越稳。

用骰子把三件套过一遍：单次掷骰的期望 E = (1+2+3+4+5+6)/6 = 3.5——注意 3.5 根本掷不出来，期望是「长期平均」不是「某次结果」；方差描述你每次掷出的点数绕着 3.5 抖多厉害（1 到 6，抖得不小）；连掷一万次取平均，结果几乎必然贴着 3.5——这就是大数定律在工作。估 π 实验里「N = 100 乱跳、N = 10⁶ 稳如老狗」的同一出戏，骰子已经预演过了。

图形学消费点一个就够：路径追踪里每个像素是「随机采样路径的平均贡献」——单次采样抖得厉害（方差大），平均之后仍然收敛到真实亮度（大数定律）。**噪点是方差的脸，样本数是它的解药。**「为什么多采样会变清晰」的完整答案在第 7 章，这里先把三件套钉进脑子。

最小现场：蒙特卡洛估 π。往单位正方形均匀撒点，数落在四分之一圆内的比例——比例 ≈ π/4（面积比），乘 4 就是 π 估计。这是一切蒙特卡洛方法的原型：「用随机采样的平均值估计一个定积分」（四分之一圆面积正是 ∫√(1−x²) dx 的定积分——1.8 的积分身份在此合流）。

```cpp
// ch01_monte_carlo_pi.cpp —— 蒙特卡洛估 π：样本数越大，估计越稳（完整可编译）
#include <cstdio>
#include <random>

int main() {
    std::mt19937 rng(20260917u);                     // 固定种子：结果可复现
    std::uniform_real_distribution<float> unit(0.0f, 1.0f);

    for (long long n : {100LL, 10'000LL, 1'000'000LL}) {
        long long inside = 0;
        for (long long i = 0; i < n; ++i) {
            float x = unit(rng), y = unit(rng);      // 单位正方形内均匀撒点
            if (x * x + y * y <= 1.0f) ++inside;     // 落在四分之一圆内
        }
        double pi = 4.0 * double(inside) / double(n);
        std::printf("N = %9lld   圆内点数 = %9lld   pi ≈ %.5f\n", n, inside, pi);
    }
    return 0;
}
```

示例输出（示意——固定种子下结果确定，但具体数值随标准库实现而异，以你本机运行为准）：

```text
N =       100   圆内点数 =        84   pi ≈ 3.36000
N =     10000   圆内点数 =      7881   pi ≈ 3.15240
N =   1000000   圆内点数 =    784897   pi ≈ 3.13959
```（MSVC 实测；固定种子下同一标准库结果确定，但 `uniform_real_distribution` 的映射算法是实现定义的，换编译器/标准库数值会不同——这正是「以你本机运行为准」的含义）

读表方式比数值重要：误差量级约按 1/√N 收缩——N 每大 100 倍，小数点后多稳约 1 位。这就是大数定律的速度感，也是第 7 章「噪点随样本数收敛」的量化直觉。

读程序也有两处小刻意：固定种子（`std::mt19937 rng(20260917u)`）保证你跑出的数与同学、与明天的你一致；分档打印（10²、10⁴、10⁶）让你亲手量出收敛速度。还有个不起眼的细节：`4.0 * double(inside) / double(n)` 先乘后除——若写成 `inside / n`，整数除法直接归零；若全程用 float，百万级累加会有可感知的精度损耗（第 1 节 ch06 的数值意识在这里就能用上）。

把三件套套在估 π 实验上回看：单次撒点「圆内/圆外」是一个随机变量（方差不小，所以 N = 100 时估计在 3.2 附近乱跳）；N 个点的「圆内比例均值」是样本均值，它的期望恰好是 π/4（大数定律保证收敛）；样本越多，样本均值绕期望的抖动越小（方差随 N 缩小）。**期望给你「终点」，方差告诉你「路上多颠簸」，大数定律保证「走得够远就能到」。**量化一行：样本均值的抖动按 σ/√N 缩水——方差除以样本数再开根号，这正是上面 1/√N 收缩速度的出处。顺带留个坐标：这条「CPU 上用随机采样逼近积分」的路线，第 5 节会把同类思想搬上 GPU——那是后话。

边界与陷阱：其一，随机数引擎务必固定种子（`std::mt19937 rng(固定值)`）——不固定种子，你永远无法向别人复现自己看到的现象；其二，蒙特卡洛估计是**无偏但带噪**的——单次结果不保证更接近，保证的是「平均意义上的收敛」。

顺带答一个常见疑问：为什么不直接用 `rand()`？——`rand()` 的随机质量与范围是实现相关的（低位质量差是历史顽疾），且无法控制分布；C++11 起的 `<random>`（引擎 `mt19937` + 分布器）是标准库正解，随机质量、固定种子可复现、分布选择三样都齐。选工具看语义与保证，不看「能跑」——第 1 节的标准库选型观在这里继续适用。

### 1.10 数学库工程：Vec2/3/4 与 Mat4 落地（对位检验标准③）

四幕的最后一幕：把前三幕钉进代码。这一节同时是一笔挂账的兑付——第 1 节阶段 1 的实践任务原文要求「为第 2 节数学库逐类标注零/三/五法则该选哪个并补齐单元测试」，现在答案揭晓：**全部 rule of zero**（第 1 节 ch01 1.6 的法则表）。Vec 与 Mat 是纯值类型：没有堆资源、没有生命周期故事、拷贝就是按成员复制——五个特殊成员函数一个都不用写。图形学数学库几乎全部如此，这不是巧合而是「值语义几何对象」的天性。

设计决策四条，每条一个出处：

1. **纯值类型，全 rule of zero**——兑付第 1 节阶段 1 挂账（上文）；
2. **运算符按值返回、零堆分配、成员 constexpr 友好**——第 1 节 ch06 的性能世界观对齐：数学库在每帧热路径上被调用成千上万次，按值返回的小结构体对编译器最友好；一句带过不展开；
3. **默认写 float 具体版**，模板化 float/double 同套测试作为可选进阶——第 1 节 ch03 3.11 的 concepts 约束模板是进阶时的工具，先具体后泛化；
4. **每个函数一句几何意义注释**——阶段路线实践任务原文要求；「归一化 = 拧到长度 1、方向不变」级别的注释。

API 骨架（任务 1 的完整清单，本章正文给 Vec3 骨架级实现做样板）：

| 类型/函数 | 几何意义一句 |
|---|---|
| Vec2/3/4 加减、标量乘 | 位移叠加 / 掉头 / 步幅伸缩 |
| dot(a, b) | 方向一致性（含 cosθ） |
| cross(a, b)（仅 Vec3） | 垂直于两者的向量 |
| length / normalize | 长度 / 拧到 1 |
| Mat4 identity / mul | 什么都不做 / 复合 |
| Mat4 rotateX/Y/Z、scale、translate | 三件套变换（列向量右乘，平移在最后一列） |
| Mat4 transformPoint / transformVector | 作用在点（w=1）/ 向量（w=0）——两个入口，不许混用 |

Mat4 的三件套构造器，矩阵形状先混个脸熟（列向量右乘约定，平移住最后一列；旋转块就是 1.5 推过的正交块）：

```text
     [ 1 0 0 tx ]        [ sx 0  0  0 ]        [ c 0 -s 0 ]
T  = [ 0 1 0 ty ]   S  = [ 0  sy 0  0 ]   Rz = [ 0 1  0 0 ]   （c = cosθ, s = sinθ）
     [ 0 0 1 tz ]        [ 0  0  sz 0 ]        [ s 0  c 0 ]
     [ 0 0 0 1  ]        [ 0  0  0  1 ]        [ 0 0  0 1 ]
```

三张矩阵都是「纯数据」——没有隐藏状态、没有初始化顺序问题，谁先谁后全由使用者的乘法顺序说了算。

Vec2 与 Vec4 不是「Vec3 的缩水版/加长版」那么简单：Vec2 是 2D 场景（UI、屏幕空间）的一等公民，Vec4 在数学库里的身份是「点的容器」（1.6 的 w 语义）而非「四维向量」——它的第四个分量不是空间维度，这个边界要守住。

**显式缺席声明**：lookAt、ortho、perspective、viewport 不在本章 API 里——它们是变换链的零件，将在第 2 章实现（对位 P3·M0 的后半部分，见下文任务衔接）。

性质测试清单（检验标准③主场，每条对应一个「数学上必须成立」的性质）：RᵀR = I（旋转矩阵正交性）、**a**·(**a**×**b**) ≈ 0 与 **b**·(**a**×**b**) ≈ 0（叉乘垂直性）、|**a**×**b**| = |**a**||**b**|sinθ、旋转保长度、normalize 后长度为 1。**浮点比较一律用容差而非 ==**：连乘几次三角函数后 0.9999999 ≠ 1.0，== 会把正确的数学判成错误。容差给建议值：1e-5 量级的相对容差（乘一个 max(1, |a|, |b|) 的地板防止接近零时吹毛求疵），理由与更多浮点细节在任务 1 展开讨论。

测试先行的工作流建议：先把性质测试写出来、跑一遍看它**红**，再去实现 Vec3 让它变绿——红着开始绿着收工，你才确信测试真的在测东西（全部直接绿＝测试可能什么都没测，参考第 1 节 ch05 的红/绿实验同款思路）。

```cpp
// ch01_vec3_core.cpp —— Vec3 骨架实现 + assert 式性质测试（完整可编译）
#include <cassert>
#include <cmath>
#include <cstdio>

struct Vec3 {
    float x{}, y{}, z{};                 // 聚合类型：rule of zero（第 1 节 ch01 1.6）
};

inline Vec3 operator+(Vec3 a, Vec3 b) { return {a.x + b.x, a.y + b.y, a.z + b.z}; }
inline Vec3 operator-(Vec3 a, Vec3 b) { return {a.x - b.x, a.y - b.y, a.z - b.z}; }
inline Vec3 operator*(Vec3 a, float s) { return {a.x * s, a.y * s, a.z * s}; }
inline float dot(Vec3 a, Vec3 b) { return a.x*b.x + a.y*b.y + a.z*b.z; }  // 方向一致性
inline Vec3 cross(Vec3 a, Vec3 b) {      // 垂直于 a、b 的向量（右手系朝向）
    return {a.y * b.z - a.z * b.y,
            a.z * b.x - a.x * b.z,
            a.x * b.y - a.y * b.x};
}
inline float length(Vec3 a) { return std::sqrt(dot(a, a)); }
inline Vec3 normalize(Vec3 a) {          // 拧到长度 1、方向不变
    float len = length(a);
    assert(len > 0.0f);                  // 零向量没有方向：教学版直接拦截
    return {a.x / len, a.y / len, a.z / len};
}

bool approx(float a, float b, float eps = 1e-5f) {   // 相对容差比较
    float scale = std::fmax(1.0f, std::fmax(std::fabs(a), std::fabs(b)));
    return std::fabs(a - b) <= eps * scale;
}

int main() {
    Vec3 a{1, 2, 3}, b{4, 5, 6};
    Vec3 n = cross(a, b);                // 手算应为 (-3, 6, -3)

    // 性质 1：叉乘垂直性——a、b 与 n 的点乘都应为 0
    assert(approx(dot(a, n), 0.0f) && approx(dot(b, n), 0.0f));
    // 性质 2：反交换 a×b = -(b×a)
    Vec3 ba = cross(b, a);
    assert(approx(n.x, -ba.x) && approx(n.y, -ba.y) && approx(n.z, -ba.z));
    // 性质 3：|a×b| = |a||b|sinθ
    float cosT = dot(a, b) / (length(a) * length(b));
    float sinT = std::sqrt(1.0f - cosT * cosT);
    assert(approx(length(n), length(a) * length(b) * sinT, 1e-4f));   // 三角函数链路误差略大，容差放宽一档
    // 性质 4：归一化后长度为 1
    assert(approx(length(normalize(n)), 1.0f));

    std::printf("全部性质测试通过：a×b = (%.0f, %.0f, %.0f)\n", n.x, n.y, n.z);
    return 0;
}
```

示例输出（示意）：

```text
全部性质测试通过：a×b = (-3, 6, -3)
```

读程序两处小刻意：`approx` 的容差带 `max(1, |a|, |b|)` 地板——纯绝对容差在比较「接近 0 的量」（比如点乘 ≈ 0）时会因基准过小而敏感误判；性质 3 的容差放宽到 1e-4——三角函数与除法的链路误差比加减法大，容差跟着链路走。若某个 assert 变红，先打印两侧实际值看量级再改容差——直接改到红变绿不是调试，是掩耳盗铃。任务 1 里你会把测试拆成 testVec3()/testMat4() 这样的分组函数，将来接 CTest（第 1 节 ch04 4.6）时每组就是一个测试用例。

测试载体声明：单文件 assert 式自测起步——零工程依赖，跑起来就是验证；要接进 CMake/CTest 的完整测试目标，第 1 节 ch04 4.6 的资产直接复用即可（可选进阶，本章不强制）。**一个必须知道的坑：`assert` 在定义了 `NDEBUG` 时会被编译掉**——MSVC 的 Release 模板默认带 NDEBUG，此时「测试程序」会变成什么都不测的空壳还显示全绿。测试构建请用 Debug 配置，或手动从编译选项里删掉 NDEBUG（构建速查里有命令）。

边界与陷阱：其一，normalize 的零向量拦截在真实工程里各有门派（断言、返回原值、返回占位方向），任务 1 会让你做一个显式决策而不是静默除零；其二，Vec4 在数学库里的身份是「点的容器」而非「四维向量」——它的 w 分量是 1.6 的语义，不是第四个空间维度。

## 深入专题：一个高度场的法线解剖——梯度、叉乘与数值验证的三方对账

1.3 的光照公式里有个 N，1.4 教了它怎么出生（叉乘），1.8 教了另一条出生路（梯度）。同一个法线，两条路，答案该一致——「该一致」是口头禅，「验给数值看」才是工程。本专题把三条路线取同一批法线，逐点对账：

1. **解析梯度路线**：h(x, y) 有闭式偏导时直接代入 n = normalize(−∂h/∂x, −∂h/∂y, 1)——理论真值；
2. **有限差分路线**：∂h/∂x ≈ (h(x+ε, y) − h(x−ε, y)) / 2ε——没有解析导数时的替身；
3. **离散几何路线**：把高度场网格化成小三角形，用 (B−A)×(C−A) 求面法线——这正是引擎处理网格的真实做法（每个顶点的「顶点法线」就是邻接面法线的平均，此处点到即止）。

三条路线的分工一句话：解析路线当**裁判**（有公式时它是真值），差分路线当**万金油**（没公式也能算），离散路线当**现场**（网格世界的日常）。网格化长什么样，看个示意：

```text
   p0 ------ p1        每个格子拆两个三角形（A、B），
   |  \      |        逐格用 (B−A)×(C−A) 造面法线；
   | A  \   B |        顶点法线 = 邻接面法线的平均（此处点到即止）
   |     \    |
   p3 ------ p2
```

选一个有解析解的高度场 h(x, y) = sin(x)·cos(y)，偏导顺手可得：∂h/∂x = cos(x)cos(y)，∂h/∂y = −sin(x)sin(y)。三条路的完整对账程序：

```cpp
// ch01_heightfield_normals.cpp —— 高度场法线三方对账：解析 vs 有限差分 vs 离散几何（完整可编译）
#include <cmath>
#include <cstdio>
#include <initializer_list>   // 花括号范围 for 需要（MSVC 不会随 cstdio 隐式提供）

struct Vec3 { float x, y, z; };

float h(float x, float y) { return std::sin(x) * std::cos(y); }   // 高度场

Vec3 normalize3(Vec3 n) {
    float len = std::sqrt(n.x*n.x + n.y*n.y + n.z*n.z);
    return {n.x / len, n.y / len, n.z / len};
}

Vec3 analyticNormal(float x, float y) {          // 路线 1：解析梯度
    float gx =  std::cos(x) * std::cos(y);       // ∂h/∂x
    float gy = -std::sin(x) * std::sin(y);       // ∂h/∂y
    return normalize3({-gx, -gy, 1.0f});
}

Vec3 finiteDiffNormal(float x, float y, float eps) {   // 路线 2：中心差分
    float gx = (h(x + eps, y) - h(x - eps, y)) / (2.0f * eps);
    float gy = (h(x, y + eps) - h(x, y - eps)) / (2.0f * eps);
    return normalize3({-gx, -gy, 1.0f});
}

Vec3 discreteNormal(float x, float y, float s) {  // 路线 3：网格三角面法线
    Vec3 e1{s, 0.0f, h(x + s, y) - h(x, y)};      // 沿 x 的网格边（含高度差）
    Vec3 e2{0.0f, s, h(x, y + s) - h(x, y)};      // 沿 y 的网格边
    Vec3 n{e1.y*e2.z - e1.z*e2.y,
           e1.z*e2.x - e1.x*e2.z,
           e1.x*e2.y - e1.y*e2.x};                // e1 × e2，1.4 的老朋友
    return normalize3(n);
}

float angleDeg(Vec3 a, Vec3 b) {                  // 两法线夹角（度）；均已归一化
    double d = double(a.x)*b.x + double(a.y)*b.y + double(a.z)*b.z; // 点乘即 cos
    if (d >  1.0) d =  1.0;   // 求角升 double：acos 在 cos≈1 处放大误差，
    if (d < -1.0) d = -1.0;   // float 会给极小角蒙上 ±0.02 度级噪声
    return float(std::acos(d) * 180.0 / 3.14159265358979);
}

int main() {
    Vec3 a = analyticNormal(3.14159265f / 3.0f, 3.14159265f / 6.0f);
    Vec3 f = finiteDiffNormal(3.14159265f / 3.0f, 3.14159265f / 6.0f, 1e-3f);
    Vec3 d = discreteNormal  (3.14159265f / 3.0f, 3.14159265f / 6.0f, 0.5f);
    std::printf("[点 (pi/3, pi/6) 的三条法线]\n");
    std::printf("  解析梯度  n = (%.4f, %.4f, %.4f)\n", a.x, a.y, a.z);
    std::printf("  有限差分  n = (%.4f, %.4f, %.4f)   与解析夹角 %.3f 度\n", f.x, f.y, f.z, angleDeg(f, a));
    std::printf("  离散几何  n = (%.4f, %.4f, %.4f)   与解析夹角 %.3f 度\n", d.x, d.y, d.z, angleDeg(d, a));

    // ── 误差方向感：步长粗细如何影响两条数值路线 ──
    std::printf("[步长扫描]  eps（差分） / s（网格）\n");
    for (float step : {0.5f, 0.1f, 0.01f}) {
        Vec3 f2 = finiteDiffNormal(3.14159265f / 3.0f, 3.14159265f / 6.0f, step);
        Vec3 d2 = discreteNormal  (3.14159265f / 3.0f, 3.14159265f / 6.0f, step);
        std::printf("  步长 %.2f：差分 vs 解析 %.4f 度   网格 vs 解析 %.4f 度\n",
                    step, angleDeg(f2, a), angleDeg(d2, a));
    }
    return 0;
}
```

示例输出（示意，角度数值以本机实测为准——趋势是稳定的）：

```text
[点 (pi/3, pi/6) 的三条法线]
  解析梯度  n = (-0.3693, 0.3693, 0.8528)
  有限差分  n = (-0.3693, 0.3693, 0.8528)   与解析夹角 0.011 度
  离散几何  n = (-0.1949, 0.5039, 0.8415)   与解析夹角 12.666 度
[步长扫描]  eps（差分） / s（网格）
  步长 0.50：差分 vs 解析 1.0618 度   网格 vs 解析 12.6662 度
  步长 0.10：差分 vs 解析 0.0466 度   网格 vs 解析 2.5889 度
  步长 0.01：差分 vs 解析 0.0179 度   网格 vs 解析 0.2590 度
```

读程序两处小刻意：其一，对账用**夹角**而不是分量差——角度是方向误差的尺度不变量纲，最直观；其二，步长扫描放在同一张表里，两条路线的误差行为同框对比，规律自己会浮出来。若把采样点换成一百个随机点、只报告最大夹角，你就得到了一台「法线正确性抽查器」——任务 3 会借用它。

读表三件事：

- **离散几何 = 「单边差分」的亲戚**。把 e1×e2 展开：n ∝ (−Δh_x/s, −Δh_y/s, 1)，其中 Δh_x = h(x+s, y) − h(x, y)——这正是**前向差分**版的梯度。所以网格法天然比中心差分粗一级。扫描表里藏着两条收敛律：中心差分在浮点噪声接管前是**二阶**的（步长 × 0.2，误差 × 0.044：1.0618 → 0.0466）；离散几何是**一阶**的（步长 × 0.2，误差也 × 0.2：12.67 → 2.59 → 0.259，误差/步长比恒在 ≈ 26）。阶数不必背，看表就能读出来。
- **差分不是越细越好**。扫描表已经露出苗头：步长 0.01 时差分误差 0.0179 度，比二阶外推的 ≈0.001 高出一个量级——float 的舍入噪声地板（本例 ≈0.01–0.02 度）已经接管。ε 再小下去，h(x+ε) − h(x−ε) 变成「两个几乎相等的浮点数相减」，有效位数被相消灭，误差只会回升。**步长是「截断误差 vs 舍入误差」的拔河**——这就是任务 1 里「浮点容差怎么定」的体感来源，也是自测题 7「ε 太小」的现场答案。
- **网格法是引擎的常态**。真实网格没有解析式，法线只能离散地造——所以「法线略有偏差」不是 bug 而是离散化的宿命，光照里的平缓或生硬差异常溯源到此。
- **换个点再跑**：把 main 里的点换成 (0.7, 0.3)，预期解析法线 ≈ (−0.5831, 0.1519, 0.7981)，差分仍在 0.01 度量级（float 噪声地板）、网格仍在 10 度上下（示意值，以本机实测为准）——趋势不随点变，规律才算被验证而非被巧合。

收束：1.3 里那个 N 现在有出身了（两条流水线都能造）；「误差量级、容差选择」的数值意识种子也在本专题发芽——它是第 4 章着色的地基，也是第 1 节 ch06「先测量」世界观在数学侧的回声。工程注记：任务 1 完成后，回头用你自己的库重写本专题的三个函数——normalize3 换成 normalize、叉乘换成库函数——这也是对库接口的一次实战检验。

延伸玩法（可选）：① 在网格上多验几个点，找一个「三条路分歧最大」的位置（坡度剧变处往往最热闹），说说为什么；② 把高度场换成 h(x, y) = sin(x)·sin(y)，重推偏导重对账——检验的是你自己的求导，不是代码；③ 把 ε 从 1e-3 一路改到 1e-7，亲眼看到「舍入误差反杀」的 U 型曲线——这一眼胜过十段文字。

## 常见误区

1. **只看视频不写作业。**
   - 症状：3B1B/GAMES101 看得津津有味，一说手推就卡壳；
   - 病根：视频建立画面感，但「看懂了」≠「会推了」，推导能力只长在草稿纸上；
   - 纠偏：每章至少动笔推一遍核心公式（本章即 1.5 旋转矩阵），任务 2 就是把这件事制度化。
2. **第一遍就用 GLM 代替手写数学库。**
   - 症状：glm::rotate 一调，画面对了但问「为什么」答不上；
   - 病根：跳过手写等于跳过几何直觉的建立期，库把你该犯的错也一并免了；
   - 纠偏：本章手写，第 3 节工程化阶段再换 GLM——届时你换的是省键盘，不是学理解。
3. **前置数学贪多求全、迟迟不进正文。**
   - 症状：在线代教材里啃特征值、秩、行列式深水区，一个月还没碰图形学；
   - 病根：把「系统学习」误解成「学完整门课」；
   - 纠偏：只学消费子集（1.1 的预算表），学完即走——缺的东西真需要时会以「痛点现场」的形式回来找你。
4. **全程跳过推导只记结论。**
   - 症状：R(θ) 背下来了，θ = 90° 时却不敢确认 x̂ 该到哪；
   - 病根：记结论拿到的是「形」，推过程拿到的才是「为什么」与「可重构性」；
   - 纠偏：三处显式推导（1.5/1.6/1.8）跟推一遍，之后同类公式都能现场重造。
5. **把行/列主序与乘法方向混为一谈。**
   - 症状：移植代码「矩阵看起来被转置了」，在存储上瞎折腾；
   - 病根：存储主序（内存问题）与 v·M/M·v（数学约定）是两张独立轴；
   - 纠偏：按 1.7 的排雷顺序查——先看乘法写法，再看内存布局，排列组合定位。
6. **叉乘方向不看手性。**
   - 症状：在左手系语境沿用右手定则的结论，法线朝向翻转、剔除判定反向；
   - 病根：「右手定则」里的「右手」是约定的一部分，不是宇宙公理；
   - 纠偏：拿到任何「法线/朝向」问题先问手性，跨 API（第 3/6 节）时把 Z 朝向当第一检查项。
7. **性质测试用 == 比较浮点。**
   - 症状：RᵀR「明明应该等于 I」测试却红；
   - 病根：三角函数与乘法累积误差，0.9999999 ≠ 1.0 是浮点的常态不是 bug；
   - 纠偏：按量级设相对容差（1e-5 量级、带 max(1, |a|, |b|) 地板），体感训练见深入专题的步长扫描。
8. **点与向量乱升 w。**
   - 症状：把方向也平移了（法线跟着物体跑、光照错位），或把位置当「平移不变」处理；
   - 病根：w 语义（1=点，0=向量）没进肌肉记忆，一个 transform 函数通吃两类输入；
   - 纠偏：数学库拆 transformPoint/transformVector 两个入口（1.10），评审时见到「对向量调用平移」直接打回。

## 参考答案

### 自测题

**1.**
- 旋转矩阵：x̂ 转 θ 后到 (cosθ, sinθ)，ŷ 到 (−sinθ, cosθ)，按列摆好即 R(θ) = [cosθ −sinθ; sinθ cosθ]；
- R(90°)：x̂ 到 (0, 1)、ŷ 到 (−1, 0)，即 [0 −1; 1 0]；
- uniform scale = 2：两列都是自身 2 倍，即 diag(2, 2) = [2 0; 0 2]；
- 微积分：d/dx x³ = 3x²（幂法则）；∫₀¹ 2x dx = [x²]₀¹ = 1（x² 的导数是 2x，反过来看面积正好是 1——积分 = 连续求和的最小体验）。

**2.**
- Lambert：物理上「表面朝向与光方向夹角越小受光越足」，这个「一致程度」的数学名就是余弦；单位化后 N·L 正是 cosθ——正对光（θ = 0）取 1 最亮，掠射（θ = 90°）取 0 熄灭，负值是背光钳零；
- 叉乘与剔除：三角形朝外的法线由 N = normalize((B−A)×(C−A)) 造出，叉乘的结果天然垂直于三角形所在平面；顶点绕序决定叉乘两条边向量的先后，反交换性意味着绕序反过来法线就反向——所以「哪个面朝外」是绕序的约定，剔除判定 N·V 的符号读数依赖这个约定必须全程一致。

**3.**
- 性质测试清单：RᵀR = I（旋转矩阵正交性——列向量组标准正交）；a·(a×b) ≈ 0 与 b·(a×b) ≈ 0（叉乘垂直性）；|a×b| = |a||b|sinθ（几何式与分量式自洽）；旋转后 |v| 不变（刚体性）；normalize 后长度为 1（归一化的定义）；平移作用于点变、作用于向量不变（w 语义）；
- 容差：用相对容差（约 1e-5），并给误差比较加 max(1, |a|, |b|) 地板防近零误报；
- 为什么不用 ==：浮点运算有累积舍入，「数学上相等」在代码里表现为「容差内相等」——强行 == 会把正确的数学判错（体感实验见深入专题步长扫描）。

**4.**
- w = 1 表示点（有位置，平移有意义），w = 0 表示向量（只有方向，平移无意义）；
- 作用于点：位置分量加上平移量，w 保持 1；
- 作用于向量：最后一列的平移量被 w = 0 全部吃掉，方向分量纹丝不动，w 保持 0。

**5.**
- 不是同一件事：乘法方向（v·M 还是 M·v）是数学约定，主序（行/列铺内存）是存储布局，两张轴独立；
- 现实组合：本章 1.6 的示例 Mat4 就是「列向量右乘 + 行主序存储」——C 风格二维数组按行铺内存，数学上照样 M·v；
- 为什么成立：内存怎么摆只影响「取下标的顺序」，不影响「数学上谁乘谁」；
- 对照：GLM 是列主序 + 列向量，DirectXMath 是行主序 + 行向量。

**6.**
- 先旋后平：点绕原点转完再整体挪走，落点 = 平移方向上偏移的「已旋转姿态」；
- 先平后旋：点先挪到远处，再绕原点转——转的角度不变但半径变了，落点完全不同（数值证据见 1.5 程序：R·S·v = (0, 2) vs S·R·v = (0, 1)）；
- 读法：M₁M₂v 从右往左读，先 M₂ 后 M₁——离向量最近的先作用。

**7.**
- 公式：∂h/∂x = y，∂h/∂y = x，法线 n = normalize(−y, −x, 1)；
- 负号：梯度指上坡最快方向，法线的水平分量要与「上坡」相反（表面朝向从坡面「竖起来」），故取负；
- ε 太大：中心差分的「以直代曲」失真（截断误差大，弯曲处偏差明显）；
- ε 太小：h(x+ε) 与 h(x−ε) 几乎相等，相减发生有效数字相消（舍入误差失控），误差反而回升——步长是两种误差的折中。

**8.**
- 三件套：期望 = 长期平均；方差 = 单次结果绕期望的抖动幅度；大数定律 = 样本均值随样本数增大收敛到期望；
- 回答：路径追踪每个像素是「随机路径贡献的平均值」：单条路径抖得厉害（方差 → 噪点），平均到足够多条后收敛到真实亮度（大数定律）——所以样本越多噪点越少，误差约按 1/√N 收缩（1.9 的估 π 表格就是它的速度感）。
