## 分节大纲（10 节）

### 2.1 变换链总览：六个空间与一张地图
- 空间序列与术语（LearnOpenGL 口径）：局部/模型空间 → 世界空间 → 观察/相机空间 → 裁剪空间 → NDC → 屏幕空间；「过渡坐标系的意义：某些操作在特定空间里做更方便」。
- 各段职责一句话：model 把局部坐标摆进世界；view 把世界搬进「以相机为原点」的观察坐标；projection 把观察坐标压进裁剪视体；÷w 得 NDC；viewport 落到屏幕像素（songho 管线视角 object→eye→clip→÷w→NDC→window 一句对照）。
- GAMES101「拍照三步」记忆结构：摆人（Model）→ 放相机（View）→ 按快门（Projection）。
- 连乘次序 P·V·M·v：离 v 最近的是 model、先作用（复用 ch01 1.5「靠近向量的先上场」）；顶点着色器输出裁剪坐标的概念级一句（不展开 API）。
- 症状定位地图预告：链路每环出错的典型症状概览（看不见/拉伸/镜像/深度错乱 → 哪一环），本节只立地图、深入专题给数值现场。
- 示例规划：无完整示例（地图节）；说明性「空间旅程表」+ 文字。
- 粗体结论候选：**MVP 不是三个孤立的矩阵，是一条流水线——每一站把世界搬进一个更好做事的空间。**
- 篇幅预算：约 90–120 行。
- 开场痛点建议（先为什么）：「画面全黑、物体不知道飞哪去了、动一个矩阵全体乱跳」——没有链路地图就只能瞎调；本节先发地图。

### 2.2 模型变换：把物体摆进世界
- 后向引用 ch01 三件套（rotateX/Y/Z、scale、translate，列向量右乘、平移在最后一列）——本节只做组装不做重推。
- M = T·R·S 的组合次序及其理由：缩放旋转绕物体自身原点进行、平移最后摆位（「先穿袜子再穿鞋」的复用）。
- 绕任意点旋转三明治套路 T(c)·R·T(−c)——兑现 ch01 1.5 边界陷阱「绕自身中心转？挪过去、转完挪回来」的承诺。
- 局部坐标的意义：模型在自身坐标系里定义（建模方便），模型矩阵 = 物体的「出生证明 + 摆放记录」；模型矩阵可分解可组合（引擎变换层级的观念种子，一句）。
- 示例规划：说明性片段即可（T·R·S 组合与三明治套路的打印小程序片段，复用 ch01 库形态）；无完整可编译示例的必要。
- 粗体结论候选：**局部坐标是物体的母语——模型变换就是把母语翻译成世界语，翻译次序即命运。**
- 篇幅预算：约 80–110 行。
- 开场痛点建议：给角色加「自转 + 公转 + 缩放」时转着转着飞出去——缩放旋转绕的是谁的原点？从三明治套路切入。

### 2.3 视图变换与 lookAt：把相机请回原点
- 拍照三步第二步；核心直觉：**视图变换 = 把世界「反向搬进相机坐标系」**——相机固定在原点、朝 −Z（OpenGL 眼空间约定）；「移相机 = 用相机变换的逆去移整个场景」。
- 正交基构造顺序（LearnOpenGL 工程口径）：zaxis = normalize(eye − target)（相机 z 基指向相机后方）、xaxis = normalize(cross(worldUp, zaxis))、yaxis = cross(zaxis, xaxis)——世界 up 只用来定向，非正交时先出 x 再回推 y，天然正交化（兑现 ch01 1.4 种子）。
- 【推导规划·显式】lookAt 完整推导全过程：视图矩阵 = R_view·T_view（GAMES101 口径）；旋转部分由正交矩阵「逆 = 转置」直接写出（回收 ch01 1.5 RᵀR=I）——基向量按行摆放、平移列 = −(各基·eye)；推导必须走完而非给结论。
- 分歧注记（如实标注，一句即可）：forward 轴符号两派——OpenGL/GLM 右手系看 −Z（z 基 = eye − target）vs D3D 左手系看 +Z（z 基 = target − eye），矩阵互为镜像差异只在符号；本章选定右手系看 −Z并全程声明。
- 示例规划：**完整可编译** `ch02_lookat.cpp`——给定 eye/target/up 构造视图矩阵，验证三条性质：eye 变换后落在原点、target 方向落在 −Z 上、三个基向量互相正交（点乘≈0 打印）。
- 粗体结论候选：**视图矩阵是相机变换的逆——不是相机走向世界，而是世界走向相机。**
- 篇幅预算：约 120–150 行（重节）。
- 开场痛点建议：「相机在哪？为什么改了相机位置全场景都动？」——因为动的从来不是相机，是整个世界；从「快门不动、景动」切入。

### 2.4 正交投影：先把长方体拍成立方体
- 直观版：相机在原点看 −Z、up 朝 Y，丢掉 z 再把矩形平移缩放到 [−1,1]²；正式版：把长方体 [l,r]×[b,t]×[f,n] 映射到规范立方体 [−1,1]³。
- 【推导规划·显式】逐轴映射推导全过程：x_ndc = 2·x/(r−l) − (r+l)/(r−l)，y、z 同构——「先缩放到长度 2、再平移到居中」的模板是白板推导一切「区间映射」矩阵的可复用方法；合并成 M_ortho = S·T 两步矩阵，推导走完。
- **n/f 负值雷区**（多源一致确认的第一颗雷）：相机看 −Z 时 n、f 取负值且 n > f；glOrtho 工程惯例是传正的距离、内部取负——推导口径与工程口径必须分清，本章推导用 GAMES101 负值口径、库 API 用正距离口径（2.10 统一声明）。
- 正交投影的两个性格（为 2.5 立对照组）：w 恒为 1（除法空操作）、平行线保持平行、远近一样大——「图纸/2D UI 的朋友，透视的对照组」。
- 示例规划：**完整可编译** `ch02_ortho.cpp`——角点映射验证（l→−1、r→+1、n→−1、f→+1）+ 一对平行线段投影后方向仍平行的数值验证。
- 粗体结论候选：**正交投影是刚性搬运：换的是坐标系，不改的是形状——它没有透视，所以它是透视最好的对照组。**
- 篇幅预算：约 100–130 行。
- 开场痛点建议：「为什么 CAD/2D 游戏永远近大远小不存在？」——先认识不带走透视的那一半，才知道透视矩阵在多做哪一半。

### 2.5 透视投影：相似三角形到矩阵的完整旅程（检验标准①主场，全章最重节）
- 视锥体引入：透视的可见区是一个截头四棱锥；为什么透视不能直接「丢 z」——透视除以深度，不是线性变换，相似三角形 x′ = n/z·x 先立画面。
- 【推导规划·显式·必须完整全过程】GAMES101「挤压」推导四步，正文逐步走完、不许结论式跳步：
  1. 相似三角形：视锥内点 (x,y,z) 在近平面上的像 x′ = n/z·x、y′ = n/z·y；
  2. 齐次化技巧：(x,y,z,1) → (nx, ny, 未知, z)——前三行解出、第四行设 (0,0,1,0) 让 w 承载 z；
  3. 用三个不变量解第三行：近平面上点不变、远平面上点的 z 不变、远平面中心点不变 → 挤压矩阵 M_persp→ortho；
  4. M_persp = M_ortho · M_persp→ortho（先压成长方体、再做正交投影）——正交推导（2.4）在此被复用，两节互为因果。
- OpenGL 口径最终矩阵：以正距离 n、f 与 l/r/b/t 表达，第三行 (0, 0, −(f+n)/(f−n), −2fn/(f−n))、第四行 (0, 0, −1, 0)；说明 −2fn/(f−n) 一项的来历（近平面映 z_ndc=−1、远平面映 +1 两约束联立解）与 GAMES101 版的代数等价。
- fovY/aspect 参数化（GAMES101 L05 开头口径）：t = |n|·tan(fovY/2)、r = aspect·t——「竖直 fov + 纵横比」是现代 API（glm::perspective、glMatrix）的通用参数形态。
- 两句边界注记：①挤压后中间深度的 z 会挪动（非不动）——z 非线性的代数根源，深入留 2.9/第 3 章；②可逆性精确口径「压扁投影不可逆，API 投影矩阵可逆但除法后不可逆」（真投影 det=0 丢深度 vs 4×4 投影矩阵把深度编码进 z/w 保住信息——分水岭是透视除法）。
- 示例规划：**完整可编译** `ch02_perspective.cpp`——验证近/远平面角点 z_ndc = −1/+1、视锥内点的 w_clip = −z_view（打印对照表）。
- 粗体结论候选：**透视投影矩阵的全部秘密一句话：让 w 偷偷记住深度，透视除法时刻一次结账。**
- 篇幅预算：约 150–180 行（重节，白板推导主场）。
- 开场痛点建议：「面试/考试让手推透视投影矩阵，背过忘了怎么推」+「抄 glm::perspective 参数全对、画面就是不对」——推导不是仪式，是检验标准①的直通车。

### 2.6 透视除法与 w：近大远小的账单（检验标准②主场）
- 裁剪空间 → NDC：(x,y,z,w) ÷ w = (x/w, y/w, z/w)；**正式收束 ch01 1.6 伏笔**（标注「兑现 ch01 挂账」）：齐次坐标 w 的第二身份从「区分点/向量」升格为「透视的载体」。
- **裁剪发生在除法之前**：判据 −w ≤ x,y,z ≤ w（Khronos 口径）；为什么用 ±w 而非 ±1——在除法前完成裁剪，除法后齐次信息已丢。
- w 的几何意义：透视投影下 w_clip = −z_view（视空间深度的负值拷贝；右手系相机前方 z_view < 0 故 w > 0）——「w 是视空间深度的一份拷贝」；正交投影 w 恒 1、除法是空操作。
- 近大远小的机制（检验标准②的标准答案）：除以 w（即除以深度）后，屏幕坐标随距离 1/z 缩放——远处 w 大、商小、显得小；平行线向灭点会聚是同一除法的结果。
- 前向指针一句：除以 w 后屏幕空间线性插值 ≠ 视空间线性——透视校正插值（1/z 插值才正确）将在第 3 章展开。
- 示例规划：**完整可编译** `ch02_perspective_divide.cpp`——同一物体（同尺寸线段/方块角点）放在两个深度，打印除法前后坐标对比（近大远小数值版）+ 一个视锥外点用 ±w 判据的裁剪判定演示。
- 粗体结论候选：**w 是视空间深度的一份拷贝——透视除法除以 w，就是除以「你离相机多远」。**
- 篇幅预算：约 100–130 行。
- 开场痛点建议：「为什么铁轨在画面里会聚成一点、近处的人比远处的大？谁在除？」——从「画面里天然存在一次除法」切入。

### 2.7 视口变换与完整链路：从 NDC 到像素（手工计算主场）
- NDC → 窗口坐标的仿射映射：(−1,−1) 映到视口左下角、(+1,+1) 映到右上角；矩阵形式：缩放 (width/2, height/2) + 平移 (x + width/2, y + height/2)，z 顺带映射深度范围（默认 [0,1]）——推导简短但显式给出。
- 数值例题（LearnOpenGL 书内例子）：NDC (−0.5, 0.5) 经 800×600 视口 → (200, 450)——正文手算走一遍。
- 口径注记一句：本教程采用 width/2 主流口径；「像素中心 vs 像素边界」的半像素偏移在 Foley 系教材中存在，不展开。
- 【推导规划·显式】**完整链路手工计算全过程**：选一组可手算的具体数值（写作代理定「标准数据集」：简单平移/旋转的 M、一组整数坐标的 eye/target/up、fovY=90°/n、f 取小整数、视口 800×600——全部数值让读者纸面可推），一个顶点从模型空间出发逐站算到像素：M·V·P → 裁剪判定（±w）→ ÷w → 视口 → 像素坐标。这一站走完，「一个顶点的完整旅程」闭环，阶段学习目标的地图成型。

### 2.8 法线变换：为什么是逆转置 (M⁻¹)ᵀ
- 事故现场：圆/球被非均匀压扁后，直接用 M 变换的法线明显不再垂直于表面（PBRT 图示口径的文字化叙述）——光照立刻错位。
- 【推导规划·显式】Lengyel 代数论证全过程：切向量 t′ = Mt、法线需保持 n′·t′ = 0；取 n′ = (M⁻¹)ᵀn 时 n′ᵀt′ = nᵀM⁻¹Mt = nᵀt = 0 恒成立——逆转置是「保持垂直关系」的选择；正文走完这五行代数。
- 概念一句（点到即止）：法线本质是协变向量（covector），与切向量（逆变向量）对偶（Nathan Reed 口径）——不展开。
- **化简边界（可直接立的工程结论）**：只含旋转与均匀缩放时 (M⁻¹)ᵀ ∝ M（差一个标量），normalize 后等价——「均匀缩放随便乘、非均匀缩放必须逆转置」；变换后必须 normalize 重新归一。
- 工程口径：法线矩阵（normal matrix）= model 矩阵去掉平移的 3×3 部分再做逆转置；与 ch01 深入专题「高度场法线」的一句衔接（同一批法线经非均匀缩放做对照实验可复用该场景）。
- 前向指针一句：切线空间与法线贴图将在第 4 章展开。
- 示例规划：**完整可编译** `ch02_normal_transform.cpp`——非均匀缩放（如 scale(1, 1, 0.5)）下，「直接乘 M」vs「乘 (M⁻¹)ᵀ」两路法线与变换后切向量的点乘对账（一路明显非零、一路≈0）。
- 粗体结论候选：**切向量用 M、法线用 (M⁻¹)ᵀ——法线不是方向，是「垂直关系」的守护者。**
- 篇幅预算：约 100–130 行。
- 开场痛点建议：「模型一压扁光照就脏了，可法线明明变换了呀」——它被变换了，但被错误地变换了；从「垂直关系才是法线的本质」切入。

### 2.9 API 差异与坑点地图：同一理论，几套约定
- NDC 对照总表（TU Wien primer 口径）：x 恒朝右；OpenGL y 朝上 + z ∈ [−1,1]；Vulkan y 朝下 + z ∈ [0,1]（两者 NDC 手性相反）；D3D/Metal 同「y 下 z ∈ [0,1]」口径（Unity 官方跨 API 对照佐证）。
- 经典症状预讲解：「OpenGL 投影矩阵直接搬进 Vulkan 会 y 翻转 + 深度半带被裁掉」——多源确认的移植第一坑；这是检验标准③「镜像/看不见」症状的理论出处。
- 弥合机制一句级（存在性声明，实操归第 3/6 节）：glClipControl(ARB_clip_control)、VK_EXT_depth_clip_control、GLM 的 NO/ZO 宏与 perspectiveZO（数学库侧显式 API 分叉佐证「z 范围双口径」）；reversed-Z（minDepth/maxDepth 倒挂 + 浮点深度提升远处精度）一句。
- 主序/乘法方向差异结论级一句（后向引用 ch01 1.7，fgiesen 出处）：存储主序与乘法方向正交，GLM 与 DirectXMath 是两端代表。
- 深度非线性第一印象（深入归第 3 章）：透视后深度值与 1/z 成正比而非线性距离，精度堆在近平面附近；**zNear 逼近 0 是深度精度第一杀手**（zFar 拉远伤害小得多）；z-fighting 一词的现场描述。代数勾连一句：z_ndc 分子分母（−2fn/(f−n) 一项）除以 w 后即成 a + b/z 型——非线性是 2.5 推导的直接副产品，不是硬件玄学。
- 边界声明：本节仅理论对照地图，全程不涉 API 实操；坑点的实操复现将在第 3 节/第 6 节展开。
- 示例规划：无完整示例；说明性对照表为主（API × y 朝向 × z 范围 × 手性四列速查表）；数值实验（GL/Vulkan 深度口径对照、z 非线性扫描）列入深入专题可选延伸。
- 粗体结论候选：**理论只有一套，约定各有一套——写投影矩阵前先问：我的 NDC z 从几到几、y 朝哪边？**
- 篇幅预算：约 90–120 行。
- 开场痛点建议：同一段投影代码从 GL 教程搬进 Vulkan 工程画面「上下镜像 + 远处消失」——不是 bug，是约定之战的实弹；本节发对照地图。

## 常见误区（8 条，症状/病根/纠偏三段式）
1. **连乘次序随手写（M·V·P·v）**：症状：全体顶点飞出画面或完全错乱；病根：忘了「离 v 近的先作用」，三个矩阵职责清楚了但顺序装反；纠偏：P·V·M·v 从右往左读——先摆物体（M）、再摆相机（V）、最后按快门（P），乘法方向约定的排雷沿用 ch01 1.7 两问自查。
2. **忘透视除法**：症状：投影后坐标量级怪异、当屏幕坐标用全飞；病根：把裁剪坐标直接当 NDC，漏掉 GPU 管线里固定的那次 ÷w；纠偏：投影后必除 w；裁剪判定在除法前用 ±w 做。
3. **Z 朝向 / forward 符号弄反**：症状：画面镜像或整个深度带被裁；病根：z 基 = eye − target（右手系看 −Z）写成 target − eye（D3D 口径），两派混用；纠偏：选定「右手系、相机看 −Z」全程声明一致，跨 API 先查 Z 朝向（ch01 1.7 + 2.9 对照）。
4. **n/f 符号两套口径混用**：症状：手推结果与库函数对不上、深度方向反了；病根：GAMES101 推导用负值（相机看 −Z，n > f）而 glOrtho/GLM 传正距离内部取负，两口径在草稿纸上打架；纠偏：推导前声明口径，库 API 统一正距离参数（2.10 口径决策）。
5. **fov/aspect 弄反或 aspect 定义用错**：症状：画面拉伸变形；病根：fovY 是竖直方向视场角、r = aspect·t 且 aspect = 宽/高，参数填反或 aspect 用了高/宽；纠偏：记「竖 fov + 宽比高」，用数值例自测（aspect=2 时 r 是 t 的两倍）。
6. **近平面取 0（或逼近 0）**：症状：远处物体闪烁、深度错乱（z-fighting 第一印象）；病根：zNear → 0 深度精度坍塌（精度堆在近平面附近，zNear 是第一杀手）；纠偏：zNear 取尽可能大的正值，深度非线性机制将在第 3 章展开。
7. **法线直接用 model 矩阵变换**：症状：非均匀缩放/压扁模型后光照脏掉；病根：法线的本质是垂直关系不是方向，直接乘 M 在非均匀缩放下不再垂直；纠偏：法线矩阵 = model 3×3 部分逆转置 (M⁻¹)ᵀ，变换后 normalize；旋转 + 均匀缩放可退化为直接乘，但要知道边界。
8. **深度范围 GL/D3D 口径混用**：症状：半个深度带的物体消失或只有一半深度可用；病根：OpenGL NDC z ∈ [−1,1]、Vulkan/D3D z ∈ [0,1]，投影矩阵与目标 API 不配套；纠偏：写投影矩阵前先问「我的 NDC z 从几到几」（2.9 速查表）；GLM NO/ZO、glClipControl、VK_EXT_depth_clip_control 是工程弥合口，实操在第 3/6 节。
