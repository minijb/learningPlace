# 模式示例、作用域决策与边界情况

本文件回答"这个工作区到底长什么样""这条请求该操作哪个文件"。目录树为两种模式的完整示例。

## 1. config.json 写法

config.json 位于**项目根目录**，由用户维护，Agent 只读不写：

```json
{ "topic_mode": "singal" }
```

- `"singal"`：单文件模式（文档主拼写，用户原始拼写）
- `"single"`：与 `"singal"` 完全等价（容忍拼写），内部一律归一化为 single
- `"nest"`：嵌套模式
- 其他任何值、字段缺失、JSON 损坏 → 按目录结构推断并告知用户（见 workflow.md 阶段 -1 回退策略）

## 2. single 模式目录树示例

```
learning-single/                        # 项目根目录
├── config.json                         # {"topic_mode": "singal"} —— 声明单主题模式
├── Topic.md                            # ★ 唯一的主题纲领文件
│                                       #   H1 = 总体学习主题（如"游戏开发学习计划"）
│                                       #   H2 = 各知识板块（OpenGL / 图形学 / C++ / 架构…）
│                                       #   所有纲领性要点全部写在这一个文件里
├── notes/                              # 普通笔记文件夹（无 topic.md，本 skill 不将其视为领域）
│   ├── opengl-notes.md                 #   具体笔记内容，与纲领文件无关
│   └── cpp-notes.md
├── assets/                             # 资源目录（同理，无 topic.md 即与作用域无关）
└── .pi/                                # agent 配置（隐藏目录，扫描时排除）
    └── skills/topic-optimizer/         # 本 skill 所在地
```

要点：single 模式下**有且只有一个**纲领文件；任何子文件夹里都不应该再出现 topic.md（出现了 → 边界情况 E6）。

## 3. nest 模式目录树示例

```
learning-nest/                          # 项目根目录
├── config.json                         # {"topic_mode": "nest"} —— 声明嵌套模式
├── Topic.md                            # ★ 根纲领：只管总体框架
│                                       #   H2 = 领域级划分（如：渲染 / 图形学理论 / C++ / 架构）
│                                       #   每个领域只放：定位、优先级、与其他领域的关系
│                                       #   禁止出现领域内部细节（那属于领域 topic.md）
├── 01-opengl/                          # ★ 一个文件夹 = 一个领域
│   ├── topic.md                        # ★ 领域纲领：限定 01-opengl/ 内一切知识的范围
│   │                                   #   H2 = 该领域内的子方向（管线基础 / 纹理 / 光照…）
│   ├── learnopengl-notes.md            #   领域内普通笔记（受本领域 topic.md 约束）
│   └── demos/                          #   领域内子目录（无 topic.md → 仍归 01-opengl/topic.md 管）
├── 02-graphics/
│   ├── topic.md                        # ★ 领域纲领：限定 02-graphics/ 的知识范围
│   └── GAMES101-notes.md
├── 03-cpp/
│   ├── topic.md                        # ★ 领域纲领
│   ├── cpp-concurrency.md
│   └── 03a-concurrency/                # （可选）领域内再嵌套子领域：支持任意深度
│       └── topic.md                    # ★ 子领域纲领：范围 ⊆ 03-cpp/topic.md ⊆ 根 Topic.md
└── misc/                               # 无 topic.md 的顶层文件夹 = 未纳管区域（边界情况 E2/E3）
```

要点：根 Topic.md 管框架，领域 topic.md 管范围；作用域链 = 任意文件路径向上找最近的（含自身目录的）topic.md；支持任意深度递归（子 ⊆ 父），不设深度上限。

## 4. nest 模式：用户请求 → 定位 topic.md 的决策流程

```
用户请求进入
   ├─ ① 请求含明确文件/目录路径 → 定位该路径；取"最近的祖先（含自身）topic.md"为操作对象
   ├─ ② 无路径但提到领域名（匹配根 Topic.md 的 H2 或文件夹名）→ 定位对应领域 topic.md；找不到该领域文件夹 → E2
   ├─ ③ 请求是总体框架层面（整体规划/领域划分/优先级/加新方向）→ 根 Topic.md
   └─ ④ 纯内容关键词、无位置线索 → 与主题地图各 topic.md 的 H1/H2 匹配：唯一命中 → 该文件；多命中/零命中 → ask 弹"作用域选择"（候选文件路径+一句话范围+空节/已填概况）
```

无论哪条分支，开始处理前都复述："本次操作对象 = `<相对路径>`，其上级作用域 = `<父文件相对路径>`"，请用户确认。

## 5. 边界情况速查表

完整处理原则见 workflow.md 阶段 -1 / rules.md 规则 8。

| # | 情况 | 处理策略 |
|---|---|---|
| E1 | config.json 缺失/非法 | 结构推断 + 告知 + 建议补建；落笔前必经 `ask` 确认 |
| E2 | nest 下某领域文件夹没有 topic.md | 该领域"未纳管"。`ask`：a) 新建（读 domain-topic-template，标题留空由用户填）b) 用户指路 c) 暂不处理。不擅自新建 |
| E3 | 顶层无 topic.md 的文件夹（如 misc/） | 未纳管区域，主题地图标注但不主动处理；内容请求涉及时按 E2 流程问 |
| E4 | 用户请求跨多个领域 | 复述涉及的 topic.md 清单 → 建议处理顺序 → 逐文件逐节推进（规则 4/8） |
| E5 | "singal"/"single"/大小写/空格变体 | 归一化接受，不改写用户文件 |
| E6 | single 模式下发现子文件夹里有 topic.md | 声明与结构矛盾 → 停下指出（列出冲突文件），给三选项：改 config 为 nest / 用户自行移动删除 / 忽略子文件仅按根处理。裁决前不落笔 |
| E7 | nest 已声明但全库只有根 Topic.md | 正常进入 nest 流程：主题地图只有根节点；复述时提示"尚未发现领域级 topic.md"，问是否计划建立。不视为错误 |
| E8 | 嵌套深度 | 支持任意深度（最近祖先继承）；防上下文爆炸靠复述分层展示（默认两层），不是限制结构 |
| E9 | 同一目录并存多个大小写变体 | 视为文件冲突，`ask` 用户保留哪个；不自行选择 |
| E10 | 根与领域文件既有内容冲突 | 不静默改任何一边；指出冲突，用户裁决；改动走对应文件的单节流程 |
