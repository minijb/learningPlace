# Grill — 分轮拷问与共识沉淀

grill 是**拷问循环**：把对象建模为一棵**设计树**（决策挂着决策），逐轮拷问直到没有沉默的假设，再把拷问出的共识沉淀为 Context.md——**规则/惯例、术语、极端情况、决策**四节——必要时同步修订 Topic.md 对应节。

它是本工作区**唯一**拥有 Context.md 与 decisions/ 写入权的技能（topic-optimizer 对 Context 只读）。

## 对象与文件体系

- **拷问对象**：任意——整个 Topic、某个领域、某份 topic.md 的某个 H2、一个新想法、一个待定决策。无 Topic 归属的纯想法也合法（Context 落在根）。
- **Context 体系**：根 `Context.md` + 领域目录 `Context.md`（与该领域 topic.md 同目录），嵌套与作用域链跟 Topic 完全一致（最近祖先；single 模式仅根）。**惰性创建**：第一条共识敲定时才建，不预建空文件。
- **决策**：满足三判据（**难逆 / 无上下文会让人惊讶 / 真实取舍**）→ 立独立 ADR：与所属 Context.md 同目录的 `decisions/NNNN-slug.md`，Context 决策节只留一行索引。三判据缺一 → 不立 ADR，只进对话，最多归入规则/惯例节。
- **条目作用域**：跨领域的共识 → 根 Context；仅本领域的 → 领域 Context；拿不准 → 问用户。

## 硬性规则（违反任何一条都是事故）

1. **事实自己查，决策必须问**：读文件、`web_search` 能定的事实不问用户；凡需要用户拍板的决策，自己替答即是事故。后台查询不阻塞本轮，只有依赖其结果的问题延后。
2. **frontier 纪律**：每轮只问"前置已全部落定"的问题；同一轮内的问题互不依赖；依赖未定答案的问题留到后续轮。目标：问题数不省、轮数尽量少（十几个问题通常三四轮问完）。
3. **每题必附推荐**：每个问题都带一条 `➡️` 推荐答案（含一句理由），用户可按编号简答。推荐与问句措辞相左时，用户以推荐为准作答并说明即可。
4. **不做点头机器**：用户回答与既有 Context/Topic 冲突、前后矛盾、或含糊 → 当场指出并追问一次；仍含糊 → 给默认理解请确认后推进。顺着含糊答案写下去是事故。
5. **共识确认门**：frontier 清空 ≠ 会话结束。必须向用户复述全部共识（按四节条目 + 拟立 ADR + Topic 修订点分组）并获得"理解一致"的明确确认，才允许落笔；确认前不写任何文件、不开始实现。
6. **落笔范围**：只允许写——Context.md 四节条目、decisions/ ADR 文件、确认门中逐条确认的 Topic.md 对应节正文。Topic 的 H1/H2 标题主权不变：一律不动，只建议。Context 四节标题（规则/惯例、术语、极端情况、决策）为固定骨架，不增删改名。
7. **惰性创建**：Context.md 与 decisions/ 目录在第一条内容敲定前不创建。
8. **一次一对象**：一次 grill 会话只拷问一个对象；拷完可问是否换对象开新会话。表面多个对象实属同一决策链 → 向用户说明并征得同意后并入。

## 工作流程（骨架）

0. **定位**：明确对象 → 读对应 topic.md（相关节）+ 作用域链上全部 Context.md → 向用户复述：对象是什么、既有共识要点、本轮拷问范围预估。请用户确认后开工。
1. **建树**：把对象拆成设计树——主干决策 + 挂靠决策，标注前置依赖。Topic 定位与 Context 既有共识视为**已定前提**，不重复拷问；要挑战前提 → 先显式声明"我想重开这条既有结论"征得同意。事实类节点（环境能定的）不进 frontier：直接 `web_search`/`read` 自己查。
2. **轮循环**：计算 frontier → 按 ❓/➡️ 格式出题（推荐需要事实支撑的先查再出）→ 用户按编号作答 → 更新树状态，把答案随手归类为候选共识（R 规则/术语/E 极端情况/D 决策）→ 计算新 frontier → 下一轮。
3. **收敛**：frontier 空 → 复述全部共识（含明确的"未拷问区域"清单），请用户确认"理解一致"；用户补充 → 可能重开分支，回到轮循环。
4. **落笔**：确认后完成——创建/更新 Context.md 条目；三判据命中的决策立 ADR 并加索引；Topic 修订点用 `edit` 写入对应节正文（标题不动）。完成后报告改动清单，问是否开新对象。

## 常见判断

- 用户没说对象 → `ask`：拷问什么？（整个 Topic / 某领域 / 某节 / 新想法 / 待定决策）
- 对应 Context.md 不存在 → 正常：拷问照常进行，第一条共识敲定后按模板创建。
- 事后发现同轮两问其实相关 → 向用户说明，下一轮重开受影响分支（已知边界，不算事故；隐瞒才是）。
- 用户要求一次只问一个 → 尊重：退化为串行模式，其余机制（推荐、确认门、落笔）不变。
- 用户中途说"差不多了" → 提前进入收敛：复述已定共识 + 明确列出未拷问区域，确认后落笔。
- 会话过长 → 提示收尾或拆对象；不设固定问题数上限，用语言引导控制。
- 拷问结论与 Topic 某节冲突 → 停下指出，给选项：修订该节（经确认后写入）/ 调整结论。
- 拷问结论与 Context 既有条目冲突 → 停下指出，用户裁决改哪边；改既有条目也在本会话内经确认完成。
- 会话很长且候选共识已积累很多 → 中途可请示"是否先把已敲定的 N 条落盘"，同意则边拷边写。
