# Grill 完整流程与话术

## 阶段 0：定位对象

1. 从用户请求中提取对象，三类：
   - **Topic 归属对象**：整个 Topic / 某领域 / 某份 topic.md 的某 H2 → 定位文件与节（nest 定位规则与 topic-optimizer 一致：路径 > 领域名 > 框架层 > 关键词匹配，多义则 `ask`）
   - **待定决策**：用户带着具体问题来（"X 还是 Y？"）→ 对象就是这个决策
   - **纯想法**：无 Topic 归属 → 合法；Context 将落在根
2. 读料：对象对应的 topic.md 相关节 + 作用域链上全部 Context.md。不存在就跳过，不建。
3. 复述开场：对象一句话 + 作用域位置（如有）+ 既有共识要点（R/E/D 计数与关键条目摘录）+ 本轮拷问范围预估。`ask` 确认后开工。

## 阶段 1：建设计树

- 设计树 = 决策为节点，"这个决定取决于那个决定"为边。主干 = 对象的目标与边界；分支 = 各主干决策的展开。
- 每个节点标注：决策内容 / 前置依赖（哪些节点定了才能问它）/ 状态（已定 / 待问 / 事实待查）。
- **已定前提**：Topic 定位、Context 既有共识、用户开场陈述。默认不再拷问；要挑战 → 显式声明并征得同意。
- 事实待查节点（环境能定的）不进 frontier：直接 `web_search` / `read` 自己查，查完变已定；查不完的，只有依赖它的下游问题延后，其余照常。
- 树不必画给用户看：用一两句话概括主干即可，细节在提问中体现。

## 阶段 2：轮循环（核心）

### 2.1 计算与出题

frontier = 所有前置依赖均已落定的待问决策。每轮把 frontier 问满、问全。出题格式（严格遵守）：

```md
### 回合 N

❓1 {问题标题}
{问题正文：背景一句 + 为什么此刻要定 + 备选项（如适用）}
➡️ 推荐：{推荐答案}（{一句理由，可含搜索得来的事实}）

❓2 {问题标题}
…
➡️ 推荐：…
```

- 同轮问题互不依赖：任何一个的答案都不应改变同轮另一问的问法。
- 推荐必须有立场；无立场的问题说明还没想清楚，回炉建树。
- 需要事实支撑推荐 → 出题前先查（`web_search` / `read`）；推荐里引用的事实要可溯源。

### 2.2 收答

- 用户可按编号简答（"1 选 A，2 同意，3 不行因为…"）、逐条展开、或推翻推荐。
- 含糊 → 追问一次；仍含糊 → 给默认理解请确认后推进。
- 答案推翻了此前轮次的结论 → 重开受影响分支，明确告知用户哪些已答作废。

### 2.3 归类候选共识（每轮必做）

每拿到一个落定答案，随手归入四类候选（内部维护，确认门前给用户看）：

- **R 规则/惯例**："以后都这么做"的约定
- **术语**：敲定的说法 + 明确避免的同义词
- **E 极端情况**：场景 + 期望行为/边界结论
- **D 决策**：满足三判据 → 拟立 ADR；不满足 → 视内容归 R 或丢弃

### 2.4 依赖反转

事后（含收敛阶段）发现某轮两问其实相关、或某答案本应改变另一问 → 下一轮重开受影响分支并向用户说明。这是机制已知的边界，不算事故；隐瞒才是。

## 阶段 3：共识确认门

frontier 清空后：

1. 复述全部共识，按落笔结构分组：
   - 根/领域 Context 各自的新增（或修订）条目——R/E/D 分列，附条目文案
   - 拟立 ADR 清单——文件名 + 一段话内容
   - Topic 修订点——哪份文件哪个 H2、改前 → 改后
2. 显式列出**未拷问区域**（想到了但没问的），避免沉默假设。
3. `ask`：理解一致吗？（一致并落笔 / 还要拷 / 部分采纳——注明采纳哪些）
4. 用户补充新答案 → 可能重开分支，回阶段 2。**未获明确确认不落笔、不实现。**

## 阶段 4：落笔

格式权威见 `references/context-format.md`。要点：

- **Context.md 不存在** → 读 `assets/context-template.md` 创建：H1 + 一句简介（可代拟，随条目清单一并确认）+ 四节骨架。
- **条目写入**：按确认稿逐节 `edit`；R/E/D 编号在每份 Context 文件内各自独立递增。
- **ADR**：`decisions/` 目录惰性创建；文件名 `NNNN-slug.md`，NNNN 同目录从 0001 递增；正文一段话（背景/决定/理由，1–3 句）；Context 决策节同步加索引行。
- **Topic 修订**：仅限确认门中逐条确认的修订点；`edit` 只动对应 H2 之下正文，标题一行绝不进编辑范围。
- **落笔后报告**：创建/修改了哪些文件、各几条、ADR 清单；然后问是否开新对象。

## 反模式清单

- 自己回答决策类问题 → 违反规则 1
- 同轮塞进互相依赖的问题 → 违反规则 2
- 出题不给推荐、或推荐只是复述问句没有立场 → 违反规则 3
- 顺着含糊/矛盾的回答推进 → 违反规则 4
- frontier 一空就开始写文件或写代码 → 违反规则 5
- 动 Topic 标题、增删改 Context 四节标题 → 违反规则 6
- 预建空 Context.md / 空 decisions/ → 违反规则 7
- 一次拷问多个对象 → 违反规则 8
- 确认门后夹带私货（写入未确认条目）→ 违反规则 5、6
- 把不满足三判据的决定立成 ADR → ADR 通胀，违反"三判据缺一不立"
- 该自己查的事实反复问用户 → 浪费用户回合，违反规则 1
