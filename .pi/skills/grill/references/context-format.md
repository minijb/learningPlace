# Context.md 与决策文件格式（权威规范）

本文件是 Context.md 与 decisions/ 的格式权威。grill 落笔前必读；topic-optimizer 只读 Context 时亦以此理解条目。

## Context.md 结构（四节固定）

```md
# {Context 名称}

{一两句话：本 Context 覆盖的作用域与存在目的。}

## 规则/惯例

- **R1** {一条规则或惯例，一句话}。{适用范围/来源，可选}

## 术语

**{规范术语}**：
{一两句话定义：它是什么，而不是它怎么实现。}
_避免_：{同义词、易混词}

## 极端情况

- **E1** {场景一句话}：{期望行为 / 边界结论}

## 决策

- **D1** → [0001-slug](./decisions/0001-slug.md)：{一句话结论}
```

## 条目规则

- **四节骨架固定**：`## 规则/惯例`、`## 术语`、`## 极端情况`、`## 决策` 不增删、不改名、不调序；条目写在对应节下。
- **编号**：R/E/D 在**每份 Context 文件内**各自从 1 递增；根与领域互不共享编号；条目删除不回收编号。
- **措辞**：
  - 规则一条一句话，写"怎么做"；为什么进 ADR 或对话，不进规则条目
  - 术语定义说"是什么"，一两句为限；**不含实现细节**；有同义词/易混词必须列 `_避免_`
  - 极端情况 = 场景 + 期望行为，成对才收；不含边界信息的泛化场景不收
- **只收本作用域特有内容**：通用常识（语言特性、行业通识）不进术语表——收之前问一句"这是本工作区语境特有的吗？"
- **作用域归属**：跨领域 → 根 Context；仅本领域 → 领域 Context；拿不准 → `ask`。禁止同一概念在两级 Context 各写一个定义：父级定了，子级引用或细化，不另造同义词。
- **过时条目**：不静默删除；经用户确认后改写或删除。决策被推翻 → 旧 ADR 保留，新立一条 superseding ADR，决策节索引注明取代关系。

## decisions/ ADR 格式

- **位置**：与所属 Context.md 同目录的 `decisions/`（惰性创建）。
- **文件名**：`NNNN-slug.md`，NNNN 在同目录内从 0001 递增；slug 用英文短横线小写。
- **模板**：

```md
# {短标题}

{1–3 句：背景是什么、决定了什么、为什么。}
```

- 可选节（仅真有价值才加）：`## 备选方案`（被否方案值得记住时）、`## 后果`（下游影响不显然时）。大多数 ADR 一段话即可。

- **索引**：Context 决策节同步加一行：`- **D{n}** → [NNNN-slug](./decisions/NNNN-slug.md)：一句话结论`

## 何时立 ADR（三判据，缺一不立）

1. **难逆**：反悔成本高
2. **无上下文会惊讶**：后来者会问"为什么这么干？"
3. **真实取舍**：存在真实备选，且因特定理由选了这个

典型合格：
- 路线类："渲染器先 OpenGL 后端、第 6 节再复刻 Vulkan"
- 边界类："第 2 节全程纯 CPU 不绑定图形 API"（明确的"不"与"是"同样值钱）
- 反直觉类："不上 ORM / 框架，手写因为 X"
- 约束类："因外部依赖必须用 Y"

典型不合格：
- 可随时改的措辞与顺序
- 顺理成章、无真实备选的做法
- 纯实现细节（那属于实现文档，不属于共识库）
