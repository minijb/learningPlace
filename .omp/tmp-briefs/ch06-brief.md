## 分节大纲（10 节）

### 6.1 帧预算：一场每帧都考的 16.6ms 考试
- 算术（粗体表）：60fps=16.67ms、144fps=6.94ms、240fps≈4.17ms；掉一帧不是「慢一点」而是预算 4 倍超支。
- 预算分摊示例表：输入/游戏逻辑/物理模拟/动画/渲染提交/等 GPU/OS 与驱动干扰——各占几毫秒的示意（标注量级示意）。
- 「够快了」不存在，只有「预算内/超支」；vsync 与帧时间抖动：偶尔一帧 100ms 比平均 18ms 更伤手感（帧时间一致性）。
- 世界观句：性能不是优化技巧的堆砌，是「预算→测量→归因→改动→复测」的工程循环（下一节给仪器）。

### 6.2 测量方法论：采样剖析器、帧计数器与时间线三分工
- ①采样剖析器（VS Performance Profiler；概念上 Very Sleepy 同类）：统计热点；**火焰图（flame graph）**怎么读：横宽=CPU 占比、纵深=调用栈、平顶=自耗时大头（伪火焰图用 text 示意一段）。
- ②帧计数器：steady_clock 帧时间统计，看 min/p50/p99 而不是平均（为什么：抖动藏在尾部）；一段最小帧计时代码（完整可编译）。
- ③时间线（Tracy / VS 并行时间线）：跨线程视角、帧栏、锁等待可视化——ch05 的异步加载线程在时间线上一目了然；Tracy 简介（游戏行业标配，FrameMark/zone，GitHub wolpld/tracy，Stages 推荐资源）。
- 三分工决策表：「哪里最慢」→采样器；「这帧几毫秒、p99 多少」→帧计数器；「线程们各自在干嘛、谁等谁」→时间线。
- 测量纪律：Release、复现场景、多次取稳定值（细则 6.3）。

### 6.3 微基准的陷阱与纪律（兑现 ch04 误区五挂账）
- 陷阱一：Debug 下测性能全部作废（回收 ch04：/Od、迭代器调试层、运行时检查——同一循环 Debug/Release 数倍差的量级示意）。
- 陷阱二：被测代码被优化器吃掉（死代码消除/循环外提）——结果必须「被消费」：DoNotOptimize/escape 惯用法（Google Benchmark 的做法），或 volatile 汇编屏障；给一个「不加防护结果恒 0 耗时」的示例。
- 陷阱三：缓存冷热（首轮遍历 vs 稳态）与分支预测状态——预热再计。
- 陷阱四：微基准冠军 ≠ 游戏内冠军（上下文不同）；微基准只回答「两个实现谁相对好」。
- Google Benchmark 一段最小示例（FetchContent 接入一句话，回收 ch04）；纪律清单收尾。

### 6.4 缓存层级：容量、延迟与那行 64 字节
- 数量级表（标注「数量级、以具体 CPU 为准」）：寄存器 ~0、L1 ~4 周期/几十 KB 每核、L2 ~12 周期/几百 KB-几 MB 每核、L3 ~40 周期/几 MB-几十 MB 共享、DRAM ~200+ 周期/几十 GB。
- 人类尺度类比一个即可（1 周期=1 秒 → L1 数秒、DRAM 数分钟量级）。
- **缓存行（cache line）**：64 字节，搬运的原子单位——回收 ch05 false sharing（写不同变量同行=乒乓）。
- 预取器：爱顺序前进与规律步长——布局的被动收益/惩罚；空间+时间局部性两原则。
- 完整可编译实验：同容量 `std::vector<int>` 求和，步长 1/8/64 元素三档对照（只报倍数关系，以本机实测为准）。
- 兜底声明（粗体）：数量级是设计直觉，不是优化免检牌——先测量。

### 6.5 AoS vs SoA：遍历模式决定布局
- 完整对照（关键示例）：`struct Particle { pos, vel, life, color }`（AoS）vs `struct ParticleSystem { vector<pos>; vector<vel>; vector<life>; ... }`（SoA），同一更新算法两版。
- 机制解释：热循环只消费 pos/vel/life，AoS 每行把 color 等冷数据一起拖进缓存行——带宽浪费+缓存行数翻倍；SoA 紧密排列被消费字段。
- 何时 SoA 赢：同质海量对象、窄字段子集消费（ECS 的 System 正是这个形状——观念指针第 4 节「Component 是纯数据」一句）；何时 AoS 无害/更好：字段总是结伴使用（transform 全家）、对象数量小、整对象一起传递。
- 混合策略一句（热点字段拆分）；结论（粗体）：**布局跟着「热点问题问哪些字段」走**。

### 6.6 分支预测：有序与无序的分野
- 机制：现代 CPU 投机执行+分支目标预测，预测命中率高时流水线才快；预测失败=冲刷流水线（几十周期量级）。
- 经典实验（完整可编译）：随机数据 vs 排序后数据，同一 `if` 过滤求和，倍数差（报量级）。
- 什么时候在乎：热循环内、数据依赖型分支、对象存活/死亡混杂时可先 sort/partition 再遍历。
- 分支消除手法概念级：查表（回收 ch03 3.12 正弦表）、std::clamp/min/max 无分支化、位技巧一句带过（警惕可读性）；cmov 一句话。
- 兜底：先测量，平顶在分支上再动手。

### 6.7 堆分配的隐藏成本：逐帧 new 为何大忌
- 一次 new/delete 做了什么：分配器找块（多线程下有锁——回收 ch05）、可能触发系统调用向 OS 要页、构造、析构、归还（还不一定还给 OS）。
- 三笔隐藏税：固定开销（次数敏感）、**碎片**（长跑进程 RSS 慢涨、缓存不友好）、分配器竞争（工作线程与主线程同时 new）。
- 缓存视角：堆数据散落，指针跳转=随机访问（接 6.4）。
- 完整可编译实验：循环内逐次 new/delete 百万小对象 vs 池化复用，倍数差（量级）。
- 结论（粗体）：帧循环里「分配次数」比「分配字节数」更敏感；零分配是纪律不是优化项（对位 Stages 误区原文措辞）。

### 6.8 零分配工具箱：reserve、池、arena 与 swap-and-pop
- ①reserve 预留：帧初一次，避免扩容搬家+迭代器失效（回收 ch03 3.1/3.2）。
- ②对象池：粒子/子弹的经典池；完整小型 `Pool<T>` 示例（free-list 或 swap 栈版，取其一写全）；池化后 new 去哪了、碎片为什么消失。
- ③arena/帧分配器概念级：每帧 bump 分配、帧末整体重置——引擎标配，给一段示意代码（十几行）。
- ④swap-and-pop：无序容器 O(1) 删除=尾部换位（remove-erase 的 O(1) 亲戚，回收 ch03 3.4）；代价：索引/引用失效，一句警示。
- ⑤逐帧容器成员化：函数局部临时 vector 升格为成员+clear() 复用容量（clear 不缩容）。
- 使用顺序建议：先 reserve/成员化（零成本），再池化（改造成本），arena 是引擎级决策。

### 6.9 字符串：string_view 传参与临时字符串规避
- 回收 ch03 3.3：string_view 借而不拥有、SSO 边界。
- 帧内拼接大忌：每帧拼日志串/资源 key（分配+拷贝+释放一条龙，且常是分配计数器头号惯犯——接深入专题）。
- 方案：传参 `std::string_view`/`const char*`；日志分级延迟格式化（错误真发生才 format）；静态化/缓存高频 key；C++20 std::format 一句（可用性以工具链为准）。

### 6.10 贵运算清单：除法、开方与「先测量」
- 整型除法/取模：数十周期量级；除数是编译期常数时编译器会改乘（运行期除数才贵）；取模 2 的幂→位掩码。
- sqrt 与 rsqrt 量级差概念级：热循环里逐粒子归一化的代价；图形学的 rsqrt 近似+牛顿迭代一句（第 2 节数学伏笔一句即可）。
- 浮点↔整型转换的历史包袱一句；查表回收 ch03 3.12。
- 收尾铁律（粗体）：本节是「候选嫌疑人清单」不是「见着就改清单」——火焰图定罪再动手；GPU 侧同名方法论归第 5 节（观念指针一句）。
