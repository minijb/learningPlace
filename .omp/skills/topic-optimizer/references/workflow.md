# 完整工作流程与话术

## 阶段 0：定位文件

1. `glob` pattern `topic.md`（工作区根目录优先；没有再试 `**/topic.md`；也没有再试 `**/Topic.md` 等**大小写变体**——文件名大小写以实际工作区为准；仍没有则问用户路径）
2. `read` 通读全文

### 文件不存在
用 `ask` 问：新建 / 用户提供路径 / 暂不处理。
新建 → 读 `skill://topic-optimizer/assets/topic-template.md` 生成骨架文件，**标题留空**，请用户自己填 H1/H2；填好后回到阶段 1。

## 阶段 1：通读与复述（每次会话开始时）

向用户输出：
- H1/H2 骨架列表（只列标题原文，不改写）
- 每个 H2 一句话现状：空 / 已有纲领 / 内容疑似过细
- 你对该文件主题方向的理解（1–2 句）

然后用 `ask` 问：理解是否准确？本轮处理哪一节？是否有想听的标题建议？

## 阶段 2：标题建议（仅当发现问题时）

格式：
> 观察：`## 当前标题` …
> 建议：`## 候选文案`；理由：…

用 `ask` 给选项：采纳（用户自己改）/ 不采纳 / 换个方向。
无论结果如何，落笔的永远是用户；你只记录结论。

## 阶段 3：单节填充循环（核心循环）

```
选定 H2 → web_search → ask 细节问题(2–4个) → 起草 → ask 确认 → edit 落笔 → 停，问下一节
```

### 3.1 搜索
- 至少一次 `web_search`；关键词 = 标题 + 用户上下文中的词
- 记录：可靠事实、主流术语、有争议的点

### 3.2 提问（`ask`，2–4 个问题）
- 范围："这节是否覆盖 X？还是 X 归入另一节更合适？"
- 侧重："搜索显示常见做法是 A / B，你更想强调哪个？"（给 recommended）
- 素材："这块你有没有已定的决定或约束？"
- 密度："3–5 条要点够吗，还是要更细 / 更粗？"

### 3.3 起草
- 只起草这一个 H2 之下的内容
- 区分来源：检索事实 vs 用户决定（草案后附一句来源说明）
- 保持纲领性（见 rules.md 规则 7）

### 3.4 确认与落笔
- `ask`：直接写入 / 修改后写入 / 重来
- `edit` 只动该 H2 与下一个标题之间的行；标题行绝不进编辑范围
- 起草时发现内容其实属于另一节、或与已填节冲突 → 停下问用户，不静默处理

### 3.5 回合结束
- 报告：本节改动摘要（几条要点、来源构成）
- `ask`：满意吗？下一节处理哪个？
- 会话继续 → 回到 3.1；用户收尾 → 确认整体状态

## 反模式清单

- 一口气把所有空节填满 → 违反规则 4
- 跳过提问直接写 → 违反规则 3
- 没搜索就写 → 违反规则 6
- 写成实现文档 → 违反规则 7
- "我帮你把标题也改了" → 违反规则 1
- 用户未回应就自行连续推进 → 违反规则 5
