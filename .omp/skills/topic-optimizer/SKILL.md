# Topic Optimizer — topic.md 理解与优化

topic.md 是当前工作区的**主题纲领文件**：它定义主题骨架与方向，是后续一切工作的顶层依据。本技能规定 Agent 如何与用户协作：理解它、对标题提建议、逐节填充内容。

## 渐进式加载

1. 本文件（已加载）：硬性规则 + 工作流程骨架。
2. `skill://topic-optimizer/references/rules.md` —— 七条规则的边界、判例、反例。**第一次处理 topic.md 前必读；对"能不能改 / 算不算细节"拿不准时读。**
3. `skill://topic-optimizer/references/workflow.md` —— 完整对话循环、`ask` 提问模板、话术示例。**开始第一轮填充前必读。**
4. `skill://topic-optimizer/assets/topic-template.md` —— 仅当用户要新建 topic.md 时读。

## 硬性规则（违反任何一条都是事故）

1. **标题主权在用户**：一级（H1）、二级（H2）标题由用户管理。禁止新增、删除、重命名、改写任何 H1/H2——即使用户口头同意你的建议，也由用户自己动手改，你不代改。
2. **对标题只能提建议**：发现 H1/H2 有可改进处（命名、划分、顺序、覆盖面），向用户陈述理由并给出候选文案，决定权在用户。
3. **填充前必须问**：填充任何二级标题下的内容之前，必须先就该节用 `ask` 向用户提出细节问题（范围、侧重、素材、期望密度），得到回答后再动笔。
4. **一节一回合**：每一轮对话最多填充一个二级标题。填完即停，与用户确认后才能进入下一节。
5. **持续对齐**：全程不断提问、复述理解、确认方向；宁可多问一句，不可自作主张。
6. **内容必须有网络搜索支撑**：动笔前先针对该节主题用 `web_search` 检索（必要时多轮），把行业事实、术语、现状融入内容。
7. **纲领性，不展开细节**：每节只放方向性要点（默认 3–6 条、每条一句话）。实现细节、操作步骤、穷举清单不进这个文件。

## 工作流程（骨架）

1. **定位与通读**：用 `glob` 找 topic.md（通常在工作区根目录），`read` 通读，向用户复述你对 H1/H2 骨架与主题方向的理解，请用户确认或纠偏。
2. **选定一节**：问用户本轮处理哪个二级标题；可基于通读发现（空节、方向不明）建议优先级，但选择权在用户。
3. **搜索**：就该节主题 `web_search`，信息不足则换关键词多轮检索。
4. **提问对齐**：基于搜索结果，用 `ask` 就该节提出 2–4 个具体问题。
5. **起草与确认**：给出该节纲领性草案，标明哪些来自搜索、哪些来自用户回答，请用户确认。
6. **落笔**：确认后仅用 `edit` 修改该 H2 之下的正文，标题一律不动。完成后停止，报告改动，再问下一节。

## 常见判断

- topic.md 不存在 → 询问是否按模板新建；标题留空由用户填。
- 用户要求"把整篇填完" → 不批量填充：说明一节一回合规则，改为逐节推进。
- 用户要求你直接改标题 → 不代改；给出改前/改后文案，让用户自己改。
- 该节内容与已填内容冲突 → 停下向用户指出，不要静默改写其他节。
